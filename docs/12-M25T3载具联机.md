## 0. 结论

把 M25-T2 的单机皮卡接入现有 KCP 联机管线，保持**服务器权威、客户端只读复制**：

- 服务器生成/接管一辆皮卡，车辆实体带稳定 ID；所有客户端看到同一辆车。
- 驾驶位同一时刻只允许一名玩家；上下车走新的 ZLC1 命令。
- 服务器用与单机相同的 `VehicleStep` 推进位置、速度、燃料和碰撞车况；客户端只做本地位置预测，不提交权威位置。
- 车辆位置/速度/燃料/车况/驾驶员/乘客通过 ZLR1 复制；后备箱继续走 `PlayerStorage` + `Container` 复制与现有服务器背包命令。
- 维修/加油在联机下也必须由服务器结算并扣物品，避免联机车辆燃料耗尽后无法恢复。
- 断线/重连/服务器重启后车辆留在世界存档中；驾驶座位不持久化，重连玩家从步行状态开始，可重新上车。

预计 **3~5 个工作日**（单人全职），按业余时间乘 1.5~2。完成后联机玩家可以共同看到、驾驶、维修、加油和使用同一辆皮卡，并通过断线/重启继续。

## 1. 背景与非目标

### 1.1 为什么现在做

M25-T2 已把单机载具闭环做完：驾驶、碰撞车况、维修、加油、后备箱、单机存档。联机模式当前直接不生成车辆，`UpdateVehicle`/`ToggleVehicle`/`TryServiceVehicle` 都有 `m_networkMode` 早退；`Vehicle` 组件也不进入 `ZLR1` 复制。因此：

- 联机玩家看不到载具；
- 没有服务器权威的位置/燃料；
- 没有上下车命令和驾驶员占用；
- 没有断线/重启恢复。

T3 要把这些补齐，同时保持单机路径不受影响。

### 1.2 本任务范围

- 单服务器、一辆皮卡、一个驾驶位。
- 服务器权威位置、速度、燃料、车况和碰撞；客户端只读复制 + 本地预测。
- `ENTER` 上下车命令；`WASD` 驾驶复用现有 `Move` 命令，服务器在驾驶态解释为车辆输入。
- 车辆位置/燃料/车况/驾驶员走 ZLR1；驾驶员座位/驾驶态走 owner-only `PlayerState` 镜像。
- 后备箱读写复用现有 `PlayerStorage` 复制和 `InventoryAction` 服务器结算。
- 联机维修/加油新增服务器命令，复用 M25-T2 的 `PlanVehicleService` 与物品扣除规则。
- 同一玩家身份断线重连；服务器重启后车辆位置/燃料/车况/后备箱恢复；不重复生成车辆。
- 单机 M25-T2 行为保持；新增纯逻辑、协议、服务器安全、双客户端集成测试与 1280 联机烟测。

### 1.3 本任务不做

- 多座位/乘客、多辆车、车辆所有权/钥匙/锁、车辆买卖/刷新。
- 车辆碾压僵尸/动物、僵尸攻击车辆、车辆噪音引怪、车灯、轮胎/悬挂/发动机部件。
- 车辆刚体物理、车辆推挤玩家、车内视角/驾驶动画/正式美术/音效（M26-V2 已补载具间阻挡，V4 已补服务器推挤，V5 已补单机多车与停放阻挡，V7 已补每车远端朝向/车灯/破损/烟雾，V10 已补碰撞乘员生命伤害，V12 已补显式车型/持久 heading/转向/侧向抓地，见 `docs/13`）。
- 主机迁移、跨服务器漫游、客户端权威位置、车辆物理反作弊。
- 车辆座位状态持久化；服务器重启或重连后不自动坐回驾驶位。
- 联机车辆碰撞伤害的完整平衡；只复用现有玩家驾驶碰撞规则。

## 2. 验收标准

### 2.1 功能验收

1. A/B 两个客户端连接同一服务器，都能看到同一辆皮卡，位置/朝向/后备箱一致。
2. A 靠近车辆按 `ENTER` 上车；B 看到 A 从步行消失/不再渲染，车辆进入驾驶态；B 再按 `ENTER` 被拒绝（座位占用）。
3. A 按住 `WASD` 驾驶，客户端立即响应；服务器按固定 tick 推进，B 看到车辆平滑移动；双方车辆位置最终一致。
4. A 驾驶撞墙，服务器扣车况并复制；HUD 显示车况下降；没有客户端自行扣车况。
5. A 下车后，B 可以上车；A 的玩家实体恢复在车辆旁可行走格，不再跟随车辆。
6. 车辆后备箱：步行靠近按 `I` 打开，A/B 都能看到同一容器内容；存取物品由服务器结算，距离/容量/堆数校验生效。
7. 联机维修/加油：靠近车辆按 `E`，服务器优先维修再加油，扣对应物品并复制燃料/车况；客户端不本地扣物品。
8. A 驾驶中断线：车辆立即停止；A 用同一身份重连后在车辆旁步行状态恢复，车辆位置/燃料/车况/后备箱保留；A 可重新上车。
9. 服务器正常保存并重启：车辆只生成一辆，原位置/燃料/车况/后备箱恢复；没有驾驶员时玩家不会自动被放进车内。
10. 非法命令被拒绝且不改变状态：距离过远、座位被占、非驾驶员发车辆输入、对不存在/非车辆实体操作、维修/加油缺物品、死亡/睡眠中操作。

## 3. 设计方案

### 3.1 权威与模块边界

保持“单机 `WorldDemoState` 组装、服务器 `ServerHost` 组装”的现有结构，不把整个车辆系统迁进 `WorldSimulation`：

- `src/game/VehicleSpike.h`：继续作为纯逻辑，新增服务器/客户端共用的 `FindVehicleExitCell`、`VehiclePredictStep`（只算位置/速度，不改燃料/车况）和座位校验辅助。
- `src/server/ServerHost.h/.cpp`：新增 `ServerVehicleRuntime`（车辆 StableId、`VehicleMotion`、驾驶员 StableId、输入、退出格等），负责服务器权威推进和命令处理。
- `src/game/states/WorldDemoState.h/.cpp`：单机保持现有路径；联机增加“绑定复制车辆 + 本地预测 + HUD/输入/座位镜像”。
- `src/game/EntityReplication.h/.cpp`：新增 `Vehicle` 复制组件与客户端 actor 字段。
- `src/net/Command.h/.cpp`：新增上下车/服务命令号；`Move` 在驾驶态复用为车辆输入。
- `src/net/PlayerState.h/.cpp`：升 v17，增加 owner-only `PlayerVehicleState`。
- `src/game/NetworkClient.*`：只透传状态，不新增独立车辆会话层。

这样单机与服务器的集成代码仍有两份，但驾驶/碰撞/维修/加油的核心规则只用一份 `VehicleSpike`；T3 以最小风险接入，后续可再统一到固定链。

### 3.2 数据模型与生命周期

服务器运行时：

```cpp
struct ServerVehicleRuntime {
    ecs::Entity entity = entt::null;
    std::uint64_t stableId = 0;
    game::VehicleMotion motion;
    std::uint64_t driverStableId = 0;
    float inputX = 0.0f;
    float inputY = 0.0f;
    bool fuelWarned = false;
};
```

- 车辆 ECS 实体保持现有组件：`Position`、`SpriteRef`、`SpriteScale`、`Collider`、`Vehicle{condition,fuel}`、`Container`、`PlayerStorage`。
- 新增运行时 `VehicleDriver{stableId}`（不注册存档、不增加存档组件数），用于 ZLR1 复制驾驶员和客户端隐藏驾驶员；不持久化座位。
- 备箱仍由 `Container` + `PlayerStorage` 保存，容量 40kg/6 堆由 `config/game.json` 的 `vehicle` 段提供。
- 生成规则：
  - `ServerHost` 启动/读档后扫描 `ecs::Vehicle`；找到一个则绑定，多个则只绑定第一个并告警（T3 不支持多车；M26-V1 已改为接管全部并补足 `vehicle.count`，见 `docs/13`）。
  - 没有车辆时，在服务器首个玩家附近按 M25-T2 的 3×3 空地搜索生成；如果 chunk 未加载则重试，不能生成在阻塞格/玩家脚下。
  - 车辆 StableId 由服务器 `EcsWorld` 分配并写入服务器世界存档；客户端不能创建/指定车辆 StableId。
- 座位状态：`ServerVehicleRuntime.driverStableId` 和 `SessionPlayer.drivingVehicleId` 只存在运行时；读档/重启/断线后为空，车辆停止。

### 3.3 命令与校验

新增 ZLC1 命令：

| 命令 | 编号 | payload | 服务器行为 |
|---|---:|---|---|
| `EnterVehicle` | 40 | `entityId` = 车辆 StableId | 校验实体是车辆、同层、距离 ≤ `enterRange`、玩家存活/非睡眠、座位为空、玩家不在其他车；设置驾驶员并同步位置。 |
| `ExitVehicle` | 41 | 无 | 校验当前会话确实是驾驶员；查找车辆旁 1~3 格可行走格；清速度/路径/输入并把玩家放到出口；释放座位。 |
| `ServiceVehicle` | 42 | `entityId` = 车辆 StableId | 校验同层/距离/非驾驶；按 `PlanVehicleService` 优先维修再加油，原子扣维修包/燃料罐，更新车况/燃料并下发状态。 |
| `TakeDriverSeat` | 46 | 无 | 仅乘客位会话可发；校验驾驶位为空且请求者是当前乘客；清空乘客位、写入驾驶位并同步车辆/驾驶员，保留燃料/车况/车灯。 |
| `GiveDriverSeat` | 47 | 无 | 仅驾驶位会话可发；校验车辆已停稳（≤ `vehicle.seatHandoffMaxSpeed`）且当前有存活乘客；交换驾驶员/乘客 StableId，清空输入/速度并同步双方，保留燃料/车况/车灯。 |

- 驾驶输入继续使用 `Move`：会话有 `drivingVehicleId` 时，服务器把归一化方向存到 `ServerVehicleRuntime.input`，不再写玩家 `MoveInput`；非驾驶态走原玩家移动逻辑。
- 驾驶中服务器拒绝 `Attack`、`E` 类交互、建造、拾取、采集、交易等会改变玩家状态/背包的动作；只允许 `Move`、`ExitVehicle`、聊天、暂停/菜单类客户端操作。服务端拒绝要有 `unsupportedCommands`/`cooldownRejected` 等现有统计归因。
- 乘客只允许 `ExitVehicle`、`TakeDriverSeat`（空驾驶位）、`InventoryAction`（车内背包/后备箱）、`UseBag`/`EquipBag`（快捷使用/装备）、快捷栏/聊天/菜单；接管后按驾驶员白名单处理。驾驶员停车让座由 `GiveDriverSeat` 处理，让座后旧驾驶员按乘客白名单。非驾驶员发送 `Move` 只影响自己的步行，不影响车辆；没有车辆目标的命令不能操作车辆。V26 起乘客可在背包关闭时用 `E` 使用消耗品、`R` 切换主手武器；驾驶员驾驶中仍不允许 `InventoryAction`/`UseBag`/`EquipBag`。
- `ServiceVehicle` 使用与单机相同的“车况优先、缺物品失败不扣车”规则；维修包/燃料罐从服务器玩家 `Container` 扣除。
- 后备箱不新增命令：客户端 `I` 打开车辆容器后，`InventoryAction` 以 `fromEntityId` 指向车辆 StableId；服务器 `PlayerInventoryService::StorageAccessible` 校验距离/容量/堆数，车辆无 `StructureOwner`，所有玩家可访问（T3 明确共享后备箱，不引入所有权）。M25-T4-V25 允许乘客在车内使用同一路径打开/存取后备箱；驾驶员的驾驶中 `InventoryAction` 仍被拒绝。

### 3.4 服务器 tick

服务器命令处理完后，在固定 tick 内执行 `TickServerVehicles`：

1. 对每个有驾驶员的车辆，按时长调用 `VehicleStep`，阻塞回调使用服务器已加载 chunk 的 `IsSquareBlocked`；未加载区域视为不可通行，避免穿墙。
2. 写回车辆 `Position`；同步驾驶员 `Position` 到车辆中心，清零 `MoveInput`/`MoveIntent`/`Velocity`，清空 `PathFollow`/`PathRequest`，物理体传送到车辆位置。
3. 碰撞扣车况、燃料消耗只由服务器结算；`crashLatched` 只在服务器状态中，复制不携带。
4. 无驾驶员的车辆不推进，速度归零；下车/断线/死亡立即停车。
5. 服务器在 `WorldSimulation::Tick` 后执行车辆同步，再生成每会话 `PlayerState`/快照，确保客户端收到本 tick 的最终位置。

驾驶员的 `SpriteRef` 不删除（避免存档/重连缺精灵），客户端根据车辆复制中的 `driverStableId`/`passengerStableId`/`secondPassengerStableId` 隐藏驾驶员/乘客；退出时清空座位，客户端恢复显示。M25-T4-V22 将座位扩为驾驶员 + 单乘客，V27 扩为驾驶员 + 最多 2 名乘客。

### 3.5 复制与协议

#### ZLR1

- 新增 `kReplicationVehicle`（四字符 `VEHI` 之外的独立复制 ID，例如 `VHCL`），负载：
  - `condition`（f32，[0,1]）
  - `fuel`（f32，[0,1]）
  - `driverStableId`（u64，0 = 无驾驶员）
  - `passengerStableId`（u64，0 = 无第一乘客；M25-T4-V22 追加）
  - `secondPassengerStableId`（u64，0 = 无第二乘客；M25-T4-V27 追加，负载 33B）
  - `headlights`（u8，0/1；M25-T4-V2 追加）
- M25-T4-V22 追加 `VehiclePassenger` 运行时组件与乘客 id；M25-T4-V27 将运行时组件扩为两名乘客、ZLR1 负载扩为 33B；M26-V12 再扩为 37B（车型 flags + heading）并升 `PlayerState` v19；旧 ZLR1 17B/25B 客户端不兼容新服务器。
- 车辆仍带 `PlayerStorage`，因此继续走 `archetype=Prop`；不新增 archetype。
- `Capture` 已包含 `PlayerStorage` 的 prop；新增 `Vehicle` 组件后车辆自然进入 AOI。
- `EntityReplicationClient` 的 `ReplicatedActor` 增加 `ecs::Vehicle vehicle`、`bool hasVehicle`、`driverStableId`；`SyncNetworkReplicas` 给本地副本补 `ecs::Vehicle`、`SpriteScale=1.7`、`Collider` 和（仅运行时）`VehicleDriver`。
- 客户端 `m_vehicle` 绑定第一个带 `Vehicle` 复制的实体；`FindNearbyStorage` 在联机下也优先返回该车辆（当前代码只允许单机车辆，需放宽）。
- 不复制 `crashLatched`、`motion.vx/vy` 以外的服务器内部字段；位置/速度走现有 `Position`/`Velocity` 组件。

#### ZLP1

`PlayerState` 升 **v17**，尾部增加 owner-only：

```cpp
struct PlayerVehicleState {
    bool valid = false;
    std::uint64_t vehicleStableId = 0;
    bool driving = false;
    float fuel = 0.0f;
    float condition = 0.0f;
};
```

> M25-T4-V22：`PlayerState` 升 **v18**，`PlayerVehicleState` 追加 `bool passenger`（与 `driving` 互斥）；客户端用 `driving/passenger` 区分驾驶/乘坐，v17 旧负载回退 `passenger=false`。

- 客户端用 `vehicleStableId/driving` 绑定驾驶态、显示 HUD、决定 `Enter`/`Exit` 文案；用 `fuel/condition` 做即时 HUD，ZLR1 作为世界实体状态。
- 服务器每次上下车/服务/碰撞后标记 `stateDirty`，随现有 `PlayerState` 下发；断线重连时先发 v17 状态。
- 旧 v16 负载仍可解码尾部缺失字段（`valid=false`，驾驶态为空）；`M25-T4-V22` 升 v18 追加 `passenger`（与 `driving` 互斥），v17 负载回退乘客 false；服务器不接受旧客户端发来的车辆命令（命令号未知/版本校验拒绝），避免半兼容。
- 不把车辆位置写进 `PlayerState`，避免与 ZLR1 双权威。

### 3.6 客户端预测与校正

- 联机驾驶时 `WorldDemoState` 维护 `m_vehiclePredicted`（x/y/vx/vy），每帧用 `VehiclePredictStep` 按本地输入积分；不改燃料/车况，不写服务器数据。
- 本地预测的碰撞读取客户端已加载 chunk；与服务器地形不同或延迟时，服务器快照为准。
- 每次收到 ZLR1 `Vehicle` 位置或 `PlayerVehicleState`：
  - `driving=false`：立即退出预测态，按服务器位置显示车辆，恢复玩家步行。
  - `distance(predicted, server) > 1.0f`：吸附到服务器位置；否则按 0.25 权重混合（与现有玩家轻量预测一致）。
  - 服务器座位丢失/车辆不存在：吸附后退出驾驶态，显示服务器状态提示。
- 远程客户端不预测车辆，只按现有 `SamplePosition` 在快照间插值；车辆位置超出 AOI 时隐藏，但驾驶员 HUD 仍由 owner-only 状态维持。
- T3 不做输入历史重放；服务器权威校正可接受短距离吸附。若高速下抖动明显，V6 再评估按 tick 重放，不改变协议。

### 3.7 断线、重连与重启

- 会话断开/超时/同身份新连接接管：服务器立即释放驾驶位、车辆速度清零、驾驶员位置保留在车辆旁（若在车内则先找出口），保存玩家档案。
- 座位不写入玩家档案/世界存档；重连后 `driving=false`，玩家步行。
- 车辆位置/燃料/车况/后备箱由服务器世界存档保存；服务器重启扫描已有车辆，不重新生成。
- 重连玩家恢复到车辆附近时，如果位置落在车辆碰撞半径内，服务器用 `FindVehicleExitCell` 放到相邻可行走格，避免卡在车内/墙内。
- 服务器销毁车辆（T3 不会主动销毁）或读档找不到车辆时，客户端清除绑定并显示一次状态提示；不自动在客户端生成新车。

### 3.8 HUD 与交互

- 靠近车辆 HUD：复用 M25-T2 文案，数据来自 `PlayerVehicleState` + 绑定车辆；显示燃料/车况/`Enter 上车`/`E 维修/加油`/`I 后备箱`。
- 驾驶中 HUD：`驾驶中：WASD 移动 · Enter 下车 · 燃料 x% · 车况 y%`；不显示 `E/I`。
- 驾驶中客户端关闭背包，禁止 `E/I/攻击/建造/拾取` 等；只提交 `Move`/`ExitVehicle`。服务端同样拒绝，不只依赖 UI。
- `I` 仅在步行、靠近车辆时打开后备箱；标题为 `后备箱：皮卡（x/40 kg）`，容量/堆数由复制的 `Container`/`PlayerStorage` 提供。
- `E` 在联机下只发 `ServiceVehicle`，不本地扣物品/不本地改车况；服务器成功/失败通过 `PlayerState.status`/notice 显示。
- 车辆损坏/燃料耗尽提示由服务器状态触发；客户端不从本地预测推断维修/加油结果。

## 6. 风险与已知限制

| 风险 | 影响 | 处理 |
|---|---|---|
| 服务器/客户端地形加载不同 | 预测穿墙或卡住 | 服务器权威；未加载格视为阻塞；快照吸附/混合 |
| 玩家物理体与车辆位置同步 | 抖动/推挤 | 驾驶每 tick 清零速度、清路径并传送物理体；M26-V2 已做载具间阻挡/车损，V4 已做服务器位置推挤，V5 已做单机多车阻挡，V7 已做每车远端视觉，V9 已做等质量线性冲量与无人车短时滑行，V11 已做分级质量与切向摩擦角速度，V12 已做车型表/车身朝向/转向/侧向抓地与 type/heading 复制 |
| 驾驶员/乘客仍可被僵尸攻击 | 车内受伤/被击退 | V9 给驾驶位、V22 给乘客位加 85% 爪/咬减伤并保留围困致死风险；不做车辆护甲耐久/完全免疫 |
| 断线时正在驾驶 | 玩家/车辆卡住 | 立即释放座位、停车、保存到车辆旁出口；重连步行 |
| 服务器重启无座位状态 | 玩家不会自动回车内 | 明确设计；玩家重新上车 |
| 后备箱共享 | 任意玩家可存取 | T3 明示共享；所有权/锁留后续 |
| PlayerState/ZLR1 版本升级 | 旧客户端不兼容 | v17 尾部兼容旧 v16 负载；旧客户端不能发新命令（含 `TakeDriverSeat=46`） |
| 多客户端抢车 | 双驾驶/状态错乱 | 单驾驶位原子占用；服务器拒绝后到者 |
| 车辆在 AOI 边缘消失 | 远端看不到车 | 驾驶时玩家就是焦点；离开 AOI 属预期，HUD 仍由 owner 状态维持 |
| 30s 周期玩家档案同步保存 | 保存耗时可能超过客户端心跳超时，触发非预期断线 | V6 烟测临时 `--net.playerProfileSaveSeconds=0` 验证；正式服务器仍默认 30s，后续将周期保存异步化并补压力回归 |
