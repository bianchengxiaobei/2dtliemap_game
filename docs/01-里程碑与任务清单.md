# 里程碑与任务清单（主任务文档）

> 这是日常使用的主文档。做任务时把 `- [ ]` 改成 `- [x]`，里程碑全部验收通过后更新 README 状态表并打 tag。

## 使用说明

1. **按里程碑顺序推进**，不跳阶段——后面的阶段都依赖前面的地基。
2. 每完成一个任务就勾选，Git 提交信息引用任务号，例如：`feat(render): sprite batch + atlas (M2-T3)`。
3. 里程碑的「验收」全部通过后：更新 README 状态表 → `git tag v0.N.0`（N=里程碑号）→ 开始下一阶段。
4. 预估是**单人全职**的粗略值；业余时间请乘 1.5~2。
5. 卡壳时先看该阶段的「参考 PZ 源码」——对应类里基本都有原始实现思路（只读思路，不抄代码）。
6. 任务粒度：每个任务 0.5~3 天，如果一个任务做不完 3 天，说明拆分不够，现场再拆。

# M0 环境与工程骨架

**目标**：装好工具链，跑出一个 bgfx 渲染的空窗口。
**交付物**：可编译可运行的最小工程 + 规范的仓库。
**参考 PZ 源码**：无（纯工程准备）。

### 任务

- [x] **M0-T1 安装工具链** — VS2022（勾选 C++ 桌面开发）、CMake、Ninja、Git、vcpkg；设置 `VCPKG_ROOT` 环境变量；命令行验证 `cmake --version` / `ninja --version` / `vcpkg version`
- [x] **M0-T2 创建工程骨架** — 目录结构（见 docs/02）、`vcpkg.json` 依赖清单、`CMakePresets.json`、根 `CMakeLists.txt`、`src/main.cpp` 占位；验证 `cmake --preset x64-debug` 配置成功
- [x] **M0-T3 Hello Window** — GLFW 创建 1280x720 窗口、注册关闭/缩放/按键回调、主循环空转；验证窗口出现并可关闭
- [x] **M0-T4 bgfx 初始化** — 把 GLFW 原生窗口句柄接给 bgfx（PlatformData）、设置 reset 参数（vsync）、每帧 `bgfx::frame()` 清屏、开启 bgfx debug 文本显示 FPS
- [x] **M0-T5 日志系统** — 封装 spdlog：控制台彩色 + 文件轮转（`logs/`），提供 `ZL_INFO/ZL_WARN/ZL_ERROR/ZL_ASSERT` 宏；启动时打印版本/构建时间
- [x] **M0-T6 Git 规范落地** — `.gitignore`（build/、.vs/、vcpkg_installed/、logs/、assets_placeholder_pz/）、首次提交、确认 docs 全部入库

### 验收

- [x] `ZomboidLike.exe` 启动出现窗口，bgfx 调试文本正常显示 FPS
- [x] 控制台 + `logs/` 日志文件都有输出

# M1 核心框架

**目标**：固定 tick 主循环 + 事件总线 + 输入 + 配置，打通"引擎心脏"。
**交付物**：可交互 demo（暂停/倍速/按键事件全部走正式框架）。
**参考 PZ 源码**：`GameTime.java`、`gameStates/GameState.java`、`input/` 目录。

### 任务

- [x] **M1-T1 GameLoop 固定 tick 主循环** — 高精度计时（`std::chrono::steady_clock`）、累加器、固定 60Hz 模拟、FPS/TPS 统计；帧时长超预算时打印警告
- [x] **M1-T2 GameTime 游戏日历** — 年/月/日/时/分结构、tick→游戏时间换算、倍速档位（暂停/1x/2x/3x）、时段判断（白天/夜晚，供渲染调色预留）
- [x] **M1-T3 TaskScheduler 线程池** — 提交任务/批量并行/结果回投队列；线程命名；主线程消费结果队列的钩子（`ProcessBackgroundResults`）
- [x] **M1-T4 EventBus 事件总线** — 字符串键（哈希）+ `std::variant` 载荷；同步派发 + 排队派发（tick 末 flush）；订阅/退订/优先级；定义事件表 v1（见 docs/03 第 5 节）
- [x] **M1-T5 配置系统** — nlohmann-json 加载 `config/game.json`，缺失键用默认值、支持命令行覆盖；热重载按键位配置
- [x] **M1-T6 输入系统** — 原始键盘/鼠标输入 → Action 映射（config 可配键位）；状态机 Pressed/Down/Released；鼠标位置与滚轮
- [x] **M1-T7 Window 封装与 AppState 骨架** — 窗口类（分辨率/全屏/标题/FPS 显示开关）、顶层状态机（Boot → MainMenu → InGame），M1 阶段用 "SandboxState" 占位

### 验收

- [x] F1 暂停、F2 循环倍速，控制台正确打印 tick 数与游戏时间
- [x] `config/game.json` 改键位后重启生效
- [x] 事件总线：按键触发的事件在另一个模块被收到并打印（验证解耦）
- [x] 线程池：提交 100 个模拟加载任务，主线程按序消费结果

**目标**：四级世界结构 + 大世界流式加载跑通。

# M4 ECS、物理与寻路

**目标**：一个能和世界正确交互的玩家：跑动、碰撞、点击寻路；ECS 骨架就位。
**交付物**：玩家在村庄里行走，被墙挡住，点击任意可达格自动走过去。
**参考 PZ 源码**：`iso/IsoMovingObject.java`（移动积分）、`MapCollisionData.java`（寻路与多线程）、`astar/` 库（A* 实现思路）。注意：PZ 本身是 OOP，这里**只借算法，不借结构**；ECS 结构参考 EnTT 官方示例。

### 任务

- [ ] **M4-T1 ECS 骨架（EnTT 接入）** — vcpkg 加 entt；`EcsWorld` 封装（registry + SystemScheduler + 延迟销毁队列）；公共组件定稿（`Position/Velocity/Collider/SpriteRef/StableId`）；实体创建/销毁 API
- [ ] **M4-T2 空间索引 + 渲染收集** — chunk 粒度均匀网格索引（跟随 Position 更新）、`RenderCollectSystem` 收集可见实体进 painter 排序管线的"高度精灵"通道
- [ ] **M4-T3 移动与物理集成** — `MovementSystem`（Velocity→Position 积分）、`PhysicsWorld` 封装（`btDiscreteDynamicsWorld`）、墙/家具静态碰撞体批量生成与卸载、`RigidBody` 组件 + `PhysicsSyncSystem`（组件 ↔ Bullet 双向同步）、调试线框
- [ ] **M4-T4 玩家控制（系统化）** — `PlayerTag` + `LocalControl` 组件、InputSystem（WASD→MoveIntent，等距方向矫正）、占位动画（`AnimState`，4 向 2 帧）
- [ ] **M4-T5 相机跟随** — 平滑跟随 PlayerTag 实体、边缘限制、调试自由相机（开发者模式）
- [ ] **M4-T6 A* 寻路（ECS 化）** — passability 位图（chunk 级缓存、局部重建）、8 向 A*（对角代价修正）、后台线程查询（只读快照）、`PathRequest/PathFollow` 组件 + `PathFollowSystem`
- [ ] **M4-T7 点击移动** — 屏幕拾取 → 目标格校验 → 写 `PathRequest` → 寻路 → 路点跟随（到达/中断/重寻路逻辑）

### 验收

- [ ] 玩家跑动流畅，不会穿墙、卡墙缝可恢复
- [ ] 点击任意可达格自动寻路过去；不可达时给出提示反馈
- [ ] 1000 格路径寻路 < 5ms（后台线程，主线程无感知）
- [ ] 500 个静态碰撞体时物理步进 < 2ms/帧
- [ ] 10000 个简单组件实体 创建/销毁压力测试无泄漏（确认 EnTT storage 复用）
