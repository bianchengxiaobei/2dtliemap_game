> 本文只描述已落地范围，不把未完成的逐车轮接地、悬挂碰撞、持续接触求解或完整刚体求解算作完成。

## 1. 目标与边界

M25-T3/T4 的服务器运行时只维护一辆 `m_serverVehicle`。M26-V1 先解决联机结构性限制：

- 服务器读取存档中的全部 `ecs::Vehicle`，并可配置生成多辆；
- 每辆车拥有独立运行时、驾驶位、两名乘客位、燃料、车况、后备箱、冷却与撞击计数；
- 玩家上下车/维修/加油按命令目标车辆执行，驾驶输入只写入当前乘坐车辆；
- 客户端在交互范围内选择最近的车辆，不把远处车辆误当作可交互目标；
- 单机按 `vehicle.count` 生成多辆，步行靠近任意一辆后绑定并在空驾驶位上车；
- ZLR1 仍按车辆实体复制，不为多车另开协议。

**本轮不做**：

- V9 已补线性冲量、双方速度继承与无人车短时滑行，V10 已补载具间碰撞对驾驶位/乘客的生命伤害，V11 已补分级质量与切向摩擦角速度，V12 已补显式车型数据、持久车身朝向、转向与侧向抓地，V13 已补轮胎转向极限与悬挂姿态，V14 已补低速接触法线冲量；仍不做车轮/悬挂/轮胎受力、持续接触求解或正式刚体求解；V4/V6 的历史行为保留为位置推挤与双方车况结算；
- 超过最近 4 辆/18 格的远端引擎声部不创建；不做正式混音、遮挡/混响、距离曲线调校或多车听感验收；
- 正式多人平衡、正式音效与自然多人试玩验收。

## 2. 服务器实现

### 2.1 运行时与生成

- `ServerVehicleRuntime` 由单例改为 `std::vector<ServerVehicleRuntime> m_serverVehicles`。
- `VehicleStableId()` 返回最小 StableId，兼容旧测试/存档的“主载具”；新增 `VehicleStableIds()` 返回升序列表。
- 读档时接管控件中所有带 `Position` 的 `Vehicle` 实体，而不是只接管第一辆。
- 未达到 `vehicle.count` 时在玩家锚点附近按候选偏移寻找可走 3×3 空地生成；默认 `count=3`，范围 1–16。
- 候选位置与已有车辆保持至少 3 格距离；无空地时下一 tick 重试。
- 载具实体、位置、燃料、车况、车灯、后备箱继续随世界存档；座位只存在运行时，重启后清空。

### 2.2 命令路由

- `EnterVehicle=40`、`EnterVehiclePassenger=45`、`ServiceVehicle=42` 使用 `payload.entityId` 查找目标车辆；不再要求目标等于唯一主车。
- `ExitVehicle=41`、`TakeDriverSeat=46`、`GiveDriverSeat=47`、`ToggleHeadlights=43`、`HonkHorn=44` 通过 `SessionPlayer::drivingVehicleId` 查找当前车辆。
- `Move` 只在驾驶当前车辆时写入该车的 `inputX/inputY`；不会写到其他车辆。
- `PlayerState.vehicle` 优先返回当前乘坐车辆；未乘坐时返回玩家附近 16 格内最近车辆，便于旧 HUD/兼容路径读取，不再固定只返回第一辆。
- `ReleaseServerVehicleSeat`、乘客同步、下车落点、死亡/断线释放都按 StableId 定位车辆。
- 撞击、动物/僵尸攻击、噪音、车况磨损、修理/加油、车灯和喇叭均按车辆运行时独立结算。

### 2.3 客户端

- `WorldDemoState::FindNearestVehicle(range)` 扫描本地 ECS 中同层 `Position + Vehicle`，用于：
  - `VehicleNearPlayer`；
  - E 上下车目标；
  - 维修/加油目标；
  - 后备箱/仓库目标；
  - 车外 HUD 提示。
- 联机非乘坐状态下，`SyncNetworkVehicleBinding` 只绑定 `enterRange` 内最近车辆，不再回退到复制流中的“任意第一辆”。
- 单机非驾驶状态下，`BindNearestLocalVehicle` 在 `enterRange` 内切换当前车辆；切换前把旧车燃料/车况/车灯同步回 ECS，再 `AdoptVehicleEntity` 载入新车。
- 乘坐状态下仍绑定 `PlayerState.vehicle.vehicleStableId`，因此驾驶第二辆/第三辆车时预测、HUD、引擎音和座位同步都切到目标车辆。
- 所有复制载具继续用各自实体/SpriteRef 渲染；`ApplyNetworkDriverVisibility` 遍历所有载具的驾驶员与两名乘客 StableId。
- 驾驶员/乘客隐藏、双乘客占位、接管/让座、后备箱和快捷使用的既有逻辑保持兼容。

### 2.4 载具间碰撞（V2）

- `game::VehicleStep` / `VehiclePredictStep` 新增可选 `VehicleBodyBlocked` 回调：候选位置与同层其他载具圆形重叠时直接阻挡，和墙体/树木使用同一套轴滑动与停住逻辑。
- 服务器 `TickServerVehicle` 把其他 `ServerVehicleRuntime` 作为动态障碍传入；客户端驾驶预测把本地 ECS 中除当前车外的同层 `Position + Vehicle` 作为动态障碍。
- 动态碰撞由 `VehicleStepResult::bodyCollision` 标记；该分支跳过墙体碰撞的单车车损，改由服务器按相对速度统一结算双方车况，避免同一次碰撞扣两次。
- 碰撞相对速度取两车速度差；双方各扣 `vehicleCollisionConditionDamageBase + (相对速度 - 最小速度) * PerSpeed`，上限 `vehicleCollisionConditionDamageMax`，按 `vehicleCollisionCooldownSeconds` 冷却。
- 服务器广播 `kVehicleRam` 撞击音并给双方驾驶员写“车辆碰撞”状态；车况变化通过 `ecs::Vehicle` / ZLR1 复制，客户端不本地扣血/扣车况。
- 不做推挤或动量传递；目标车不会因被撞而自动滑行。

### 2.5 客户端碰撞反馈（V3）

- 客户端 `ApplyNetworkWorldSounds` 处理服务器广播的 `kVehicleRam`：在撞击位置生成与 `kVehicleHit` 相同的火花/金属碎片，并记录“网络载具撞击”日志。
- 镜头震动只在本地正在驾驶且撞击点距本地车辆 8 格内触发，避免远端车辆在任意位置碰撞时抖动本地镜头；网络 `kVehicleHit` 也复用该距离门控。
- 反馈仅修改表现，不改变服务器车况结算、冷却、音效广播、协议或存档；本地驾驶预测仍由服务器权威车况回传，不重复扣车况。

### 2.6 服务器位置推挤（V4）

- `VehicleCollisionPushDistance` 按 `(相对速度 - 最小速度) * PushPerSpeed` 计算，上限 `PushMax`；低于最小速度不推挤。
- 服务器结算碰撞时沿“撞击车 → 被撞车”方向逐步移动被撞车，单步 0.05 格；目标格不可走或被第三辆载具阻挡时提前停止，避免把车推入墙体/障碍/其他车。
- 被撞车位置同步到 `Position`，并立即同步其驾驶员/乘客位置；撞击车仍由动态车身回调停住，不反向位移。
- 推挤复用碰撞冷却（0.75s）与车况结算；不做质量、速度继承、持续冲量或乘员伤害。
- 客户端不预测推挤，收到服务器位置/车况后校正；协议与存档 schema 不变。

### 2.7 单机多车（V5）

- `EnsureVehicleSpawned` 改为统计 ECS 中全部 `Position + Vehicle`，按 `vehicle.count`（1–16）补足；首个候选沿用 `spawnOffsetX/Y`，其余使用 6/10/14 格候选偏移，保持车辆间距并避开不可走格。
- 新增 `SpawnLocalVehicle` 统一创建位置、精灵、碰撞体、`Vehicle`、后备箱与存储；所有单机车辆随世界存档保存。
- `BindNearestLocalVehicle` 在非驾驶、背包关闭时只绑定 `enterRange` 内最近车辆；切换前同步旧车燃料/车况/车灯到 ECS，再恢复新车运行时。
- 单机驾驶把其他 `Position + Vehicle` 作为 `VehicleBodyBlocked` 动态障碍；完全阻挡时按 `vehicleCollisionConditionDamage*` 对当前车与目标车各扣一次车况，使用 `vehicleCollisionCooldownSeconds` 冷却，生成既有火花/撞击音提示。
- V5 不推挤停放车辆、不做质量/动量/乘员伤害；非绑定车辆只显示基础精灵和静态碰撞，不更新每车车灯/破损外观（V7 已补）。

### 2.8 单机停放车推挤（V6）

- `game::VehiclePushBody` 统一按 `VehicleCollisionPushDistance` 的结果做 0.05 格分步推挤；每步检查目标格阻挡与第三辆车，方向自动归一化，非法/零距离输入原地返回。
- 单机 `ApplyLocalVehicleVehicleCollision` 在双方车况结算后调用 `PushLocalVehicleOnCollision`：沿“本车 → 目标车”方向一次性推开被撞车，单机 ECS `Position` 立即更新并按世界存档保存；目标格/第三辆车阻挡时提前停止。
- 服务器 V4 推挤改为复用同一 `VehiclePushBody`，行为与原先 0.05 格步进、第三辆车检查和 0.8 格上限一致；仍同步推挤后的载具/乘员位置。
- V6 只做一次性位置推挤，不保留被撞车速度/质量、不做持续冲量或乘员伤害，不改变协议/存档 schema；非活动车辆仍不持续模拟移动。

### 2.9 每车远端视觉（V7）

- 服务器 `ServerVehicleRuntime` 新增 `visualDirection`；每次 `SyncServerVehicleToEcs` 按当前速度用 `VehicleVisualDirectionFor` 更新八向朝向，停车时保留最后方向，并把对应 `object.vehicle_*` 写入 `SpriteRef`，随既有 ZLR1 复制到客户端；读档接管时从已有精灵恢复方向。
- 客户端 `UpdateVehicleVisual` 维护按 StableId 的 `m_vehicleVisualDirections`：本地绑定车继续用平滑朝向与八向滞回选帧；其他车辆从复制精灵/速度恢复朝向，供车灯和烟雾定位使用。单车切换绑定或网络绑定切换时会从当前精灵恢复朝向，避免回退为南向。
- `DrawVehicleHeadlights` 遍历视野内所有 `Position + Vehicle` 且 `headlights=true` 的车辆，分别按本地平滑朝向、复制速度或缓存八向朝向绘制光束；停放的已开车灯车辆也保留光束，不再只有当前绑定车。
- `DrawVehicleDamageVisual` 改为对每个载具 DrawItem 按 StableId 查 `m_vehicleDamageVisuals` 并叠加划痕/凹陷；`UpdateVehicleDamageVisual` 遍历全部车辆并更新日志。`UpdateVehicleDamageSmoke` 改为按 StableId 维护计时器，遍历所有受损车辆生成软粒子烟雾（全局上限 96），不再只服务当前绑定车。
- V7 只改复制/表现，不改变碰撞/推挤/车况/存档 schema；不新增命令、`PlayerState` 字段或网络包；多辆远端车仍共用最近一辆的引擎音（V8 已补多车远端声部）。

### 2.10 多车远端引擎音（V8）

- `VehicleSpike.h` 新增 `VehicleEngineAudioCandidate` 与 `SelectRemoteVehicleEngineAudio`：按 `remoteDriven`、车况 > 0、与监听者距离 ≤ 18 格筛选，按距离升序（同距按 StableId）取最近最多 `kVehicleRemoteEngineMaxVoices=4` 辆；非法坐标/NaN/重复 StableId 安全跳过。
- 客户端 `m_vehicleEngineVoices` 从单个句柄改为按 StableId 维护句柄映射；本地驾驶车辆继续用本地优先声部，其他已复制 `VehicleDriver` 的车辆在监听者 18 格内创建独立远端循环；驾驶员退出、车况归零、载具超出范围或断线时对应声部停止。
- 每个声部用 `VehicleEngineToneForSpeed` 按各自速度更新音量/音高和位置；本地声部优先，避免同一车辆双重引擎声。所有声部复用既有 `vehicle_engine` 资源与 `Play3D`，不新增音频资源、命令、复制字段或存档 schema。
- V8 不改变 V7 车身视觉/灯光/破损/烟雾，不改变碰撞/推挤/车况；多个远端声部仍受 AudioEngine 全局 `maxVoices` 限制。

### 2.11 碰撞冲量与残余滑行（V9）

- `VehicleSpike.h` 新增 `VehicleCollisionImpulseFor`：按两车中心法线计算接近速度，使用等质量线性冲量（默认质量 1:1）和可调恢复系数（默认 0.20）分配碰撞后速度；保留切向分量，位置重合时用第一辆车速度方向或 +X 兜底，NaN/非法质量/低于 `vehicleCollisionMinSpeed` 返回未应用。
- 服务器在 V2/V4 碰撞结算中同时把冲量写回双方 `VehicleMotion`：撞击车失去部分速度，被撞车获得速度；被撞车若无人驾驶且仍有残余速度，`TickServerVehicle` 以 `vehicleCoastBraking`（默认 3.0 格/秒²）调用 `VehiclePredictStep` 滑行，不消耗燃料、不追加车损，撞到墙体/第三辆车或速度低于 0.05 时停止。
- 单机 `WorldDemoState` 新增 `m_localParkedVehicleMotions`：撞击后当前车和被撞停放车获得冲量速度；被撞车按 StableId 保存残余 `VehicleMotion`，每 tick 用 `VehiclePredictStep` 更新 ECS `Position`/`Velocity` 并滑行，速度耗尽或碰到障碍后移除；当前车保留可用速度继续驾驶。
- `VehicleStepResult` 新增 `bodyContact`：即使动态车身只造成轴滑动、没有完全阻挡，也会触发本地/服务器的载具碰撞结算，避免侧向接触绕过 V2/V6 的碰撞路径；完整阻挡仍使用 `bodyCollision`。
- V9 只做线性等质量冲量、位置分离和短时残余滑行；V11 已补分级质量与切向摩擦角速度，但仍不做完整刚体朝向、持续冲量、碰撞乘员伤害或轮胎抓地模型。仍复用现有命令/复制字段/存档 schema；V9 新增 `vehicleCollisionRestitution` 与 `vehicleCoastBraking`，V11 新增 `vehicleCollisionFriction` 与 `vehicleAngularDamping`。

### 2.12 碰撞乘员伤害（V10）

- `VehicleSpike.h` 新增 `VehicleCollisionOccupantDamage`：以 `vehicleCollisionMinSpeed` 为门槛，按 `base + (impactSpeed - minSpeed) × perSpeed` 计算 HP 伤害，并受 `max` 上限钳制；NaN/非法配置返回 0。
- 服务器在 V2/V4/V9 的载具间碰撞结算中，对碰撞双方分别遍历驾驶位、第一乘客位和第二乘客位；每名存活乘员收到一次 `Blunt` 伤害事件，伤害事件不施加击退/硬直，避免把车内玩家挤出座位。伤害实际值受既有护甲钝击减伤影响，随后通过 `stateDirty`/`PlayerState` 同步生命。
- 单机在 `ApplyLocalVehicleVehicleCollision` 中对当前驾驶玩家结算同规则生命伤害，并显示 `碰撞受伤：-X HP` 提示；服务器日志为 `服务器载具碰撞乘员伤害`，单机日志为 `单机载具碰撞乘员伤害`。
- V10 只做载具间碰撞的乘员生命伤害与提示；撞墙/撞僵尸/撞动物仍走各自既有车况、驾驶员减伤与反馈路径，不新增协议、命令、复制字段或存档 schema；新增 `vehicleCollisionOccupantDamageBase/PerSpeed/Max` 三个配置项。乘客槽位复用同一循环，未单独构造乘客碰撞 1280 烟测。

### 2.13 分级质量与碰撞角动量（V11）

- `VehicleSpike.h` 新增 `VehicleMassClass`（轻/标准/重）与 `VehicleMassClassForStableId`：当前只有一种皮卡外观，因此按车辆 StableId 稳定循环分级，轻/标准/重质量分别为 0.85/1.0/1.35；`VehicleMassForStableId` 供单机与服务器共用，不写存档、不新增复制字段。车外/驾驶/乘客 HUD 显示当前车辆质量档位。
- `VehicleCollisionImpulseFor` 的法线冲量改用双方质量计算；速度分配满足动量守恒，重点车撞轻车时轻车获得更高速度，反之重点车保持更多速度。质量只参与载具间碰撞，不改撞墙/撞僵尸/撞动物路径。
- 新增 `vehicleCollisionFriction`：按法线冲量上限计算切向摩擦冲量，并把切向速度变化写回双方；同时用 `VehicleAngularInertia` 计算角速度。接触半径取车辆圆形碰撞半径，角速度以 `kVehicleMaxAngularVelocity` 钳制；NaN/零质量/非法半径安全返回。
- `VehicleMotion` 新增运行时 `angularVelocity` 与 `spinAngle`；`VehicleIntegrateAngular` 在 `VehicleStep`/`VehiclePredictStep` 中按 `vehicleAngularDamping` 积分并阻尼回正。`VehicleVisualDirectionForMotion` 把 `spinAngle` 叠加到八向外观，服务器通过既有 `visualDirection`/`SpriteRef` 复制，单机活动车与 `m_localParkedVehicleMotions` 中的停放车共用该表现；不新增命令、协议或存档 schema。
- V12 起 `VehicleMotion.heading` 是持久车身朝向，转向、侧向抓地、碰撞力矩和视觉八向选帧共用它；旧 `spinAngle` 已移除。V14 已补低速接触冲量，但仍没有车轮/悬挂、轮胎受力、持续接触求解或正式刚体求解，视觉仍受八向资源限制。联机通过 ZLR1/PlayerState 复制 heading，本地预测只做平滑校正。

### 2.14 显式车型与完整车身朝向（V12）

- 新增 `ecs::VehicleType`（`LightPickup/Pickup/HeavyPickup`）和 `VehicleProfile` 表：轻型皮卡/标准皮卡/重型皮卡，质量 **1100/1600/2400 kg**，碰撞半径 **0.60/0.65/0.65 格**，车长/车宽 **2.10×1.00 / 2.35×1.10 / 2.60×1.20 格**；极速/加速/制动倍率、转向速率、侧向抓地、车况伤害倍率、乘员伤害倍率也在同一表内。车型不再只由 StableId 临时推导，`ecs::Vehicle.type` 持久化并在生成时按 StableId 分配。
- `VehicleMotion` 新增运行时 `heading`（弧度，0=+X）和 `type`；`VehicleIntegrateAngular` 把角速度积分到 heading，不再维护 `spinAngle`。`VehicleStep` 先按转向速率把 heading 转向输入方向（低速直接对齐），再沿 heading 加速，并按 `lateralGrip` 衰减侧向速度；碰撞切向冲量继续产生 `angularVelocity`，由下一步积分改变车身朝向。视觉八向选帧、服务器 `visualDirection`、本地活动车/停放车统一使用 heading。
- 单机/服务器按车型生成 `VehicleTuningForType`：极速/加速/制动/半径/转向/抓地按 profile 缩放，质量用于冲量，半径用于碰撞和角惯量；质量还按源/目标质量缩放推挤距离，车况与乘员伤害按车型倍率缩放。HUD 显示车型、质量 kg；服务器日志生成时显示车型/质量。
- 持久化与复制：`ecs::Vehicle` 追加 `type/heading`；存档 Vehicle 组件版本 **v3** 追加 type byte + heading float，旧档回退标准皮卡/南向。ZLR1 `VHCL` 负载从 33B 扩为 **37B**（flags 的 bit1-2 存 type，追加 heading），复制组件版本升 **v4**、`Vehicle` maxBytes 40B。`PlayerState` 升 **v19**，载具字段追加 type/heading；服务器权威写入，客户端预测用 `VehicleCorrectHeading` 平滑校正。
- 不新增命令或配置项；`vehicleCollisionFriction`/`vehicleAngularDamping` 继续控制切向冲量和角速度衰减。转向/抓地/车型表是代码常量，后续可迁移为外部车辆数据。
- V14 已补低速接触冲量；仍不做车轮/悬挂、轮胎受力、持续接触求解、完整刚体求解或八向以外的精确朝向渲染；视觉仍受现有八向皮卡资源限制，重型车碰撞半径不放大到标准车以上以保持狭窄道路通行。

### 2.15 轮胎转向极限与悬挂姿态（V13）

- `VehicleProfile` 追加每车型轴距、轮距、最大前轮转角、最大轮胎横向加速度、悬挂频率/阻尼比和 roll/pitch 增益：轻卡 **1.02/0.84 格、0.92 rad、20 格/秒²**，标准皮卡 **1.15/0.90 格、0.85 rad、18 格/秒²**，重卡 **1.28/0.98 格、0.72 rad、15 格/秒²**；`TrackWidth` 目前只作为数据和后续扩展基础，不参与单车轮胎宽度受力。
- 新增 `VehicleTireYawRate`：以前轮转角、轴距和车速计算自行车模型横摆角速度，再按 `turnRate` 和 `maxLateralAcceleration / max(speed, 0.5)` 双重钳制。高速转弯因此出现转向不足；横向加速度上限为 0 时不允许横摆，NaN/非法参数返回 0。
- `VehicleStep` 先由车身朝向与输入方向误差求出前轮转角（受 `maxSteerAngle` 限制），再用 `VehicleTireYawRate` 更新 heading；低速仍直接对齐输入方向。原侧向抓地衰减保留，用于产生侧滑与回正。
- `VehicleMotion` 新增运行时 `steerAngle/lateralAcceleration/longitudinalAcceleration/bodyRoll/bodyRollVelocity/bodyPitch/bodyPitchVelocity`。`VehicleSuspensionStep` 以弹簧-阻尼趋近目标 roll/pitch，目标由横向加速度和纵向加速度映射；非法 dt/加速度安全归零。姿态只存在运行时，不写存档、不复制、不新增命令或协议。
- 路面横向附着：铺装 1.0、泥土路 **0.90**、草地 **0.62**；只缩放轮胎横向加速度上限，和 V3 的极速/加速/制动倍率共用 `VehicleSurfaceProfile`。
- V14 已补低速接触冲量；仍不做逐车轮接地采样、轮胎纵向滑移/ABS、悬挂碰撞、车身姿态渲染旋转、持续接触求解或完整刚体求解。V13 的 1280 回归仅重跑 V5 单机多车烟测；未补稳定的双车碰撞/乘客 1280 构造烟测。

### 2.16 低速持续接触冲量（V14）

- 新增 `kVehicleContactMinSpeed=0.15f` 与 `VehicleContactImpulseFor`：当载具间已经发生动态车身接触、但接近速度低于 `vehicleCollisionMinSpeed`（默认 2.0）时，仍按双方质量分配完全非弹性法线冲量；接触路径关闭恢复系数与切向摩擦，避免低速推挤反复弹跳/旋转。
- `VehicleCollisionImpulseFor` 追加可选 `minClosingSpeed` 参数，默认仍使用 `vehicleCollisionMinSpeed`；V9 的高速碰撞、车况伤害、乘员伤害、推挤、音效与冷却逻辑保持不变。
- 服务器 `ApplyServerVehicleVehicleCollisions` 在 `bodyContact`/`bodyCollision` 时同时计算接触冲量：低于车损门槛只改速度并同步目标 `Position`/`Velocity`/乘员，目标无人时由既有 `vehicleCoastBraking` 滑行；不扣车况、不伤乘员、不广播 `kVehicleRam`、不设置碰撞冷却。达到车损门槛仍走原有高速路径。单机 `ApplyLocalVehicleVehicleCollision` 使用同一纯逻辑，低速目标写入 `m_localParkedVehicleMotions` 后由既有滑行逻辑移动。
- 接触路径只传递接近速度，不做位置分离、持续法向约束或高速持续推力；目标被墙体/第三辆车卡住时只保留速度，不强制挤出。低速度阈值是代码常量，不新增命令、复制字段、`PlayerState`、协议或存档 schema。
- 由于接触路径不进入 `vehicleCollisionCooldown`，持续低速顶推会逐 tick 重新评估接近速度；正常分离后自然停止。服务器/单机接触日志使用 debug 级别，避免持续推挤刷 info 日志。

## 3. 配置

`config/game.json`：

```json
"vehicle": {
  "count": 3,
  "spawnOffsetX": 6,
  "spawnOffsetY": 6,
  "spawnSearchRadius": 3,
  "vehicleCollisionMinSpeed": 2.0,
  "vehicleCollisionConditionDamageBase": 0.01,
  "vehicleCollisionConditionDamagePerSpeed": 0.008,
  "vehicleCollisionConditionDamageMax": 0.1,
  "vehicleCollisionOccupantDamageBase": 3.0,
  "vehicleCollisionOccupantDamagePerSpeed": 1.2,
  "vehicleCollisionOccupantDamageMax": 20.0,
  "vehicleCollisionCooldownSeconds": 0.75,
  "vehicleCollisionPushPerSpeed": 0.12,
  "vehicleCollisionPushMax": 0.8,
  "vehicleCollisionRestitution": 0.2,
  "vehicleCoastBraking": 3.0,
  "vehicleCollisionFriction": 0.35,
  "vehicleAngularDamping": 3.0
}
```

`vehicle.count` 是单机/服务器的最小目标数量；存档中已有更多载具时全部接管。设为 1 可回到旧的单车行为。碰撞配置由客户端与服务器解析并钳制；服务器使用同一组参数结算。V5 单机沿用同一组碰撞参数做位置阻挡与双方车况，V6 起单机也使用 `vehicleCollisionPushPerSpeed/Max` 执行位置推挤，V9 起两侧再用 `vehicleCollisionRestitution` 分配碰撞后速度并用 `vehicleCoastBraking` 控制无人车滑行，V10 起按 `vehicleCollisionOccupantDamageBase/PerSpeed/Max` 对车内乘员结算生命伤害，V11 起用 `vehicleCollisionFriction` 产生切向冲量/角速度并用 `vehicleAngularDamping` 衰减角速度；V12 车型质量/尺寸/性能与 V13 轴距/前轮转角/横向加速度/悬挂姿态是 `VehicleSpike.h` 的 `VehicleProfile` 表，`ecs::Vehicle.type` 随存档/ZLR1/PlayerState 持久化，旧档回退标准皮卡；V13/V14 不新增 `config/game.json` 项，V14 的接触门槛 `kVehicleContactMinSpeed` 与接触冲量规则是代码常量。V7 不新增配置，复用既有 `SpriteRef`、车况和车灯复制。V8 也不新增配置；远端引擎声部上限（4）和可听距离（18 格）是 `VehicleSpike.h` 常量，复用既有 `vehicle_engine` 音频资源。
