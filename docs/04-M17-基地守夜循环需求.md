# M17 基地守夜循环 2.0（需求稿）

> 状态：已完成，2026-10-24。T1 耐久持久化、T2 维修/拆除、T3 夜间基地尸潮、T4 闭环验收均已完成并通过实机验收。
> 依赖：M16 基地建造与防御已完成；M15-T6 平衡与端到端验收暂缓。
> 定位：先把 M16 的“搜刮 → 建造 → 守夜 → 被破坏 → 再修/再建”闭环做完整，不扩联机建造、不扩美术。

## 1. 背景与当前缺口

M16 已经支持单机建造木栅栏、篝火、工作台，僵尸会拆栅栏，建筑随 chunk 存档。但当前循环仍然是断裂的：

- 栅栏 HP 不持久化，重载后回满，守夜损失没有意义。
- 没有维修/拆除，损坏后只能重建，基地无法维护。
- 没有夜间尸潮/基地事件，玩家没有“为什么现在要建、要守”的压力。
- 存档/读档、破坏、重建之间缺少端到端验收。

M17 只解决这四件事，让玩家能在一个完整夜晚里感受到“建造有代价、损失可恢复、基地值得守”。

## 2. 目标

1. 玩家建造的结构在存档、chunk 卸载/重载、退出重进后保留耐久。
2. 玩家可以维修受损结构、拆除己方结构并取回部分材料。
3. 单机夜晚会出现有预警、有波次、可结束的基地尸潮；僵尸会攻击栅栏。
4. 一次完整循环可实机验收：搜刮木材 → 建造 → 守夜 → 栅栏被破坏 → 维修/重建 → 存档重载。

## 3. 非目标

- 不做联机建造/拆除同步；联机模式继续不支持建造。
- 不做储物箱、完整建造 UI、墙体连接、建筑旋转、建筑升级。
- 不做感染/疾病、NPC、车辆、大地图。
- 不做尸潮中途存档恢复；读档后取消进行中的事件（见风险）。
- 不新增正式美术/音频资源，复用现有 HUD、音效和占位帧。

## 4. 玩家体验闭环

### 白天

- 搜刮木材，选择地点建造木栅栏；篝火/工作台作为制作站。
- 栅栏受损后可按 `H` 维修；建造模式下可按 `X` 拆除己方结构并返还部分木材。

### 夜晚

- 22:00 前，如果玩家附近有己方结构，HUD 出现守夜预警和倒计时。
- 预警结束后按波次生成僵尸；僵尸优先接近玩家，遇到栅栏阻挡时攻击栅栏。
- HUD 显示当前波次、剩余僵尸/栅栏状态；栅栏被摧毁后有明确提示。
- 三波清完或天亮后事件结束，显示“守夜结束/基地损失”。

### 第二天

- 玩家用木材维修或重建栅栏。
- 保存、退出、重载后，栅栏当前 HP 仍保留；被摧毁的栅栏不会复活。

## 5. 任务与需求

### M17-T1 建筑耐久持久化

**目标**：玩家建造的结构不再“重载回满”，并把结构元数据纳入现有 chunk 存档。

**需求**

- 记录每个玩家建造结构的：所在格、层、sprite、当前 HP、是否为玩家建造。
- 木栅栏保存当前 HP/maxHP；篝火、工作台等无 HP 结构保存“玩家建造”标记，供拆除使用。
- 以下路径都必须保留 HP：
  - `F12` 快速存档 → 退出 → 继续游戏；
  - 自动存档/退出存档；
  - chunk 卸载 → 重新加载（同一会话）；
  - 读档后再次保存。
- 被摧毁的结构不得在读档后复活；损坏的结构不得回满。
- 地图自带的 `object.barricade` 等静态对象不算玩家建造，不参与维修/拆除，也不因缺少元数据而报错。
- 旧版 chunk diff（v1）必须可读：旧结构按满 HP 加载，不因字段缺失失败。
- 新格式写入失败的日志必须包含 `[building]`/`[save]` 上下文，不能静默丢耐久。

**建议数据模型**

- 在 `world::SquareObject` **末尾**增加可选字段，避免破坏现有聚合初始化：
  - `float hp = -1.0f;`（`<0` 表示无耐久/非可损坏结构）
  - `bool playerBuilt = false;`
- `maxHp` 仍由 `BuildableDef` 按 sprite 解析，避免重复存配置值。
- `ChunkDiff` 版本升到 v2，编码 HP/玩家建造标记；解码兼容 v1。
- `TrackNearbyBarricades` 只收集 `playerBuilt` 对象，并从对象 HP 恢复，不得把已有结构重置为 max。
- `m_barricades` 继续作为运行时缓存；所有伤害/维修/拆除同时更新对象字段。

**验收**

- [x] 新建栅栏打到 60/120 HP，存档重载后仍为 60/120。
- [x] 摧毁栅栏后保存重载，该格没有栅栏、没有耐久记录、碰撞和 A* 仍为可通过。
- [x] 篝火/工作台保存重载后仍在，且可继续作为制作站。
- [x] 旧 v1 存档可加载，不崩溃；旧栅栏按满 HP 处理。
- [x] 单测覆盖对象编码/解码、v1 兼容、HP 往返和“摧毁后不复活”。

### M17-T2 维修与拆除

**目标**：让损坏结构可恢复、己方结构可回收，避免只能无限重建。

**交互**

- `H`：维修最近的可维修结构（默认 2.5 格内）。仅对玩家建造且当前 HP < maxHP 的栅栏生效。
- `X`：建造模式下拆除最近的玩家建造结构。非建造模式不响应，避免误拆。
- 维修/拆除都只作用于玩家建造结构；地图自带对象不可操作。
- 维修消耗 1 木材，恢复 30 HP，不能超过 maxHP；木材不足/已满/距离内无目标时给出明确提示。
- 拆除返还 `ceil(woodCost * 0.5)` 木材：木栅栏 2、篝火 1、工作台 2。
- 拆除后立即移除对象、更新物理静态体与 A*，并清除结构元数据。
- 维修/拆除增加短冷却（默认 0.5 秒），避免按住键每帧重复执行。

**HUD/提示**

- 靠近可维修栅栏时提示 `H 维修（1 木材 +30）`。
- 建造模式下靠近己方结构时提示 `X 拆除（返还 N 木材）`。
- 成功/失败都通过 HUD notice 与 `[building]` 日志反馈。

**验收**

- [x] 30/120 栅栏按 3 次 `H` 恢复到 120，消耗 3 木材；满血/无木材时不消耗。
- [x] 拆除木栅栏返还 2 木材，对象消失、碰撞与 A* 恢复。
- [x] 拆除篝火/工作台返还对应木材，制作站扫描不再命中。
- [x] 地图自带 barricade 不能被维修/拆除。
- [x] 单测覆盖费用、上限、无目标、非己方对象和返还数量。

### M17-T3 夜间基地尸潮

**目标**：给基地循环增加可预警、可结束、可验收的夜间威胁。

**触发**

- 仅单机；联机模式不触发、不生成。
- 每晚最多一次；以游戏内 `hour` 判断，默认 22:00 进入预警。
- 玩家 12 格内至少有一座玩家建造结构时才会触发；否则当晚跳过。
- 预警默认 30 秒（真实时间，暂停时暂停计时），HUD 显示倒计时。
- 预警结束后进入波次；默认 3 波，每波 `4/6/8` 只，最大同时存活 12 只。
- 波次间隔默认 45 秒；三波全部生成且事件僵尸清空，或到 05:00，事件结束。

**生成与行为**

- 以预警时玩家位置为“基地中心”，在 10~14 格环形范围寻找已加载、可站立格生成。
- 复用 `WorldSimulation::SpawnZombieAt`，生成后设置 `AiState::Chase`、目标玩家、感知最后已知位置。
- 事件僵尸应进入正常 AI/物理/战斗链；被栅栏阻挡时复用 M16 的栅栏攻击逻辑。
- 事件僵尸用 StableId 记录，并标记为 BaseSiegeZombie，不参与 SpawnLod 人口统计/虚拟化；事件结束/中止时清理事件生成的残余僵尸（不清理原有世界僵尸）。
- 事件期间不改变全局 `spawner.demoZombies` 人口配置。

**HUD**

- 预警：`守夜将至 00:30`，显示基地中心附近结构数量。
- 波次中：`守夜 第 1/3 波 | 存活 4 | 栅栏 3/4`。
- 结构全毁：提示 `基地失守`；玩家仍可继续战斗。
- 结束：`守夜结束：损失 2 座栅栏`。
- 复用现有 HUD 文本/notice/音效，不新增 UI 资源。

**中止**

- 玩家死亡、返回主菜单、读档、联机切换时立即中止事件。
- 玩家离开基地中心超过 25 格时中止并提示，避免僵尸在空基地空转。
- **保存即中止**：事件进行中触发快速存档/退出自动存档时，先取消事件并清理本次事件生成的僵尸，再采集存档快照；不把波次状态或事件僵尸写入存档，避免读档后无预警围攻。
- 读档不恢复进行中的波次；读档后事件回到空闲状态。

**验收**

- [x] 新存档在 22:00 前建造至少一座栅栏，能看到 30 秒预警，随后出现三波僵尸。
- [x] 僵尸会攻击栅栏，栅栏 HP 下降/被摧毁，HUD 波次和结构状态同步。
- [x] 三波清完或到 05:00 事件结束，不残留事件僵尸，不重复触发同一晚。
- [x] 事件中保存后事件取消且事件僵尸不落入存档；读档不出现无预警围攻；玩家死亡/离开基地会中止。
- [x] 事件最大 12 只同时存活时，Release 保持 60fps 目标；无资源缺失日志。
- [x] 单测覆盖触发条件、波次计数、结束/中止和重复夜晚防重。

### M17-T4 闭环验收与平衡

**目标**：证明玩家不依赖 F6/F7/控制台也能完成一次基地循环。

**验收**

- [x] 新存档 30~60 分钟：搜刮木材 → 建造至少 1 栅栏 + 篝火/工作台 → 守夜 → 维修 → 再存档重载。
- [x] 不出现“栅栏重载回满”、结构丢失、重复结构、碰撞残留或 A* 不可达。
- [x] 联机模式按 `B` 仍提示不支持建造；M16 的联机拒绝逻辑不回退。
- [x] C++ Debug/Release、Python 资源/工具测试全绿；无资源缺失日志。
- [x] 更新 README、docs/01、docs/devlog、配置说明；记录测试数量与实机结论。

## 6. 配置草案

```json
"baseEvent": {
  "enabled": true,
  "minStructures": 1,
  "startHour": 22,
  "endHour": 5,
  "warningSeconds": 30,
  "waveIntervalSeconds": 45,
  "waves": [4, 6, 8],
  "maxAlive": 12,
  "triggerRadius": 12,
  "spawnRadiusMin": 10,
  "spawnRadiusMax": 14,
  "leaveRadius": 25
}
```

数值全部可调；不在代码中硬编码波次、伤害或预警时长。测试可临时把 `startHour` 设为 21、`warningSeconds` 设为 3 缩短验收时间。

## 7. 技术方案建议

### 7.1 结构元数据

优先把 HP/玩家建造标记放进 `SquareObject` 末尾，原因是 chunk 卸载、自动存档、快速存档都走同一套 `ChunkDiff`，不需要额外的 sidecar 文件同步。

必须同步修改：

- `SquareObject` 的聚合比较/拷贝/基线捕获；
- `ChunkDiff` 的 v2 编码/解码、校验和 v1 兼容；
- `MapLoader`/`ApplyChunkData` 的默认字段；
- `TrackNearbyBarricades` 的 HP 恢复；
- `tests/test_chunk_diff`、`test_entity_save`/存档相关测试。

### 7.2 建造操作

- 结构维修/拆除建议抽成 `BuildingActions.h` 或 `WorldDemoState` 内部纯逻辑，输入、扣料、对象删除通过回调注入，便于单测。
- 维修/拆除必须复用现有库存原子扣料和 `ReturnOrDropItem` 返还逻辑。

### 7.3 尸潮

- 建议新增 `game/BaseSiege.h/.cpp` 状态机（Idle/Warning/Waves/Finished），通过回调注入：
  - `Now`、`IsNight`、`PlayerPos`、`StructureCount`；
  - `SpawnZombieAt`、`FindWalkableCell`、`AliveCount`；
  - `SetHud`、`Notice`、`EmitEvent`。
- `WorldDemoState` 只负责把游戏上下文接入状态机，避免把波次/计时/生成坐标塞进 5000 行的世界状态。
- 事件僵尸记录 StableId，清理时按 ID 检查存活，避免 entt handle 回收导致误删。
- 复用 M16 的 `BarricadeDefense`；不要为尸潮另写一套拆栅栏逻辑。

## 8. 测试计划

### 自动测试

- `test_chunk_diff`：v2 往返、v1 兼容、HP/玩家建造标记、损坏/摧毁后保存。
- `test_building`：维修费用与上限、拆除返还、非己方对象拒绝、A*/碰撞重建。
- `test_base_siege`：触发条件、预警、波次、最大存活、结束、中止、重复夜晚。
- `test_script_ui`/`test_ui`：HUD 新文案/元素存在；不破坏现有背景点击透传。
- Python 资源/工具测试保持全绿。

### 实机验收

- 新建存档，使用 `--game.startHour=21` 或 F2 加速到 21:50。
- 建造一座栅栏，等待预警，确认三波、HUD、攻击、摧毁、结束。
- 维修到满血，存档重载，确认 HP 保留；摧毁一座后保存重载，确认不复活。
- 联机模式进入世界后按 `B`，确认拒绝建造。
- 观察 12 只事件僵尸时帧率、日志无报错。

## 9. 风险与降级

| 风险 | 影响 | 降级 |
|---|---|---|
| 存档格式 v2 兼容出错 | 旧存档无法加载/结构丢失 | 先实现 v1 兼容与 fixture 测试；读取失败时按旧数据满 HP 降级并记录 |
| 僵尸绕开栅栏，不触发攻击 | 守夜体验不成立 | 事件生成点优先选栅栏外侧；保留 M16 1.5 格攻击判定；必要时给事件僵尸增加“阻挡时优先拆栅栏”状态 |
| 事件与 SpawnLod/演示人口冲突 | 事件僵尸被虚拟化/重复生成 | 事件僵尸记录 StableId，禁用其事件期间的 LOD 回收；不修改全局人口 |
| 中途存档/读档 | 半波状态复杂、可能刷怪 | 保存即中止：先取消事件并清理本次事件僵尸，再采集快照；不持久化波次 |
| 维修/拆除误操作 | 玩家损失建筑 | `X` 仅建造模式生效；维修/拆除都需要 2.5 格内目标与明确提示 |
| 性能 | 12 只 + 演示人口掉帧 | 事件波次上限、生成预算、Release 验收；必要时降低 `maxAlive` |

## 10. 待确认决策

- `H`/`X` 键位是否接受，或改为建造模式右键菜单/`E` 上下文。
- 维修消耗是否固定 1 木材 +30 HP，还是按缺失 HP 比例扣料。
- 拆除返还是 50%（当前建议）还是 30%。
- 守夜是否每晚触发，还是首次建造后只触发一次；当前按“每晚最多一次”。
- 是否需要在守夜结束后给补给奖励；当前不做，保持范围。
- 是否允许在守夜中维修；当前允许，风险换资源。

## 11. Definition of Done

- M17-T1~T3 实现完成，T4 验收通过。
- 一次无调试命令的 30~60 分钟实机循环可完成。
- 结构 HP 在存档/重载/chunk 重载后保持；摧毁不复活。
- 维修/拆除费用、返还、碰撞、A*、HUD 全部有自动测试。
- 夜间尸潮可预警、可结束、可中止，事件僵尸不残留。
- C++ Debug/Release、Python、联机拒绝建造冒烟全绿。
- README、docs/01、docs/devlog、配置文档同步更新。
