# 脚本系统设计（Lua 主 / Python 可选）

> 适用阶段：M7（Lua）、M8（Python 开关）。实现任务见 `01-里程碑与任务清单.md`。
> 前置说明：PZ 用的 Kahlua 是 Lua 5.1 的 **Java** 实现，C++ 无法使用；本项目的等价物是官方 **Lua 5.4 + sol2**。

---

## 1. 设计目标

1. **游戏不改 C++ 就能扩展**：mod 通过事件 + Host API 改变/增加游戏行为；
2. **双后端等价**：同一套 Host API 契约、同一套事件名；后端差异对 mod 作者尽可能透明；
3. **可切换**：编译期开关（是否带 Python）+ 运行期配置（默认后端）双层控制；
4. **错误隔离**：mod 报错/死循环不能崩游戏；日志能定位到 mod 与行号；
5. **热重载**：改脚本不重启游戏。

---

## 2. 后端选择机制

| 层级 | 机制 |
|---|---|
| 编译期 | CMake 选项 `ZL_ENABLE_PYTHON=ON/OFF`（默认 OFF）。OFF 时整个 PythonRuntime 不编译，游戏不引入 Python 依赖 |
| 运行期 | `config/game.json` → `"script": { "enabled": true, "backend": "lua" }`，决定"没有声明 backend 的 mod"用哪个后端 |
| 每个 mod | `mod.json` 的 `"backend": "lua" | "python"` 字段，可显式指定；两后端可同时加载各自的 mod（ScriptManager 同时持有多个 runtime 实例） |

加载流程：

```
ScriptManager.Initialize(config)
  → 按配置创建 LuaRuntime（总是有）
  → 若 ZL_ENABLE_PYTHON：按配置创建 PythonRuntime
ModLoader.Scan(mods/)
  → 对每个 mod：校验 mod.json → 选择 runtime → runtime.LoadMod(mod)
```

## 3. 核心接口

### 3.1 IScriptRuntime（C++ 侧抽象）

```cpp
// src/script/IScriptRuntime.h
namespace zl::script {

struct ModInfo {
    std::string id;
    std::string name;
    std::string version;
    int         apiVersion = 1;
    std::string backend;            // "lua" / "python"
    std::string rootPath;           // mods/<id>/
    std::string mainScript;         // 相对路径，如 scripts/main.lua
};

class IScriptRuntime {
public:
    virtual ~IScriptRuntime() = default;

    virtual const char* Name() const = 0;               // "lua" / "python"

    virtual bool Initialize() = 0;                      // 创建解释器/沙箱
    virtual void Shutdown() = 0;

    virtual bool LoadMod(const ModInfo& mod, std::string& errorOut) = 0;
    virtual bool ReloadMod(const std::string& modId, std::string& errorOut) = 0;
    virtual void UnloadMod(const std::string& modId) = 0;

    // EventBus → 脚本：把游戏事件派发给所有订阅者
    virtual void DispatchEvent(const core::ScriptEvent& ev) = 0;

    virtual const std::vector<std::string>& LoadedMods() const = 0;
};

} // namespace zl::script
```

### 3.2 ScriptManager（门面）

职责：
- 持有所有 runtime；按 config/mod 路由；
- 订阅 EventBus（`ScriptEvent` 全量转发 `DispatchEvent`）；
- 热重载：主线程轮询文件 mtime（后台线程只发通知）；
- 错误策略：单次调用出错 → 记日志（mod id + 脚本路径 + 行号）并**禁用该 mod 的本轮后续调用**，不崩游戏；LoadMod 阶段出错 → 该 mod 直接不加载。

## 4. Host API（ScriptApi）设计

### 4.1 原则

1. **薄包装**：C++ 侧只提供 `ScriptApi` 中签名简单（数值/字符串/句柄/int id）的函数，Lua/Python 各自只做一层直译绑定；不做深类型双向编组，避免维护双份复杂绑定；
2. **门面受限**：脚本不得直接访问 C++ 内部类；World/Entity 等复杂对象以**稳定 ID 句柄**（ECS `StableId`，跨存档有效）暴露；接口全部设计成平铺函数，避免长链（`Player.GetPosition()`、`Zombies.GetPosition(id)`）；
3. **版本化**：`API_VERSION = 1`；mod.json 声明 `api`，不匹配时拒绝加载并提示；
4. **命名**：全局表 `Game`、`Events`、`Log`、`World`、`Player`、`Items`、`Zombies`；函数 `PascalCase`（与 C++ 侧一致）。

### 4.2 API v1 最小集（M7-T3 实现，两后端同签名）

| 分类 | 函数 | 说明 |
|---|---|---|
| Game | `Game.GetTick() / Game.GetTime() / Game.GetPlayerId()` | 基本信息 |
| Log | `Log.Info(msg) / Log.Warn(msg) / Log.Error(msg)` | 进游戏日志（带 mod 前缀） |
| Player | `Player.GetPosition() / Player.Teleport(x,y,z) / Player.GetHealth() / Player.AddItem(itemId) / Player.GiveItem?` | 玩家操作 |
| World | `World.GetSquare(x,y,z) / World.IsPassable(x,y) / World.SpawnItem(itemId,x,y,z)` | 世界查询/生成 |
| Zombies | `Zombies.Spawn(x,y,z) -> handle / Zombies.Count() / Zombies.GetPosition(handle)` | 僵尸控制（handle = 稳定 ID） |
| Events | `Events.On(name, fn) / Events.Off(name, fn)` | 事件订阅 |
| 定时 | `Game.SetTimer(seconds, fn)`（脚本侧实现也行） | 便捷工具 |

> 后续每个里程碑扩 API 时，**必须同时更新两个后端的绑定与 docs/modding.md**，并在 M8 的对照验收清单里补条目。

## 5. 事件表 v1（EventBus 与脚本共用命名）

| 事件名 | 触发时机 | 载荷（variant 字段） |
|---|---|---|
| `OnGameStart` | 新游戏/读档完成 | - |
| `OnTick` | 每个模拟 tick 末 | `tick: int64` |
| `OnPlayerMove` | 玩家移动一个路点后 | `playerId, x, y, z` |
| `OnPlayerDeath` | 玩家死亡 | `playerId` |
| `OnZombieSpawn` | 僵尸实体化/生成 | `zombieId, x, y, z` |
| `OnZombieDead` | 僵尸死亡 | `zombieId, killer: playerId/0` |
| `OnItemPickup` / `OnItemDrop` | 捡起/丢弃 | `itemId, defId, count` |
| `OnSound` | 世界声音事件（脚步/枪声等） | `x, y, z, radius, soundType` |
| `OnChunkLoaded` / `OnChunkUnloaded` | chunk 生命周期 | `cx, cy` |
| `OnSaveBegin` / `OnSaveEnd` | 存档前后 | `slotName` |
| `OnModReload` | mod 热重载后 | `modId` |

约定：事件名与 PZ 的 LuaEventManager 风格对齐（`OnXxx`），但**载荷与语义按本项目定义**，不照抄；载荷中的 `xxxId` 一律是稳定 ID（StableId）。

## 6. Mod 结构

```
mods/
└─ example_hello_lua/
   ├─ mod.json
   ├─ scripts/
   │  └─ main.lua
   └─ assets/        (可选：贴图等资源，经 Host API 注册)
```

### mod.json

```json
{
  "id": "example_hello_lua",
  "name": "Example Hello (Lua)",
  "version": "1.0.0",
  "api": 1,
  "backend": "lua",
  "main": "scripts/main.lua",
  "loadOrder": 100
}
```

### 示例 main.lua（M7-T7 交付物之一）

```lua
Log.Info("hello mod loaded")

Events.On("OnGameStart", function()
    Player.AddItem("bandage")
    Player.AddItem("canned_beans")
end)

local elapsed = 0
Events.On("OnTick", function(e)
    elapsed = elapsed + 1
    if elapsed % (60 * 30) == 0 then          -- 每 30 游戏秒
        local p = Player.GetPosition()
        Zombies.Spawn(p.x + 8, p.y, 0)
    end
end)
```

## 7. 沙箱与安全

| 项 | Lua | Python |
|---|---|---|
| 危险库 | 移除 `os`/`io`/`debug`/`package`；`print` 重定向到 Log | 白名单 `import`（`math`、`random`、`json`…），禁用 `os`/`sys`/`subprocess`/`open` |
| 死循环 | 每 mod 设 Lua hook 指令计数（可选，M7-T6 加）| 暂不处理（文档声明） |
| 文件访问 | 禁；mod 资源经 Host API 读取 | 同左 |
| 定位 | **信任本地 mod**：不追求完整沙箱，定位是"防手滑"不是"防恶意" | 同左 |

## 8. 热重载设计

1. 后台线程轮询 `mods/**` 的 mtime（每 1s，只收通知不碰运行时）；
2. 主线程下一帧消费通知 → 调 `runtime.ReloadMod(id)`；
3. Reload 实现：清空该 mod 的所有事件订阅 → 重新走 `LoadMod`（Lua 側重建独立环境 `_ENV`；Python 侧重执行模块）→ 成功/失败日志 + `OnModReload` 事件；
4. 重载失败：保留旧版本继续跑（加载到临时环境成功后再换）。**先做简单版：失败=该 mod 禁用**，有钱再优化。

## 9. 两后端实现要点

### 9.1 LuaRuntime（sol2）

- 一个 runtime 实例内：每个 mod 一个独立 `sol::environment`（沙箱）；
- 事件表 `Events.On(name, fn)`：C++ 收 fn 句柄存 per-mod 列表；DispatchEvent 时用 `sol::protected_function` 调用并捕获错误（`sol::error` → 日志）；
- `Log.Info` 等直接绑 C++ 函数；
- 定时器可以先用"每 tick 检查"实现。

### 9.2 PythonRuntime（pybind11）

- 每个 mod：独立内置 `module` 对象作为它的全局命名空间（`exec(main, modGlobals)`）；
- **GIL 纪律**：所有脚本调用只发生在主线程；C++ 主线程持有 GIL 期间执行（进入/退出用 `py::gil_scoped_acquire/release` 包在主线程回调外层）；
- `Events.On`：同样存 `py::function` 句柄；
- 打包：若发行版不带 Python，mod backend=python 报"本构建未启用 Python 后端"。
