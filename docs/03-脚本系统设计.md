# 脚本系统设计（Lua 主 / Python 可选）

> 适用阶段：M7（Lua）、M8（Python 开关）。实现任务见 `01-里程碑与任务清单.md`。
> 前置说明：PZ 用的 Kahlua 是 Lua 5.1 的 **Java** 实现，C++ 无法使用；本项目的等价物是官方 **Lua 5.4 + sol2**。

---

## 1. 设计目标

1. **游戏不改 C++ 就能扩展**：mod 通过事件 + Host API 改变/增加游戏行为；
2. **双后端等价**：同一套 Host API 契约、同一套事件名；后端差异对 mod 作者尽可能透明；
3. **可切换**：编译期开关（是否带 Python）+ 运行期配置（默认后端）双层控制；
4. **错误隔离**：mod 报错/死循环不能崩游戏；日志能定位到 mod 与行号；
5. **热重载**：改脚本不重启游戏。

---

## 2. 后端选择机制

| 层级 | 机制 |
|---|---|
| 编译期 | CMake 选项 `ZL_ENABLE_PYTHON=ON/OFF`（默认 OFF）。OFF 时整个 PythonRuntime 不编译，游戏不引入 Python 依赖 |
| 运行期 | `config/game.json` → `"script": { "enabled": true, "backend": "lua" }`，决定"没有声明 backend 的 mod"用哪个后端 |
| 每个 mod | `mod.json` 的 `"backend": "lua" | "python"` 字段，可显式指定；两后端可同时加载各自的 mod（ScriptManager 同时持有多个 runtime 实例） |

加载流程：

```
ScriptManager.Initialize(config)
  → 按配置创建 LuaRuntime（总是有）
  → 若 ZL_ENABLE_PYTHON：按配置创建 PythonRuntime
ModLoader.Scan(mods/)
  → 对每个 mod：校验 mod.json → 选择 runtime → runtime.LoadMod(mod)
```

## 3. 核心接口

### 3.1 IScriptRuntime（C++ 侧抽象）

```cpp
// src/script/IScriptRuntime.h
namespace zl::script {

struct ModInfo {
    std::string id;
    std::string name;
    std::string version;
    int         apiVersion = 1;
    std::string backend;            // "lua" / "python"
    std::string rootPath;           // mods/<id>/
    std::string mainScript;         // 相对路径，如 scripts/main.lua
};

class IScriptRuntime {
public:
    virtual ~IScriptRuntime() = default;

    virtual const char* Name() const = 0;               // "lua" / "python"

    virtual bool Initialize() = 0;                      // 创建解释器/沙箱
    virtual void Shutdown() = 0;

    virtual bool LoadMod(const ModInfo& mod, std::string& errorOut) = 0;
    virtual bool ReloadMod(const std::string& modId, std::string& errorOut) = 0;
    virtual void UnloadMod(const std::string& modId) = 0;

    // EventBus → 脚本：把游戏事件派发给所有订阅者
    virtual void DispatchEvent(const core::ScriptEvent& ev) = 0;

    virtual const std::vector<std::string>& LoadedMods() const = 0;
};

} // namespace zl::script
```

### 3.2 ScriptManager（门面）

职责：
- 持有所有 runtime；按 config/mod 路由；
- 订阅 EventBus（`ScriptEvent` 全量转发 `DispatchEvent`）；
- 热重载：后台线程按 scripts/metadata、content、assets、other 分类轮询 mtime/大小/小文件内容指纹，只发通知；脚本变更立即重载，content/assets 防抖通知，主线程消费；X3-T2 起 content 通知触发独立 `ContentBundle` 事务，成功才替换内容并记录旧→新指纹，失败保留旧注册表；X3-T3 起联机只告警并提示重启+重连，不静默应用；X3-T4 起联机热重载拒绝显示 HUD 提示，动态内容仅单机、联机入口拒绝；X3-T5 已覆盖失败原子性/未变指纹/旧档；X3-T6 文档收口；
- 错误策略：单次调用出错 → 记日志（mod id + 脚本路径 + 行号）并**禁用该 mod 的本轮后续调用**，不崩游戏；LoadMod 阶段出错 → 该 mod 直接不加载。

## 4. Host API（ScriptApi）设计

### 4.1 原则

1. **薄包装**：C++ 侧只提供 `ScriptApi` 中签名简单（数值/字符串/句柄/int id）的函数，Lua/Python 各自只做一层直译绑定；不做深类型双向编组，避免维护双份复杂绑定；
2. **门面受限**：脚本不得直接访问 C++ 内部类；World/Entity 等复杂对象以**稳定 ID 句柄**（ECS `StableId`，跨存档有效）暴露；接口全部设计成平铺函数，避免长链（`Player.GetPosition()`、`Zombies.GetPosition(id)`）；
3. **版本化**：`API_VERSION = 2`；mod.json 声明 `api`，过新拒绝、偏旧告警并尽力加载；
4. **命名**：全局表 `Game`、`Events`、`Log`、`World`、`Player`、`Items`、`Content`、`Zombies`、`Hud`、`Menu`、`Inventory`、`Save`、`UI`；函数 `PascalCase`（与 C++ 侧一致）。

### 4.2 API 最小集（v2；M35-F1 只读观测层、F3-T2 命令化物品动作、F3-T3 单机直接状态效果、F3-T4 制作动作、F3-T5 建造动作、F4-T2 `Mod.Data`、F4-T3 `Json`、F4-T4 Lua `require`、F5-T3 `Audio`、F5-T4 查询统计；除 `require` 外两后端同签名）

> 后续每个里程碑扩 API 时，**必须同时更新两个后端的绑定与 docs/modding.md**，并在 M8 的对照验收清单里补条目。
> M35-F3-T2：动作返回 `{ok,queued,error}`；`index` 为 0-based，`-1` 表示第一件可用消耗品/第一堆；`slot` 接受 `primary/body` 或 `0/1`。`ok=true` 只代表命令被接受，实际失败（如物品不可用、目标超出范围）由 HUD/事件体现；`Attack` 显式目标不存在、已死亡/尸体、无敌（闪避无敌）时直接返回 `ok=false`。
> M35-F3-T3：仅 Direct；`ApplyDamage` 走 `CombatSystem::ApplyDamage`，支持 `blunt/bite/claw/fire/debug`，有 `Facing` 时按正面来袭处理（格挡/弹反可参与），`ok=true` 不代表实际扣血；`AdjustNeeds` 非负增量后钳制 [0,1]，负值/NaN 拒绝；`GiveXp` 返回 `{ok,queued,error,characterLevels,skillLevels,perkPoints,characterXp,skillXp}`。
> M35-F3-T4：`Craft.Start/Cancel` 走 `InventoryAction` 命令（Start 的 `fromIndex=配方索引`，数量 1~99），Direct 立即执行、loopback/KCP 排队；Start 提交前校验已学会/站点/材料，Cancel 无活跃批次与队列时拒绝。`Craft.Learn` 仅 Direct，成功追加 `KnownRecipes`，未知/已会/联机拒绝。
> M35-F3-T5：`Build.CanPlace` 仅 Direct，复用 `CanPlaceBuild` 预检距离/地面/占用/任务/系统开关/木材且不扣物品；联机拒绝。`Build.Place` Direct 直调 `WorldDemoState` 放置路径（扣木材/设施生成/XP/事件），loopback/KCP 发 `PlaceStructure`（`index` 为目录索引，`flags bit0=vertical`）。`Demolish/Repair/ToggleDoor` Direct 按格坐标校验距离/所有权/耐久/门口占用，MP 分别发 `DemolishStructure`（flags=0 立即执行）/`RepairStructure`/`ToggleDoor`。
> M35-F3-T6：`Zombies.Spawn` 的 `variant` 缺省 `normal`，支持 `normal/fast/strong/armored`；HP/速度/缩放/减伤沿用现有变体配置，未知变体返回 0。`World.EmitSound` 的 `radius` 为 (0,256]，`kind=generic/gunshot/impact/footstep/growl/zombie_growl/zombie/ui/vehicle`，Direct 下通过 `OnSound` 同时供音频与 AI 听觉消费，不进入联机广播。
> M35-F3-T7：`Game.IsMultiplayer()` 在主机/加入/loopback 均为 true，`Game.GetNetMode()` 返回 `direct/loopback/client`。非 direct 下 `Player.ApplyDamage/AdjustNeeds/GiveXp`、`Craft.Learn`、`Build.CanPlace`、`World.EmitSound` 全部 fail-closed；命令化动作仍提交服务器。v1 的 `Teleport/AddItem/SpawnItem/Zombies.Spawn` 保持本地兼容行为。
> M35-F4-T2：`Mod.Id()` 返回当前 mod id；`Mod.Data` 按 mod 隔离字符串 key/value，单 mod 64 key、value 4096 bytes、全局 128 KB。`Set/Remove/Clear` 单机返回 bool，`Get` 不存在返回 nil/None，`Keys` 字典序；热重载与存档保留，新世界为空。联机下 `Get/Keys` 为空、写全部 false，每个 mod 每次加载只警告一次。
> M35-F4-T3：`Json.Encode/Decode` 双后端同名；Lua 连续整数 key 为数组、空 table 为对象，空数组/null 用 `Json.Array()/Json.Null()`；Python 用 list/dict/None。深度 16、单字符串 64 KB、数组/对象 1024 项、数字有限，循环引用失败并告警；对象 key 排序，非法输入返回 nil/None。
> M35-F4-T4：Lua `require("util")` 解析 `<scripts>/util.lua`，`require("wave.director")` 解析 `<scripts>/wave/director.lua`，`require("./x")` 相对当前模块；模块返回首值，无返回/`nil` 为 `true`。只允许 canonical `<modRoot>/scripts/**` 内的 `.lua`，拒绝 `..`/绝对路径/symlink 逃逸，单文件 1 MB、嵌套 32 层、循环依赖报错；缓存按 mod，热重载清空。Python 后端仍单文件，不支持本地模块 import。
> M35-F4-T5：`api` 省略/1 的 v1 mod 继续加载，初始化日志一条“API 版本较旧”告警，v1 函数签名/返回值不变；`api>2` 仍拒绝。旧存档无 `MDAT` 时 `Mod.Data` 为空；M35 不要求旧档迁移。Lua `require` 可选，Python 仍单入口；旧档测试为 `M35-F4-T1`/`M35-F4-T5`。
> M35-F5-T4：`Entities.Query` 仍为默认 limit 32/最大 128、半径默认 8/最大 32；按 mod 归属并按 tick 统计查询/截断次数，每 mod 每 tick 首条截断写 `ZL_WARN`，tick 末由 `GameApp` 输出 `ZL_INFO` 汇总，仅观测不额外限流。查询组件 storage 在单次调用内缓存，`ScriptEntityInfo` 只为最终 limit 条构造。
> M35 的 API v2 扩展（玩家状态/背包/实体查询、行为事件、命令化动作、`Mod.Data`、`Json`、Lua `require`）设计见 [docs/23-M35脚本API与内容化扩展.md](23-M35脚本API与内容化扩展.md)。

## 5. 事件表 v1（EventBus 与脚本共用命名；M35-F2 起追加字段）

| 事件名 | 触发时机 | 载荷（variant 字段） |
|---|---|---|
| `OnGameStart` | 应用启动、脚本加载后（可能还在主菜单，玩家未生成） | - |
| `OnWorldStart` | 世界加载/新游戏后、玩家实体已生成的首个 tick（同步） | `saveId, isNewGame, day, playerId` |
| `OnWorldExit` | 离开世界、自动存档快照前（同步） | `saveId` |
| `OnTick` | 每个模拟 tick 末 | `tick: int64` |
| `OnUiFrame` | 每个 UI 渲染帧（状态 OnFrame 后、RmlUi Render 前；暂停/菜单期间仍触发） | - |
| `OnPlayerMove` | 玩家移动一个路点后 | `playerId, x, y, z` |
| `OnPlayerDeath` | 玩家死亡 | `playerId, sourceId, cause`（`cause` 为小写 `DamageCause` 名） |
| `OnDamage` | 伤害经 `CombatSystem::ApplyDamage` 落地且实际扣血 > 0（SP） | `targetId, sourceId, amount, damageType, cause, remainingHp, lethal, blocked`；闪避/弹反/完全格挡/零伤害不发 |
| `OnZombieSpawn` | 僵尸实体化/生成 | `zombieId, x, y, z` |
| `OnZombieDead` | 僵尸死亡 | `zombieId, killer: StableId/0`（来自 `LastDamage.sourceId`） |
| `OnAnimalKilled` | 动物转尸体 | `animalId, speciesId, killerId, x, y, z` |
| `OnItemPickup` / `OnItemDrop` | 捡起/丢弃 | `itemId, defId, count` |
| `OnItemUsed` | 玩家成功使用消耗品/工具后（SP） | `playerId, defId, spoiled, remaining`；`remaining` 为使用后槽位剩余数量（0 = 空） |
| `OnLootSearched` | 容器首次搜刮成功（SP） | `playerId, containerId, tableId, itemCount`；重复搜索/失败不发 |
| `OnCraftStart` | 一个制作批次开始（SP） | `playerId, recipeId, outputDefId, outputCount, batchCount`；`batchCount` 为实际开始件数 |
| `OnCraftFinished` | 一个制作批次完成/失败/中断（SP） | `playerId, recipeId, outputDefId, outputCount, batchCompleted, failed` |
| `OnBuildPlaced` | 建造成功（SP） | `playerId, defId, x, y, z, vertical`；x/y 为世界格坐标 |
| `OnBuildDemolished` | 拆除成功（SP） | `playerId, defId, x, y, z` |
| `OnBuildRepaired` | 维修成功（SP） | `playerId, x, y, z` |
| `OnSound` | 世界声音事件（脚步/枪声等） | `x, y, z, radius, soundType, clip` |
| `OnChunkLoaded` / `OnChunkUnloaded` | chunk 生命周期 | `cx, cy` |
| `OnSaveBegin` / `OnSaveEnd` | 后台存档提交/完成 | - |
| `OnModReload` | mod 热重载后 | `modId` |
| `OnUiReady` | UI Host 初始化完成 | - |
| `OnUiEvent` | 脚本 UI 文档输入/拖拽事件 | `modId, document, element, type, value, key, button, mouseX, mouseY` |
| `OnMenuChanged` | 主菜单/暂停菜单开关/模式变化（同步） | `open, pauseMode, canContinue` |
| `OnInventoryChanged` | 背包开关/数据刷新（同步） | `open` |

约定：事件名与 PZ 的 LuaEventManager 风格对齐（`OnXxx`），但**载荷与语义按本项目定义**，不照抄；载荷中的 `xxxId` 一律是稳定 ID（StableId）。M35 的 `OnDamage`/`OnAnimalKilled`/`OnItemUsed`/`OnLootSearched`/`OnCraft*`/`OnBuild*` 当前只在单机派发；`OnBuild*` 的 x/y/z 为世界格坐标，`OnBuildPlaced.vertical` 为实际朝向，拆除首次确认和门槛拒绝不发事件。`OnWorldStart/OnWorldExit` 在单机与联机客户端都发一次；`OnWorldStart` 在玩家实体生成/读档实体恢复后同步发，适合恢复玩家/世界状态；单机暂停菜单的“返回主菜单”只是覆盖层，不算离开世界。应用进程退出时 EventBridge 先于状态销毁，不能保证收到 `OnWorldExit`。

## 6. Mod 结构

```
mods/
└─ example_hello_lua/
   ├─ mod.json
   ├─ scripts/
   │  ├─ main.lua
   │  ├─ util.lua          (可选：Lua require)
   │  └─ wave/
   │     └─ director.lua
   ├─ content/       (可选：X-F2 内容管线)
   │  ├─ items.json
   │  ├─ recipes.json
   │  └─ buildings.json
   └─ assets/        (可选：贴图等资源，经 Host API 注册)
```

`content/` 由 `game::LoadModContent` 在脚本加载前合并，不经过 ScriptManager；格式与示例见 `docs/modding.md` §3.6.1。X3-T1 起 `ModWatcher` 分类监听 `content/` 与 `assets/` 并防抖；X3-T2 起单机且无脚本动态内容时，content 变更由 `game::LoadContentBundle` 在独立候选注册表整批校验 items/recipes/buildings/loot/forage/animals/crops/POI/missions/settlements，成功后才 move 替换并刷新指纹，失败完整保留旧内容。assets 仍只通知并需重启；联机/主机只告警并提示重启服务器+所有客户端重连；`Content.Register*` 动态内容需重启，X3-T4 起动态内容仅单机、联机入口拒绝，联机热重载拒绝显示 HUD 提示；X3-T5 已覆盖失败/指纹/旧档测试，X3-T6 完成文档收口。脚本热重载仍覆盖 `scripts/`/`mod.json`；X-F2b-2e 起脚本也可用 `Content.Register*` 在单机运行时追加物品/配方/建造/POI/任务。

### 示例 main.lua（M7-T7 交付物之一）

```lua
Log.Info("hello mod loaded")

Events.On("OnWorldStart", function(e)
    Player.AddItem("bandage")
    Player.AddItem("canned_beans")
end)

local elapsed = 0
Events.On("OnTick", function(e)
    elapsed = elapsed + 1
    if elapsed % (60 * 30) == 0 then          -- 每 30 游戏秒

end)
```

## 7. 沙箱与安全

| 项 | Lua | Python |
|---|---|---|
| 危险库 | 移除 `os`/`io`/`debug`/`package`；`print` 重定向到 Log | 白名单 `import`（`math`、`random`、`json`…），禁用 `os`/`sys`/`subprocess`/`open` |
| 死循环 | 每 mod 设 Lua hook 指令计数（M7-T7 已实现：单次调用约 500 万条指令上限，超限中止本次调用并按错误隔离）| 暂不处理（文档声明） |
| 文件访问 | 仅 `require` 只读 `<modRoot>/scripts/**` 的 `.lua`（canonical 前缀、1 MB、32 层、循环拒绝）；其余文件访问禁，mod 资源经 Host API 读取 | 仅白名单标准库 `import`（`math/json/...`）；无本地模块 import，文件访问禁 |
| 多文件 | `require("util")` / `require("wave.director")` / `require("./local")`；每 mod 缓存，热重载清空 | 单入口 `scripts/main.py`；M35 不做本地模块 import |
| 定位 | **信任本地 mod**：不追求完整沙箱，定位是"防手滑"不是"防恶意" | 同左 |

## 8. 热重载设计

1. 后台线程轮询各 mod 根目录，按 `scripts`+`mod.json`、`content`、`assets`、`other` 分类计算文件数、mtime、大小和小文件（≤256KB）内容指纹（只收通知不碰运行时）；扫描不可读时保留旧基线；
2. `scripts`/`mod.json`/`other` 变更立即排队；`content`/`assets` 变更合并后等待 `script.contentHotReloadDebounceSeconds`（默认 0.5s）静默期再通知；主线程分别消费 `PollChanges()`/`PollContentChanges()`；
3. 脚本路径：主线程调 `runtime.ReloadMod(id)`；Reload 清空该 mod 的事件订阅，重新走 `LoadMod`（Lua 侧重建独立环境 `_ENV` 与 `require` 缓存；Python 侧重执行模块），成功/失败日志 + `OnModReload` 事件；
4. 重载失败：保留旧版本继续跑（加载到临时环境成功后再换）。**先做简单版：失败=该 mod 禁用**，修复后再保存可恢复；
5. X3-T1 完成监听/分类/防抖；X3-T2 把 content 通知接到 `game::ContentBundle`：独立候选注册表重新加载基础+mod 的 items/recipes/buildings/loot/forage/animals/crops/POI/missions/settlements，整批校验通过后由 GameApp move 提交，成功重算指纹并令 `WorldDemoState` 下一次 tick 刷新本地定义；任一基础/mod 文件或交叉引用失败则保留旧内容。联机/主机、存在脚本动态内容、assets 变更仍不热替换；X3-T3 已明确联机只拒绝并提示重启服务器+所有客户端重连；X3-T4 已确认动态内容仅单机，联机 API/启动拒绝并显示统一文案/HUD 提示；X3-T5 已覆盖失败原子性/未变指纹/旧档，X3-T6 完成文档收口。

## 9. 两后端实现要点

### 9.1 LuaRuntime（sol2）

- 一个 runtime 实例内：每个 mod 一个独立 `sol::environment`（沙箱）；
- 事件表 `Events.On(name, fn)`：C++ 收 fn 句柄存 per-mod 列表；DispatchEvent 时用 `sol::protected_function` 调用并捕获错误（`sol::error` → 日志）；
- `Log.Info` 等直接绑 C++ 函数；
- 定时器可以先用"每 tick 检查"实现；
- `require` 是每 mod 环境内的 C 闭包：canonical 路径沙箱、每 mod 缓存、循环/深度/1 MB 限制，模块共享同一 `_ENV`；Reload 重建环境即清缓存。

### 9.2 PythonRuntime（pybind11）

- 每个 mod：独立内置 `module` 对象作为它的全局命名空间（`exec(main, modGlobals)`）；
- **GIL 纪律**：所有脚本调用只发生在主线程；C++ 主线程持有 GIL 期间执行（进入/退出用 `py::gil_scoped_acquire/release` 包在主线程回调外层）；
- `Events.On`：同样存 `py::function` 句柄；
- 模块加载：M35 仅单入口 `main.py`，不提供本地模块 import；`import` 只允许白名单标准库（`math/json/...`），其余 `ImportError`；
- 打包：若发行版不带 Python，mod backend=python 报"本构建未启用 Python 后端"。
- **嵌入实现要点（M8-T2 实测）**：
  - `PyConfig.home` 必须指向含 `Lib/` 的标准库目录，否则 `Py_InitializeFromConfig` 报
    `Failed to import encodings module`；home 查找顺序：环境变量 `ZL_PYTHON_HOME` →
    exe 旁 `python/` → 编译期默认（dev 构建= vcpkg `tools/python3`）。
  - Debug 构建同样链接 **release CPython**（`MAP_IMPORTED_CONFIG_DEBUG=RELEASE`）：vcpkg 的
    python3 debug 树只有 `python314_d.lib`，没有配套运行时/标准库。
  - 执行路径：`compile(source, filename=真实路径, "exec")` + `PyEval_EvalCode`；不能用
    pybind11 3.x 的 `py::exec`（只有 `str` 重载，会把 code 对象转成字符串按 `<string>` 编译）。
  - 每个 mod 的 `__builtins__` 是受限 copy：`print` 重定向到 `[script-py] [mod-id]` 日志、
    `__import__` 白名单（math/random/json/re/time 等）、去掉 open/eval/exec/compile 等。
  - **API 绑定（M8-T3）**：per-mod `types.SimpleNamespace`（Game/Log/Player/World/Zombies/
    Items/Hud/Menu/Inventory/Save/UI/Events），函数名与参数和 Lua 侧完全一致；位置/时间返回 dict
    （`pos['x']` / `t['year']`），无玩家时返回 `None`；事件回调参数为字段 dict
    （`e['tick']`）；`Events.Off` 按函数对象同一性解析；`Game.SetTimer` 与 Lua 同一泵机制
    （OnTick 派发前检查到期）。
