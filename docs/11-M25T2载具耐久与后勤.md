## 0. 结论

在 M25-T1 的可驾驶皮卡上增加：

- **耐久**：碰撞按冲击速度扣车况；车况归零后不能加速，但仍可下车和打开后备箱。
- **维修**：靠近车辆按 `E`，消耗 1 个 `repair_kit`，恢复 40% 车况。
- **加油**：靠近车辆按 `E`，消耗 1 个 `fuel_can`，恢复 50% 燃料。
- **后备箱**：车辆拥有 40kg / 6 堆的容器，靠近按 `I` 打开，复用现有仓库 UI。
- **持久化**：车辆位置、车况、燃料和后备箱内容写入单机存档；读档后不再重置到玩家身边。
- **配置化**：把 M25-T1 硬编码的驾驶参数迁移到 `config/game.json` 的 `vehicle` 段，保留代码默认值以兼容旧配置。

预计 **2~3 个工作日**（单人全职），按业余时间乘 1.5~2。完成后车辆具备“找到车 → 开 → 撞坏 → 修 → 加油 → 装货 → 存档 → 读档继续”的最小闭环。

## 2. 玩家体验与验收

### 2.1 体验目标

1. 开车撞墙/树/家具，车况按速度下降；低速蹭墙不扣车况。
2. 车况低时 HUD 显示百分比和维修提示；车况归零后不能加速。
3. 靠近车辆按 `E` 消耗维修包修车；没有维修包时给出明确提示。
4. 靠近车辆按 `E` 消耗燃料罐加油；燃料恢复且 HUD 立即更新。
5. 靠近车辆按 `I` 打开后备箱，可存入/取出/整理物品。
6. 保存后重启，车辆仍在原位置，车况/燃料/后备箱内容不丢失。
7. 驾驶中不会误开背包/后备箱，不会误触发 E 交互；下车后恢复正常。

### 3.2 数据与配置

纯逻辑结构（`VehicleSpike.h`）：

```cpp
struct VehicleTuning {
    float maxSpeed = 10.0f;
    float acceleration = 8.0f;
    float braking = 14.0f;
    float radius = 0.65f;
    float enterRange = 2.2f;
    float fuelPerSecond = 0.012f;
    int spawnOffsetX = 6;
    int spawnOffsetY = 6;
    int spawnSearchRadius = 3;
    float crashMinSpeed = 3.0f;
    float crashDamagePerSpeed = 0.08f;
    float maxCrashDamage = 0.56f;
    float repairAmount = 0.40f;
    float fuelPerCan = 0.50f;
};
```

可存档组件（`VehicleComponents.h`；M25-T4-V2 增加运行时/存档 `headlights`，组件版本 v2；M26-V12 升 v3 并追加 `type/heading`，旧 v1/v2 缺省标准皮卡/南向）：

```cpp
struct Vehicle {
    float condition = 1.0f; // 0..1，归一化，HUD 显示为百分比
    float fuel = 1.0f;      // 0..1

```

### 3.3 碰撞耐久

- 在 `VehicleStep` 的完整位移失败、且 X/Y 轴滑动都失败时，视为一次碰撞。
- 冲击速度取碰撞前速度；低于 `crashMinSpeed` 不扣车况。
- 单次伤害 `min((speed - crashMinSpeed) * crashDamagePerSpeed, maxCrashDamage)`。
- 用 `crashLatched` 防止贴着墙持续扣血；离开碰撞后重置。
- 车况 `<=0` 后：
  - 不能加速，只能制动/滑行；
  - 可以下车、开后备箱、维修；
  - HUD 显示“损坏”。
- 碰撞日志：`[vehicle] 碰撞：速度 x，车况 y%`，同一接触只在首次扣血时记录。

### 3.4 维修与加油

- 靠近车辆（`enterRange`）且不在驾驶中，按 `E`：
  1. 车况 <100% 且背包有 `repair_kit`：消耗 1 个，车况 `min(1, +0.40)`，提示“已维修：车况 xx%”。
  2. 否则燃料 <100% 且背包有 `fuel_can`：消耗 1 个，燃料 `min(1, +0.50)`，提示“已加油：燃料 xx%”。
  3. 车辆需要维修但背包没有 `repair_kit`：提示“缺少维修包”，消费本次 `E`，避免误用其他物品。
  4. 车辆需要加油但背包没有 `fuel_can`：提示“缺少燃料罐”，消费本次 `E`。
  5. 车辆不需要服务：不拦截通用 `E` 交互（继续走原有使用/拾取/睡觉等逻辑）。
- 维修包/燃料罐从玩家 `Container` 扣除；扣除失败不修改车辆状态。
- 维修/加油受 `VehicleTuning` 上限夹取；结果写回 `ecs::Vehicle`，HUD 当帧刷新。
- 车况为 0 时仍可维修；燃料为 0 时仍可加油。
- 不使用技能加成，避免把车辆后勤和技能平衡绑在一起。

### 3.5 后备箱

- 车辆实体新增 `Container{capacityKg=40, items={}}` 和 `PlayerStorage{maxStacks=6}`。
- 复用现有仓库 UI：
  - 靠近车辆按 `I` 优先打开车辆后备箱；
  - 支持原有“存入全部 / 取出全部 / 整理”；
  - 后备箱名称显示“皮卡后备箱”，标题显示 `后备箱：皮卡（x/40 kg）`。
- `PlayerStorage` 归属为 0（无结构 owner），单机可编辑。
- 驾驶中禁止打开背包/后备箱；上车时若背包已打开则关闭。
- 后备箱内容随车辆实体保存；车辆损毁不影响取物。
- 后备箱不参与车辆重量/速度计算，避免 T2 扩展成载重系统。

### 3.6 持久化

- 车辆实体使用 `EcsWorld::Create()` 获得 StableId；从 M25-T1 的“保存过滤”改为正常保存。
- `ecs::Vehicle` 注册到 `save::ComponentRegistry`，编解码仅包含两个 float，校验 `[0,1]` 且有限。
- 首次生成：无已存在车辆时，按 M25-T1 规则在玩家附近生成。
- 读档：
  - `EnsureVehicleSpawned` 先查找 `registry.view<ecs::Vehicle>()`；
  - 找到则绑定 `m_vehicle`，从 `Position`/`Vehicle` 恢复 `m_vehicleMotion`，补上 `SpriteScale`/`Collider`（这两个仍是运行时组件，不写存档）；
  - 找不到才生成新车。
- 驾驶中存档：
  - 车辆位置/车况/燃料/后备箱照常保存；
  - 玩家当前在车内，存档时临时恢复玩家 `SpriteRef` 再抓快照，避免读档后角色隐形；
  - 不保存 `m_driving`，读档后从步行状态开始，车辆停在原地。
- 不修改 `PlayerState`、`ZLR1`、内容指纹、网络协议；新增组件不改变 `kContentHashVersion=13`。
- 旧档没有车辆/组件：正常生成车辆；新档包含 `Vehicle` 组件，旧可执行文件读取新档不作为兼容目标。

### 3.7 输入与 HUD

- `ENTER`：上下车（不变）。
- `WASD`：驾驶（不变）。
- `ESC`：暂停（不变）。
- `E`：靠近车辆时优先尝试维修/加油；不满足条件则继续原有 E 逻辑。
- `I`：靠近车辆时优先打开后备箱；驾驶中禁止。
- `H`：结构维修保持不变，不复用为车辆维修。
- HUD 仍复用 `HudState.actionHint`：
  - 接近正常：`皮卡：燃料 100% · 车况 100% · Enter 上车 · E 维修/加油 · I 后备箱`
  - 接近低车况：`皮卡：燃料 80% · 车况 35% · Enter 上车 · E 维修 · I 后备箱`
  - 接近低燃料：`皮卡：燃料 12% · 车况 100% · Enter 上车 · E 加油 · I 后备箱`
  - 驾驶：`驾驶中：WASD 移动 · Enter 下车 · 燃料 80% · 车况 60%`
  - 损坏：`车辆损坏：按 E 维修（维修包）`
- 不新增 HUD 字段/RML 节点；文本过长时保持单行，必要时截断次要状态。

### 3.8 网络与存档边界

- 联机模式不生成车辆，`Vehicle` 组件不参与网络复制。
- 不修改 `net::Command`、`ZLR1`、服务器权威逻辑。
- 单机存档才保存车辆；服务器世界存档不处理该组件。
- 车辆实体读取后如果处于网络模式，直接忽略/不绑定，不影响现有联机流程。

|---|---|---|
| 新增存档组件 | 旧可执行文件可能读不了新档 | 只保证新代码读旧档；不承诺旧版本读新档 |

| 联机误生成 | 与网络权威冲突 | 联机不生成、不复制、不保存车辆 |
