# M33 世界内容扩展：多聚落/声望、动态事件、同伴、载具改装与 POI 探索（规划稿）

> 状态：**实施中（2026-11-13），12/35 任务完成；本文件是 M33 的唯一 TODO 依据。**
> 依赖：M23-F4 聚落/NPC、M19 任务/POI、M24 内容密度、M30 战斗、M25/M26 载具、M31 大地图、M32 战略层。
> 目标：在不改变“单主角、NPC 自主行动”的前提下，把现有系统串成可持续游玩的世界内容循环。
> 执行方式：严格按 **F1 → F2 → F3 → F4 → F5**、每个功能包内按 T 顺序实施；每个 T 完成并通过测试后勾选、汇报，再进入下一个。不要跨功能包并行。

## 1. 目标体验

玩家仍然只控制主角一人，但世界从“一个主聚落 + 随机事件”变成：

1. **多聚落网络**：不同聚落有不同商人、任务、防御和态度；玩家通过帮助或伤害聚落积累声望。
2. **动态世界事件**：赶路、扎营或守城时会遇到需要选择的事件；选择会改变奖励、声望、区域压力和后续事件。
3. **幸存者同伴**：在聚落招募一名同伴，同伴自主跟随、战斗、撤退和互动，不是 RTS 小队。
4. **载具改装**：把车辆从交通工具变成可投资的后勤资产；改装改变载重、防护、撞击和夜间能力。
5. **多阶段 POI**：医院、军营等地点有进入条件、阶段目标、钥匙/发电机、精英敌人和可选路线。

最终希望形成一条自然循环：

> 在聚落接任务/招募同伴 → 改装车辆准备出发 → 赶路时遇到动态事件 → 到达多阶段 POI 探索 → 带回物资提升声望 → 聚落提供更好的交易/任务/同伴能力。

---

## 2. 非目标

本阶段明确不做：

- 不做 RTS 式框选、编队、多单位操控、生产建筑或资源采集；同伴只能使用少量上下文指令。
- 不做完整派系外交、婚姻/生育、NPC 社会模拟、动态人口经济或无限程序化剧情。
- 不做无限随机任务生成；事件和任务仍以数据驱动的有限内容为主。
- 不做完整 z 轴/多层建筑/楼梯系统；POI 多阶段通过位置、门禁、钥匙和阶段状态实现。
- 不做移动基地、车辆建造、车辆物理大改；改装只影响既有车辆参数和库存。
- 不默认开启 PvP，不把聚落声望变成玩家间掠夺系统。
- 不做跨机 NAT/公网高延迟验收；联机验收仍以本机双客户端/三客户端为主。
- 不替换正式美术、正式动画、正式混音或全语音。
- 不做联机动态 mod 热重载；联机 mod 变化仍要求重启服务器和所有客户端。

# F1 多聚落与声望

## F1.1 目标

- 4 个聚落（村庄营地、北部诊所、南部农场、河畔营地）全部完成单机/服务器接线，不再只有主聚落可交易/接任务。
- 第 5 个聚落作为后续内容，不阻塞 F1。
- 每个聚落有独立商人库存、任务池、防御状态、声望和对话入口。
- 声望是玩家个人进度，影响交易价格、任务可用性和对话，不做派系战争模拟。

## F1.2 设计决策

### 声望范围与等级

- 范围 `-100..100`，默认 0；只保存整数，不保存浮点累积。
- 等级：`Hostile`（≤ -40）、`Wary`（-39..-1）、`Neutral`（0..19）、`Friendly`（20..59）、`Trusted`（≥60）。
- `Hostile` 只拒绝交易/任务/招募并显示警告，不默认让守卫追杀玩家；主动攻击仍走既有敌对逻辑。
- 声望变化由数据配置驱动，建议初始值：完成任务 +10，完成守城 +15，交易 +1（每游戏日每聚落最多一次），放弃任务 -10，攻击聚落 NPC/偷窃 -25。
- 声望变化必须幂等：同一任务完成、同一次守城结算、同一事件结果不能重复加。

### 聚落数据

- 继续使用 `settlements-v1`，新增字段为可选字段；旧数据不写新字段时按默认值运行。
- 新增 `regionId`、`services`（trade/missions/defense/recruit）、`startingReputation`、`dialogueProfile` 等字段；不把声望阈值硬编码进每个聚落。
- 商人仍使用现有固定 5 档报价表；F1 先通过价格倍率/声望折扣影响买卖，不做每个聚落完全自定义商品表。自定义商品表放后续。
- 每个聚落只生成一个商人；商人实体仍使用 `MerchantStock`，按 `settlementId` 绑定，不能出现“所有商人共享主聚落库存”。

# F2 动态世界事件

## F2.1 目标

- 在 M31 区域事件基础上增加“可选择、有阶段、有后果、可连锁”的世界事件。
- 事件由数据定义，玩家通过正常 UI 做选择；不同选择影响奖励、声望、区域压力和后续事件。
- 事件先单机闭环，再服务器权威和联机复制；不把事件做成无限随机任务。

## F2.2 事件状态机

```text
Scheduled → Warning → Active → Resolved
                         ├→ Failed
                         ├→ Expired
                         └→ Chained（生成 nextEvent）
```

- `Scheduled`：已排期，未对玩家显示精确内容。
- `Warning`：显示区域、大致时间、强度/情报误差；给玩家准备时间。
- `Active`：生成地点/敌人/容器/选项；玩家可参与或离开。
- `Resolved`：选择结果已结算，奖励/声望/战略效果一次性写入。
- `Failed`/`Expired`：失败或超时，按配置产生负面后果。
- 同一时间最多 1 个详细事件（单机）；服务器最多 1 个详细事件 + 若干摘要事件。玩家离开后事件降级为摘要，不无限空转。

## F2.3 事件数据

新增 `assets/world_events.json` 与 `mods/<id>/content/world_events.json`（格式暂定 `world-events-v1`）。

```json
{
  "format": "world-events-v1",
  "defs": [
    {
      "id": "caravan_ambush",
      "name": "商队伏击",
      "kind": "caravan",
      "minDay": 3,
      "maxDay": 60,
      "weight": 1.0,
      "cooldownDays": 5,
      "warningMinutes": 120,
      "durationMinutes": 30,
      "region": "any",
      "stages": [
        { "kind": "reach", "radius": 8, "description": "赶到商队遇袭点" },
        { "kind": "kill", "target": "event_caravan_raider", "count": 3, "description": "击退掠夺者" }
      ],
      "choices": [
        { "id": "rescue", "label": "护送商队", "reputation": 15, "rewardXp": 80, "pressure": -10 },
        { "id": "rob", "label": "抢走货物", "reputation": -25, "rewardItem": "ammo_9mm", "pressure": 8 },
        { "id": "leave", "label": "离开", "reputation": -5, "pressure": 3 }
      ],
      "nextEvent": "caravan_aftermath",
      "failureReputation": -5,
      "failurePressure": 8
    }
  ]
}
```

- `kind` 只做表现/生成提示，逻辑由 stages/choices 决定，避免为每种事件写死 C++ 分支。
- 选项的 `pressure` 正负改变区域压力；事件 `failureReputation/failurePressure` 提供失败/超时负面后果；生成/结算由 T3 runtime 统一处理。
- 阶段类型第一版只做 `reach`、`interact`、`kill`、`loot`、`defend`、`choice`；不新增复杂剧情脚本。
- 事件 id/阶段/选项全部进入内容指纹；单条非法定义跳过并告警，整文件失败时保留旧内容。
- `nextEvent` 只能引用已存在定义；循环链要拒绝或限制深度。

# F3 幸存者同伴

## F3.1 目标

- 在聚落招募 1 名同伴；同伴自主跟随、战斗、撤退和互动。
- 同伴不是 RTS 单位：只提供上下文指令（跟随/停留/撤退），不做编队、框选、逐单位指挥。
- 同伴可装备、受伤、倒地/死亡、存档和联机复制；玩家断线时安全回到聚落。

## F3.2 设计决策

- 同时最多 1 名活动同伴；额外同伴只能留在聚落作为“已招募/待命”，第一版不做小队。
- 招募条件：聚落声望达到 Friendly、完成该聚落的前置任务、支付/消耗配置物资。
- 同伴拥有独立 StableId、生命、装备、背包、信任和简单特长；不复制玩家技能系统。
- 同伴 AI：
  - 跟随玩家，保持 2–4 格距离；玩家战斗时攻击最近威胁，但不主动拉怪。
  - 距离玩家/聚落超过 leash 半径时回撤；低生命时请求撤退/自动撤退。
  - 不踩玩家陷阱，不攻击玩家/友方 NPC；AOE/火焰仍走既有伤害规则。
  - 不执行 RTS 目标点命令；只接受跟随/停留/撤退三个上下文指令。
- 倒地：同伴生命归零后倒地，可在短时间内救起；再次死亡为永久死亡（可从聚落重新招募同定义的新同伴，但不复活原 StableId）。
- 玩家断线/退出：同伴回到最近聚落或原地安全待命，服务器保存其状态；重连后不重复生成。

- 阶段状态为世界级、服务器权威：同一服务器所有玩家共享 POI 进度；个人奖励单独结算。
- 阶段条件：
  - `reach`：到达坐标/半径。
  - `interact`：与门禁/开关/尸体/文件交互。
  - `kill`：清理指定敌人或精英。
  - `loot`：取得钥匙/文件/样本。
  - `power`：启动发电机/恢复供电。
  - `choice`：选择路线/是否销毁证据。
- 允许多条可选路线，但第一版最多 2 条；不要求全部完成才能结束。
- 每个阶段可配置奖励、提示、敌人刷新和下一阶段；阶段奖励只发一次。
- Boss 复用现有敌人变体/精英数据，不新增复杂动画；Boss 可带一个简单机制（召唤/冲锋/破坏工事）。
- POI 阶段失败可重试；已完成阶段不重复刷奖励；旧单段 POI 不受影响。
