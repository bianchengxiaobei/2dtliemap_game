## 1. 目标与边界

### 1.1 目标

P1 只回答三个问题：

1. **看得清**：1280×720 与 1920×1080 下，HUD 文本不重叠、不裁切、不遮挡关键世界元素。
2. **看得懂**：POI、任务、电力、守夜、战报、Mod 字段的颜色、顺序、状态词与实际玩法一致。
3. **点得到/按得到**：E/H/L/K/X/ESC 等交互提示在正确时机出现，操作后 HUD 能即时反映结果。

通过标准是“当前版本可被用户直接实机验收”，不追求像素级美术统一。

### 1.2 不在本次范围

- M15-T6 的 15~30 分钟无调试键完整流程；该项仍单独待验收。
- M13/M0 跨机验收、双客户端实机组合验收。
- 真实动态光照、阴影、小地图、方向箭头；当前仅验收光晕、HUD 文本和场景标记。
- POI/任务/动态内容的联机同步；当前只支持单机。
- Mod HUD 的图标、进度条、交互控件；当前只有 8 行文本字段。

### 1.3 已有自动化覆盖

- `test_ui`：HUD 元素结构、战报面板 8 行、1280/1920 HUD 布局、长目标/POI/任务文案、8 个 Mod 字段组合、战报卡片边界、1280 背包布局、部分 1920 背包布局。
- `test_base_hud`：守夜结束文本解析、评级色调、低燃料/停电摘要。
- `test_base_siege`：破口坐标/方向、结果结构、结束文本。
- `test_player_state`：战报/破口坐标 v8 往返与旧版本回退。
- `test_settlement_integration` / `test_settlement_network`（F4-T7）：四段委托链、库存、巡逻/躲避避障、同晚读档不重复夜袭、双客户端复制/重复接取/失守交易。
- `test_script_ui`、`test_python_api`：Lua/Python `Hud.GetState()` 字段同构。
- `test_network_integration`：双客户端战报/破口坐标一致。
- `test_homestead`、`test_building`：电力/泛光灯状态、HP、维修与建造目录。

这些测试只证明字段、结构和固定样本布局，不证明真实字体/DPI 下的视觉结果；P1 仍以窗口截图和人工操作为准。

## 2. 执行环境

### 2.1 构建与启动

优先使用 Release 做视觉和帧率观察；需要看日志时再用 Debug。

```powershell
Import-Module 'C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\Tools\Microsoft.VisualStudio.DevShell.dll'
Enter-VsDevShell -VsInstallPath 'C:\Program Files\Microsoft Visual Studio\2022\Community' -SkipAutomaticLocation -DevCmdArguments '-arch=x64 -host_arch=x64'
$env:VCPKG_ROOT='E:\Dev\vcpkg'
cmake --build --preset x64-release
```

默认配置：`window.width=1280`、`window.height=720`、`window.fullscreen=false`、`render.debugText=true`、Lua + `mods/core_ui`。

| 目的 | 启动方式 |
|---|---|

### 2.2 显示设置

- Windows 缩放建议 100%。若使用 125%/150%，在记录中注明，不能与 100% 截图混用。
- 关闭游戏内菜单/聊天/输入框后再截图，避免焦点遮住 HUD。
- WorldDemo 左上调试文本默认显示；P1 截图建议用 `--render.debugText=false` 隐藏，POI/电力/破口世界标记仍保留。`F9` 仍只切网格线。
- 截图前确认日志无资源缺失、脚本报错或 RmlUi 布局警告。
- 需要暂停画面时用 `F1`，但必须先确认暂停后 HUD 仍显示；截完恢复并再操作一次验证状态未冻结。

### 2.3 状态构造原则

1. 优先走自然流程：新档 → 搜刮 → 建造 → 夜间守夜。
2. 需要快速到达状态时，允许使用 `F1` 暂停、`F2` 倍速、`F6` 演示击杀、`F7` 枪声、临时测试 mod 或传送；必须在记录中标注“构造状态”。
3. 构造状态不能替代最终自然流程抽查；至少完成一次新档夜间守夜和一次 POI/任务自然到达。
4. 不修改正式 `assets/`、`config/game.json` 或 `mods/core_ui/` 来制造验收结果；需要特殊数据时使用临时 mod 或临时配置覆盖，记录后清理。

## 7. 已知风险

- HUD 使用固定像素定位；右侧目标/Mod、中央状态/Perk 与左侧等级/生命/状态已改为同列流式排列，但极长文案会把后续面板持续下移/上移，仍需实机确认不会遮挡底部提示或世界关键元素。
- 左侧状态行的长文本组合已由自动断言覆盖（T5 起 9 行）；若后续继续增加状态行或单行换行超过 3 行，等级面板可能被推到屏幕上方，需要重新检查。
- 战报卡片宽 560、垂直居中偏移 210px，8 行长文本可能换行后裁切，必须用最长文案验证。
- 1920 下固定像素面板不会等比放大，可能出现视觉偏小但可读；这是现设计可接受项，除非影响操作。
- 泛光灯当前只有程序化光晕/照明圈，不是真实动态光照；不要把“无阴影”判为失败。
- 默认 Lua 与 native HUD 是两套渲染路径，必须分别启动，不能只切窗口大小。
- 1920 窗口化在 1080p 桌面会被任务栏/标题栏裁切；1920 验收用 `--window.fullscreen=true` 或 `Alt+Enter` 全屏，或确认桌面可用高度、使用更大的显示器。
- 临时 mod/传送构造状态会跳过自然流程，必须在记录中标注，不能替代最终抽查。
- 默认 `baseEvent.minStructures=1` 时，没有任何玩家结构不会触发守夜；D2 需要临时覆盖为 0，不能把“未触发”误判为 HUD 失败。
