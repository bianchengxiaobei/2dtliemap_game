## 1. 目标与非目标

**目标**
- 2D 等距视角、分块大世界、僵尸生存玩法骨架（移动 / 战斗 / 物品 / AI / 生存状态）
- 架构对齐 PZ 的核心思想：四级世界坐标、固定 tick、事件总线、数据驱动、脚本 mod
- C++20 实现，Windows 优先（尽量保持可跨平台）

**非目标（现阶段）**
- 不做 3D / 写实画面；不做内容量（地图、物品、剧情以"够验证系统"为准）
- 联机采用服务器权威 + KCP over UDP；双客户端垂直切片、命令安全/容错、服务器权威背包/世界交互、玩家持久化、主菜单入口/内嵌主机/聊天与玩家列表已完成；X-F1 联机建筑只读同步与服务器权威写入阶段 2a/2b-1/2b-2a/2b-2b/2b-3/2b-4/2b-5/2b-6 已完成自动化；M21-F1a 单机夜袭导演 2.0、M21-F1b 联机守夜状态广播与每玩家奖励、M21-F2a 单机电力防御 2.0 与 M21-F2b 联机电力防御 2.0 已完成自动化，M0 跨机验收待做

## 2. 总体分层

```
┌──────────────────────────────────────────────────────┐
│ 游戏内容层   具体玩法组装（M5~M11 逐步填充）              │
├──────────────────────────────────────────────────────┤
│ 系统层       AI · 物品/物品栏 · UI · 音频 · 存档 · 脚本    │
├──────────────────────────────────────────────────────┤
│ 世界层       World / Cell / Chunk / GridSquare · ECS(EnTT) │
├──────────────────────────────────────────────────────┤
│ 物理层       Bullet 封装（碰撞 / 动力学 / 射线）          │
├──────────────────────────────────────────────────────┤
│ 渲染层       bgfx（SpriteBatch / Camera / 纹理 / UI 绘制）│
├──────────────────────────────────────────────────────┤
│ 核心层       主循环 · GameTime · 事件总线 · 任务池 ·        │
```

**依赖铁律**：只允许上层依赖下层，禁止反向依赖；模块对外只暴露 `xxx.h` 公共头，内部实现文件不允许被其他模块 include（详见 02 文档目录结构）。

## 3. 运行时模型

### 3.1 固定 tick 主循环

```
loop:
  PollPlatformEvents()              // GLFW 窗口/输入事件
  accumulator += frameDt
  while (accumulator >= kTickDt):   // kTickDt = 1/60 秒，固定步长
      CommandPipeline.Pump()        // M12：loopback 服务器消费上一帧命令
      GameTime.Tick()               // 游戏日历推进
      SimulateWorld(kTickDt)        // AI/物理/移动/战斗
      EventBus.FlushQueued()        // tick 末尾统一派发排队事件
      accumulator -= kTickDt
  UpdateRenderState(alpha)          // 渲染插值系数（先不用，预留）
  CollectDrawCalls()                // 遍历可见 chunk → SpriteBatch
  Ui.Draw()
  bgfx::frame()                     // 提交；bgfx 内部有渲染线程
  CommandPipeline.Flush()           // M12：帧末打包玩家命令（direct 为空操作）
  ProcessBackgroundResults()        // 后台任务结果回投（chunk 加载完成等）
```

- 模拟 **60Hz 固定步长**；渲染跟随 vsync，二者解耦；
- 渲染**不做插值**（与 PZ 一致），后续需要再加 `alpha`；
- 游戏倍速 = 每帧执行 N 次 tick（暂停/1x/2x/3x）；
- M12 命令层：状态/UI 在渲染帧提交命令，direct 立即执行；loopback 在下一 tick 开头由 Server 解码执行（最多 1 tick 延迟）。

### 3.2 线程模型

| 线程 | 职责 | 铁律 |
|---|---|---|
| 主线程（逻辑） | 模拟、事件、渲染收集、UI | **唯一允许修改世界数据的线程** |
| 渲染线程 | bgfx 内部自动管理 | 我们只提交 drawcall，不直接碰 |
| 任务线程池（N=核数-2） | chunk 文件解析、存档 IO、寻路查询、地图生成 | 只读已发布的只读数据；产出结果放入结果队列 |
| 文件监视线程（M7） | 轮询 mod 文件 mtime/大小/内容指纹 | 只发通知 |

**交接机制**：后台线程产出 `XXXResult` 结构体 → 推入线程安全结果队列 → 主线程在 `ProcessBackgroundResults()` 中消费并挂接进世界。禁止后台线程直接 `new GridSquare` 进世界结构。EnTT registry 为**主线程独占**资源：后台线程不得访问 registry，只处理自己的快照与结果结构。

## 4. 世界模型

### 4.1 四级坐标体系（对齐 PZ）

```
World  ── 由 Cell 组成的稀疏网格（世界可以无限大，按需生成/加载）
 └─ Cell（300 × 300 格） ── 地图大区，加载单位
     └─ Chunk（10 × 10 格） ── 流式加载/卸载单位、存档单位
         └─ GridSquare ── 单格，含 x,y,z 与分层对象
```

**关键常量**（统一放 `core/Constants.h`，先给默认值，可调）：

| 常量 | 默认 | 说明 |
|---|---|---|
| `kChunkSize` | 10 | chunk 边长（格） |
| `kCellSize` | 300 | cell 边长（格），30×30 chunks |
| `kMaxZ` | 8 | z 层数，0=地面 |
| `kTileW / kTileH` | 64 / 32 | 等距菱形精灵占屏尺寸（2:1） |
| `kFloorPx` | 24 | 每层楼在屏幕上的垂直偏移像素 |
| `kTickRate` | 60 | 模拟频率 Hz |
| `kChunkLoadRadius` | 2~3 | 以相机为中心加载的 chunk 半径 |

### 4.2 GridSquare 内容分层

每格内的数据按层存放，绘制顺序固定：

```
0. Floor/Terrain   地面（必有一块）
1. Wall            墙
2. Furniture       家具/大型物体
3. Container/Item  容器与地面物品
4. Mark            临时标记（血迹、脚印，不存档或单独存）
动态实体（角色/僵尸/抛掷物/地面物品）不挂在格子上，由 ECS（EnTT）registry + 空间索引统一管理
```

### 4.3 内存与流式加载

- 只有"已加载窗口"内的 chunk 占用内存；相机移动 → 差集计算 → 后台加载新 chunk、释放旧 chunk；
- 每个 chunk 状态：`Unloaded → Loading(后台) → Loaded → Unloading`；用共享只读指针发布，确保后台线程不访问正在卸载的 chunk；
- 世界修改（拆墙、丢物品）= diff 记录，卸载 chunk 时 diff 进存档缓冲，不动地图母文件。
- **M31-T3**：`ChunkManager` 增加 resident 轻量坐标窗口（仅摘要，不创建 `Chunk`/物理）、按玩家速度前向预测 1–2 chunk、有限地图边界开关；`RegionStreaming` 维护 `Active/Ambient/Frozen` 相位与焦点夹取。
- **M31-T4**：`world_manifest_v1.bin` 记录地图身份/区域相位/chunk 索引；车辆、尸体、动物、聚落 NPC、地面物品按 `world.json` 区域写入独立实体桶，玩家与无位置世界状态留在全局 `entities.bin`；卸载时主线程采集脏 `ChunkDiff`，`zl-save` 后台写并重试；启动前校验 `mapHash/seed/generatorVersion/mapId`，旧档无 manifest 继续兼容。
- **M31-T5**：`WorldGraph` 从 `world.json` 派生道路图、`TerrainKind` 与 biome 密度；长距离路线走图，起终点接地复用 `PathfindingService` 局部 A*；水面阻挡、桥/道路可通行，载具碰撞与 server walkable 都校验 `vehiclePassable`，`SpawnLodSystem` 按焦点区域缩放虚拟尸群目标。
- **M31-T6**：`RegionEventDirector` 按区域/day/seed 生成尸潮、商队/巡逻、空投、感染爆发；只在 Active 区域且焦点近距生成内容，Ambient/Frozen 冻结计时；`WorldManifest` v2 保存事件状态，单机读档恢复且不重复生成；复用 `SpawnZombieAt`/`SpawnLootContainer`/`SettlementNpc`，`WorldDemoState` 用 `eventGuide` 显示方向/距离。
- **M31-T7**：`WorldMap` 从 `world.json`/`WorldGraph`/POI 配置生成区域、道路、桥梁派生河流、路标、POI、事件、玩家与任务目标快照；`WorldMapPanel` 用 RmlUi 图层绘制地图/迷雾/图例，`M` 打开并暂停单机时间，按半径发现区域/POI；点击 POI 用 `WorldGraph::PlanRoute` 生成驾车路线，`regionGuide` 显示当前区域/最近路标/导航距离，不做快速旅行。
- **M31-T8**：`ChunkManager::UpdateFocuses()` 维护多会话兴趣窗口并集，`RegionStreaming::SetFocuses()`/`RegionEventDirector::UpdateFocuses()` 让多个远距玩家各自区域保持 Active 与事件可见；`ServerHost` 每 tick 汇总玩家、待恢复档案与复活点的兴趣焦点，按 `net.structureInterestRadius` 过滤每会话结构/墓碑 diff，实体继续走既有 AOI；`SaveWorld` 写服务器 world manifest（身份/区域相位/桶/v2 事件），重启恢复。
- **M31-T9**：`SaveManager::MeasureStorage()` 统计存档文件数/总字节/chunk/实体桶/manifest，`SaveService::ChunkWriteStats` 记录后台 chunk 写吞吐与尾延迟；1024 个 4 格脏 chunk 后台写 3.8s、主线程快照 max 0.10ms、单文件 max 13.66ms，文件 1027/280,649 bytes，无需 cell 打包；36×36 headless soak 以 3,888 tick×1.0s 覆盖 64.8 虚拟分钟、1296/1296 chunk、最多 49 驻留、失败 0，Release tick P95 1.39ms；2/4 玩家仍 50/100 chunk。
- **M31-T10**：`WorldSelection` 让单机默认 M31、旧图可回退、专用服务器显式 opt-in；`assets/maps/village_demo_m31_content.json` 提供 4 个运行时 POI（诊所/农场/河畔资源危险区/检查站）与 5 段主线 + 支线，内容由内容指纹覆盖、不改 mapHash；主任务优先于 mod/支线，M31 隔离旧电台 Objective；主路线 1810 格，单机 1280 42 chunk/FPS 59–62，双客户端快照失败 0；文档/截图/日志见 `docs/16` §5 T10、`docs/mapformat.md` §7.10。

### 4.4 地图数据来源

- **v1（M3）**：JSON 文本格式 + 自研小生成器（随机村庄/房间），可手改、可 git diff；格式规范在 M3 建立 `docs/mapformat.md`；

## 5. 渲染架构

### 5.1 bgfx View 规划

| View | 用途 | 说明 |
|---|---|---|
| 0 | 世界 | 等距场景（clear depth，先透明黑） |
| 1 | UI | 正交屏幕空间，世界渲染后叠加 |
| 2 | 调试 | 碰撞框/寻路网格/网格线（可开关） |

### 5.2 精灵批渲染（SpriteBatch）

- 动态顶点缓冲：每帧收集 `SpriteInstance{ pos, size, uvRect, color, flags }`；
- 按**纹理图集**分批 → 每批一次 `bgfx::submit`；同帧 drawcall 目标 < 100；
- 顶点格式与 shader（`vs_sprite / fs_sprite`）在 M2 定稿，之后不轻易改；
- 光照/阴影先不做，用 tint/alpha 支持昼夜调色（M11 后再议）。

### 5.3 深度排序（Painter's Algorithm，无 z-buffer）

同帧绘制顺序（M3-T5/T6 定稿，实现见 `WorldDemoState::CollectWorld`）：

**第 0 段：地面批**（z=0 的 Floor 层，按纹理分批）
- 地面块之间互不遮挡，不需要精确序；1~3 个 drawcall 画完全部地面。

**第 1 段：对象批**（其余所有精灵，按 key 升序）：

```
1. z 层升序            ← 跨层全局优先：所有 z=0 内容先于一切 z≥1
2. (x + y) 升序        ← iso 纵深：离屏后方的先画
3. x 升序              ← 同一纵深对角线的稳定顺序
4. 格内层序（Floor→Wall→Furniture→Item→Mark）
```

- 多 z：z=0 地面、z=1 楼上；**上层（z≥1）统一乘 35% 透明度**（临时"上层透明度"策略，让室内可见；
  正式方案是楼层剖切/相机跟随的室内模式，后续里程碑再做）；
- 已知简化：z 优先意味着前景 z=0 高物体（大树）会被后方 z≥1 半透明层轻微覆盖——极端构图下的
  可接受损耗，实测肉眼不可见；
- 跨格大物体（树、多格家具）按**锚点格**排序；悬浮物（血条、名字）最后单独一批画。

### 5.4 等距数学（IsoMath 工具类）

```
toScreen(x, y, z)  = ( (x - y) * kTileW/2, (x + y) * kTileH/2 - z * kFloorPx )
toGrid(screen)      = 逆变换（先在 z=0 平面反解，再按 z 逐层拾取）
```

所有世界↔屏幕↔拾取的换算只允许走 IsoMath，禁止各处手写公式（PZ 的 `IsoUtils` 同理，M2-T4）。

### 5.5 相机

- 平移（鼠标拖拽 / WASD / 屏幕边缘滚动）、缩放 0.5x~3x（吸附到挡位）、边界限制；
- 可见性裁剪：相机 AABB → 相交 chunk 列表 → 逐格收集；
- 相机跟随时平滑（lerp），死亡/自由观察模式预留。

## 6. 实体 / 物理 / AI

### 6.1 实体系统（ECS · EnTT）

后期目标是大规模尸潮，实体系统采用 **EnTT**：实体只是 ID，数据是组件（纯数据 struct），逻辑是系统（对 view 批量处理）。

- 组件示例（M4 定稿）：`Position / Velocity / MoveIntent / Collider / RigidBody / SpriteRef / AnimState / Health / StableId`，角色域还有 `AiState / Perception / PathRequest / PathFollow / ZombieSpecial / SiegeAssaultTarget / Wounds / Pain / Infection / Climate / Progression / CombatStamina / CombatStance / Poise / AttackIntent` 等；M20-F4 基地经营新增 `FarmPlot / Generator / ColdStorage / SpikeTrap / MerchantStock`（`FARM/GENR/COLD/TRAP/MRCH` 存档，2b-2a 起 `FarmPlot/Generator/SpikeTrap` 与 `PlayerStorage` 内容进入 `ZLR1`，2b-4 起 `MerchantStock` 进入 `ZLR1`）；X-F1 2b-1 新增 `StructureOwner`（设施建造者归属，`STRO` 存档），2b-5 起客户端从复制 Prop 的 owner 字段还原该组件用于归属 UI；M23-F3-T2/T3 新增 `FireAnchor/FireSource`（火源格与阶段/燃烧/烟量/热半径/蔓延累计），M23-F3-T5 新增 `BurningZombie`（僵尸燃烧/传播/恐慌运行时状态），M23-F3-T6 起 `FireAnchor/FireSource/BurningZombie` 进入存档与 `ZLR1` 复制，M23-F3-T7 起自然燃尽会删除可燃结构并生成掉落；M23-F4-T2 新增 `SettlementNpc`（聚落/类型/驻点/活动/目标/计时）与 `SettlementNpcSystem`，商人/守卫/求助者共用寻路移动，按昼夜切换巡逻/站岗/休息并在活僵尸进入安全区外缘时躲避，36 格外冻结；M23-F4-T3 新增非 ECS 的 `DialogueTree/DialogueNode/DialogueOption` 运行时与 `VisibleDialogueOptions`，条件覆盖任务可用/进行/无委托/物品数量，结果覆盖跳转/关闭/交易/接取/聚焦，由 `WorldDemoState` 落到现有商人/任务系统；M23-F4-T5 增加聚落夜袭/守卫/失守运行时，M23-F4-T6 新增可存档 `SettlementState`（守卫生命/失守/当晚进度）与 `SettlementNpc` 复制组件，客户端只读，任务接取与交易由服务器权威；

### 6.5 玩家命令层与本地环回（M12）

- 玩家会改变状态的操作统一为 `net::Command{type, payload, tick, playerStableId}`；实体引用只用 `StableId`（`entityId/targetEntityId`），不跨层携带 `entt::entity`；
- 命令类型覆盖移动、点击移动、攻击、拾取（最近/指定实体）、使用/装备/卸下/丢弃、背包 UI 动作、开枪、投射物、快捷栏、建造/拆除/维修/开门/设施交互、商人报价、POI 容器搜刮、任务放弃/电台交互与联机睡眠/投票；暂停/相机/存档/调试仍属本地元操作，不进命令层；
- `net::CommandPipeline` 两种模式：`net.mode=direct`（默认，提交即执行）与 `loopback`（Client 编码字节包 → `LoopbackTransport` 队列 → Server 在下一 tick 开头解码执行，并回心跳快照）；
- 帧序：状态/UI 在渲染帧提交命令 → 帧末 `Flush()` 发包 → 下一 tick 开头 `Pump()` 消费；`InputSystem` 只把服务端写出的 `MoveInput`（屏幕方向）转成世界速度 `MoveIntent`；
- 环回仍是单机/测试通路；真实联机走 `net.mode=client`：`game::NetworkClient` 负责 KCP 会话、命令编码、`ZLA1` 玩家分配与 `ZLR1` 快照应用；`GameApp` 在 client 模式下跳过本地权威模拟，`WorldDemoState` 把复制副本同步为纯渲染 ECS 实体（本地预测 + 相机跟随）。服务器共享当前 ECS，所有命令先校验 SessionId 对应的 `playerStableId` 与命令包序列；命令协议为小端定长 v1，单包 ≤64 条/4KB。M33-F2-T5 增加独立的 `ZLW2` 世界事件快照（`ZLW1` 已被 WorldSound 使用）和 `ChooseWorldEvent` 命令；客户端只读快照、只发选项索引，服务器权威校验并结算，旧客户端忽略未知消息。事件快照与幂等结果键随 manifest v6 保存，服务器重启/客户端重连恢复。
- **传输选型（D9，T1/T2/T4 已接入）**：真实联机底层采用 **KCP over UDP**（ikcp），封装在 `KcpClient`/`KcpServer` 后，只负责可靠有序字节流；长度前缀帧、命令、快照、会话、鉴权与复制仍由上层 `net` 层定义。`KcpSessionClient/Server` 已完成 Hello/Welcome 握手、协议版本/内容 hash 校验、服务器分配 SessionId、Ping/Pong 心跳和握手/会话超时；握手完成前不会向游戏层产生 Connected 事件。当前 `LoopbackTransport` 保留用于单机与测试，KCP 尚未替换游戏主循环中的命令管线。
- **无窗口模拟（M13-T3）**：`game::WorldSimulation` 是地图/ECS/物理/寻路/AI/固定系统链的唯一所有者，构造只依赖 `Config/EventBus/TaskScheduler/SaveManager`，不依赖窗口、渲染、UI、输入或音频；GameApp 把它的指针挂到 `GameContext`，ServerHost 则直接驱动固定 tick。
- **实体复制层（M13-T4）**：`net/Replication` 保持无 game 依赖，定义 `ZLR1` v1 快照：magic/版本/全量或增量/baseTick/serverTick/序列号 + 实体（StableId/archetype/owner/组件字节）+ 移除列表；组件按 type/version 注册，单包 ≤60KB、最多 4096 实体，未知组件/重复实体/非法基线严格拒绝。`game/EntityReplication` 只读 ECS，注册 Position/Velocity/Health/SpriteRef/Facing/AnimState/ItemInstance/Equipment/ActionState/Wounds（M15-T2）/Pain（M15-T4）/PlayerStorage（2b-2a）/FarmPlot/Generator/SpikeTrap/MerchantStock（2b-4），按 AOI 半径与实体上限抓取玩家/角色/地面物品/投射物/瞬时特效，维护每客户端全量基线并生成组件级增量；玩家/角色/物品 archetype 和 `ecs::NetworkOwner` 表达拥有关系；仓库组件按会话 viewer 过滤，只有 owner 收到库存内容。客户端副本按 StableId 应用快照，远程位置在上一/当前快照间插值；本地玩家只做输入积分轻量预测，收到服务器位置后按误差阈值吸附或平滑校正。
- **会话接线（M13-T5）**：`ServerHost` 在启用网络后监听 UDP，`KcpSessionServer` 的 Connected/Data/Disconnected 驱动会话表；每个会话生成一个权威玩家（`SpawnNetworkPlayer`，PlayerTag + MoveInput），并持有独立 producer。连接后先发 `ZLA1` 玩家分配（sessionId/playerStableId/serverTick），再发全量快照，之后每 tick 增量；发送失败丢弃 producer 基线并在下一 tick 重发全量。移动/点击移动/攻击命令由服务器执行（Attack 写 `AttackIntent`，CombatSystem 扣血），客户端不直接改世界。断线销毁权威玩家，剩余客户端的下一帧增量带 removal；M13-T8 起客户端身份随 Hello 发送，服务器从档案恢复同一 StableId/位置/背包/装备/生命，重连不再重新分配。
- **M30 战斗命令与 v20 状态（T6–T9）**：`PlayerState` 升 **v20**，末尾仅 owner 追加 `PlayerCombatState`（体力/上限/姿态/弹反窗口/破防/闪避无敌）；旧 v19 及更早解码回退满体力/None。`Attack` 复用 flags bit0 表示重击，新增 `Block=48`（按下/松开）与 `Dodge=49`（世界方向）。服务器校验体力、姿态、硬直、驾驶/死亡与冷却后写 `AttackIntent`/`CombatStance`，`CombatSystem` 在服务器 tick 结算伤害；`combat.pvp=false` 时 PvP 目标不可选。客户端网络模式只发送命令并从 `PlayerState` 只读镜像，不能上传体力/伤害/冷却；`ZLR1` 不携带体力，T9 新增 `CombatStance` 姿态组件（`CBST`）供远端盾弧/残影表现，正式动画仍不在 v1。`SessionProtocol` v2 与命令包协议 v1 不变；`ZLR1` 新组件要求客户端/服务器同版本重建。

## 7. 脚本系统（详见 docs/03）

- 双后端：**Lua 5.4 + sol2（主）**，**Python + pybind11（可选，编译开关）**；同一套 Host API 契约、同一套事件名；
- 游戏内所有"可扩展点"从第一天就走事件总线：`OnGameStart / OnTick / OnPlayerMove / OnZombieDead / OnItemPickup ...`；
- `ScriptManager` 负责：后端选择、mod 加载/卸载/热重载、事件派发、错误隔离（mod 报错不崩游戏）；
- Host API 采用**薄包装**设计：C++ 侧只暴露 `int/float/string/vec/句柄` 级别的函数（`ScriptApi`），两种后端各自做薄绑定，避免双份深类型编组；

## 8. 存档架构

```
saves/<存档id>/
  meta.sqlite       存档元数据（名称/时间/缩略图/版本/玩家列表/游戏分钟，schema v2）
  save.bin          存档头（saveVersion/gameVersion/mapId/createdAt，段 ZLSV v1）
  entities.bin      动态实体 + 玩家（按 StableId 索引，段 ZLEN v1；含物品栏/装备）
  thumbnail.png     渲染一帧回读的缩略图
  world/chunk_x_y.bin   仅保存"被修改过"的 chunk（diff），按 chunk 分文件
  world/world_manifest_v1.bin  地图身份/区域相位/chunk 索引/实体桶索引（新档）
  world/entities_<region>_<hash>.bin  按区域拆分的实体桶（新档）
saves/.backup/<存档id>/  上一代完整存档（原子提交失败/主档损坏时回退）
```

- 自研 `BinaryWriter/BinaryReader`：每段带 **段头（magic + version + 长度）**，未知段可跳过；
- 存档头写 `saveVersion` 与 `gameVersion`；不兼容时**明确报错**，不做静默迁移；
- 读档流程：加载地图母文件 → 校验 manifest 身份 → 应用 chunk diff → 合并全局/区域实体桶 → 挂接玩家；
  无 manifest 的旧档走原 `entities.bin` 路径；
- 自动存档：只在主线程把"存档快照请求"交给后台线程（快照 = 只读拷贝），不阻塞模拟；
  后台 `zl-save` 写临时 generation 后目录改名，旧档保留到 `.backup/<id>`；主档损坏时
  `Load`/`LoadChunk` 回退 backup 并在 HUD 明确提示；
- 卸载 chunk：主线程采集脏 `ChunkDiff` 后交给 `SaveService` 后台队列，失败重试并计数，不阻塞主循环；
- 地图身份不匹配：加载前停止并清空 active save（只读保护），不把旧建筑/容器套到新地形。

## 11. 关键决策记录（ADR）

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 渲染用 **bgfx** | 裸 OpenGL / Vulkan | 自带渲染线程与多后端抽象；shaderc/texturec 工具链成熟；学习成本远低于 Vulkan |
| D2 | **ECS（EnTT）** | 深继承 OOP（PZ 风格） | 后期目标是大规模尸潮/怪物：组合优于继承、系统批量更新利于性能与扩展；代价是复杂行为要拆成系统、脚本/存档全部走稳定 ID |
| D3 | **自研轻量线程池** | enkiTS / Taskflow | 需求只有"单队列 + 结果回投"，自研约 200 行，学习价值高；不够用再换 enkiTS |
| D4 | 脚本 **Lua 为主 + Python 可选** | Kahlua / 仅 Python | Kahlua 是 Java 实现不可用；Lua 嵌入成本最低（~300KB、无 GIL）；Python 满足偏好，用同一接口抽象 |
| D5 | **Painter 排序**，无深度缓冲 | z-buffer / 3D | 2D 等距的正确遮挡本质是绘制顺序问题 |
| D6 | 地图 **JSON v1** | 直接二进制 | 早期可手改可 diff 可调试；性能不够再上二进制 v2 |
| D7 | 单机架构预留 **命令化输入**（M12 已落地 direct/loopback） | 直接操作实体 | 为联机铺路；命令层与状态执行解耦，当前环回每 tick 最多 1 tick 延迟 |
| D8 | UI 用 **RmlUi + bgfx 后端** | cocos2d-x / Dear ImGui / 自研 Widget | RmlUi 是 retained HTML/CSS 控件库，可只实现渲染/系统接口接入现有 View 1；cocos2d-x 是完整引擎（持有窗口/GL 上下文/主循环，无法当 UI 层），ImGui 控件与布局偏工具风 |
| D9 | 联机底层用 **KCP over UDP** | TCP / ENet / 裸 UDP | KCP 提供可靠有序字节流与可调重传/窗口，适合实时游戏；命令、快照、会话与复制协议仍由上层自研。T1 传输/帧协议、T2 会话握手、T4 实体复制协议、T5 会话接线、T6 命令安全/容错、T7 服务器权威背包/地面物品同步、T8 玩家持久化、T9 联机入口/聊天/玩家列表、T10 远程装备/动作/投射物表现已落地，`LoopbackTransport` 继续用于单机与测试 |
