## 0. 目标与约束

### 0.1 本阶段目标

在现有搜刮、建造、生存、基地防御、任务、联机和 Mod 基础上，增加新的可玩循环，而不是只增加数值或占位 UI。

优先顺序：

1. 先做能直接改变战斗/生存决策的系统。
2. 再做能延长单局寿命的内容。
3. 最后做需要新地图、新 AI 或大规模编辑器支持的系统。

### 0.2 明确非目标

以下内容暂不进入 M23：

- 车辆、驾驶、载具改装。
- 多层建筑、楼梯、完整 z 轴寻路。
- 完整 NPC 社会模拟、长期关系、结婚/生育等。
- 全量手绘美术、正式音频替换、PZ 资源导入。
- 默认开启 PvP 或强制 PvP 服务器规则。
- 跨进程/跨机器的无缝大地图。

### 0.3 每个功能的完成定义（DoD）

一个任务只有同时满足以下条件才算完成：

- [ ] 数据驱动：新增内容优先走 `assets/*.json` / `config/game.json` / `mods/<id>/content`，不把平衡值硬编码进状态机。
- [ ] 输入与 UI：玩家能通过正常操作触发，HUD/提示能解释当前状态，不依赖 F6/F7 调试键。
- [ ] 单机闭环：开始、消耗、结果、失败/中断、退出/读档都能恢复。
- [ ] 存档与联机：新增持久字段有存档；联机字段有服务器权威校验、复制和旧负载回退。
- [ ] 旧档兼容：旧存档/旧客户端缺失字段有安全默认值，不崩溃、不误发奖励。
- [ ] 测试：补 C++ 单测/联机测试/UI 或脚本测试；Debug、Release、Python 全绿。
- [ ] 文档：更新本文件、`docs/01`、`docs/05`、`docs/devlog.md` 和 README 状态；记录新测试计数。
- [ ] 回归：不降低现有搜刮、建造、任务、守夜、Mod 和联机测试。

### 0.4 版本与兼容规则

- 新增或改变内容数据结构时，同步评估 `kContentHashVersion` 是否升级。
- 改变 `PlayerState`/`ZLR1`/`ZLCD` 等网络或存档载荷时，必须保留旧版本解码路径。
- 新组件默认值必须让旧档表现为“功能未启用”，而不是错误触发。
- 新功能如果只支持单机，必须在 UI/文档明确标注，并在联机入口拒绝。

## 2. M23-F1 远程武器与弹药闭环（P0）

### 2.1 目标

把现有 F7 枪声和 V 远程武器输入升级为正式远程武器：

- 手枪：低伤害、中等射速、弹匣小、换弹快。
- 霰弹枪：近距离多弹丸、强击退、散布大、换弹慢。
- 弹药：至少两种弹药，可搜刮/制作/购买。
- 枪声吸引僵尸，形成“开枪有收益也有代价”的决策。
- 联机由服务器权威扣弹药、生成投射物和结算命中，客户端只预测表现。

### 2.2 非目标

- 不做枪械配件、瞄具、穿甲、跳弹和复杂弹道。
- 不做完整角色持枪动画，只复用现有主手挂点和投射物表现。
- 不做默认 PvP；PvP 必须配置显式开启。
- 不做枪械拆解/清洁/卡壳。

### 2.3 数据契约（T1 定稿）

`assets/items.json` 的 weapon 新增可选 `ranged`：

```json
{
  "damage": 18,
  "range": 18,
  "spreadDegrees": 3,
  "pellets": 1,
  "cooldownSeconds": 0.45,
  "magazine": 8,
  "reloadSeconds": 2.0,
  "ammoDefId": "ammo_9mm",
  "noiseRadius": 28,
  "wearPerShot": 0.01,
  "projectileSpeed": 20,
  "falloffStart": 8,
  "falloffEnd": 18,
  "falloffScale": 0.55
}
```

候选物品：

- `pistol` / `ammo_9mm`
- `shotgun` / `ammo_shells`

所有字段做类型、范围、引用校验；任一非法时整条武器定义拒绝加载，不影响其他定义。

T1 实际落地约束：`ranged` 仅允许 weapon；14 个字段全部必填；`falloffStart <= falloffEnd <= range`；`ammoDefId` 必须是已注册物品 id；`pistol`/`shotgun` 使用 `item.kitchen_knife`/`item.axe` 占位图标；`ammo_9mm`/`ammo_shells` 暂为 generic 堆叠物品。本步只做数据契约，尚未接入装备、射击、换弹和联机。
