# M21 基地防御 2.0：夜袭导演与电力防御（需求稿）

> 状态：需求稿；M21-F1a 夜袭导演、M21-F1b 联机守夜状态广播与每玩家奖励、M21-F1c 独立战报与破口高亮、M21-F2a 单机电力防御与 M21-F2b 联机电力防御已实现自动化（2026-10-25/26），待实机验收；统一视觉/交互矩阵见 `docs/07-视觉与交互验收.md`。
> 日期：2026-10-25/26
> 依赖：M17 `BaseSiege`、M18-F4 建造、M20-F3 特殊僵尸、M20-F4 发电机/陷阱、X-F1 服务器权威设施同步。
> 定位：先把单机“建基地 → 守夜”做成有方向、有破口、有电力取舍的防御循环；联机兼容放到第二阶段，不阻塞单机验收。
> 原则：优先复用现有实体、组件、HUD、存档和复制链路；首版不新增僵尸种类、不扩美术工程、不做完整动态光照。

## 1. 背景与问题

当前基地循环已经完整：搜刮木材 → 建造墙/门/设施 → 夜间守夜 → 维修/拆除 → 存档。但夜袭仍偏向“固定环形刷怪 + 数量比拼”：

- 僵尸从四周随机生成，玩家的墙线朝向、门的位置和防线缺口对尸潮决策影响有限。
- 玩家只能看到波次和存活数，缺少“哪边会来、哪里最危险”的预警。
- 发电机目前主要服务冷藏柜，电力系统还没有成为基地防御的一部分。
- 尖刺陷阱只能被动等僵尸踩中，缺少可主动布置的电网、照明和诱饵。
- 守夜结束只有一句结论文案，缺少“这次守得怎么样”的战后反馈。

本需求把夜袭从“刷怪事件”推进为“有情报、有破口、有电力取舍的基地防御”。

## 2. 目标与非目标

### 2.1 目标

1. **攻击有方向**：尸潮选择 1~2 个主攻方向，优先压力薄弱防线；玩家可以通过墙线、门、诱饵和补墙改变压力分布。
2. **破口有意义**：特殊僵尸和普通僵尸围绕破口行动；破口被摧毁后，后续波次可以转向第二方向，而不是继续无脑撞同一堵墙。
3. **预警可读**：预警阶段给出方向、预计破口和波次信息；不暴露精确刷新坐标。
4. **电力成为防御资源**：发电机可供电给泛光灯/电网，产生负载、燃料消耗和停电风险；玩家要在冷藏、照明、防御之间取舍。
5. **灯光可当诱饵**：泛光灯提供照明，也会吸引夜袭僵尸；玩家可以把危险引到预设的电击区。
6. **战后有反馈**：事件结束给出防御评级和一次性奖励，形成“准备 → 守夜 → 修复 → 变强”的循环。
7. **单机先验收**：F1/F2 单机垂直切片独立可玩；联机权威/复制在后续阶段补齐。

### 2.2 非目标

- 不做完整动态光照、阴影或屏幕空间光追；首版用光晕、HUD 和现有调色表达照明。
- 不新增僵尸种类；复用普通/快速/强壮、Howler、Breaker 和现有 `BaseSiegeZombie`。
- 不做完整寻路重写；优先在现有 A*、`BarricadeDefense` 和 `BaseSiege` 上增加“目标选择/方向约束”。
- 不做每玩家独立基地；联机仍共享一个守夜锚点/基地中心。
- 不做车辆、完整 NPC 社会模拟、默认枪械、无缝大地图。
- 不做波次中途存档恢复；保存/退出仍中止并清理事件僵尸。
- 不把 F1/F2 做成 Mod API 前置依赖；Mod 注册留给 X-F2。

## 3. 玩家体验闭环

### 白天

- 玩家根据基地地形选择防线：留门、加墙、把电网放在最容易破口的位置。
- 建造泛光灯和电网，给发电机加燃料；HUD 显示预计可供电时间和当前负载。
- 玩家可以把泛光灯放在外墙外侧作为诱饵，也可以在仓库/生活区使用照明。

### 黄昏/预警

- 22:00 前后出现守夜预警，HUD 显示：
  - 来袭方向（八方向，例如“西北”）；
  - 预计破口（例如“北侧木门 68/120”）；
  - 当前波次和倒计时。
- 玩家可以最后一次补墙、修门、搬燃料、打开/关闭泛光灯。

### 夜袭

- 主攻方向先受压；Howler 在后排引怪，Breaker 优先砸门/墙，普通僵尸沿缺口或绕行。
- 泛光灯把一部分事件僵尸吸引到灯光附近；电网在供电时电击并短暂硬直。
- 发电机燃料耗尽会停电，泛光灯熄灭、电网失效；玩家要在“保发电机”和“保防线”之间选择。

### 战后

- 显示防御评级、击杀数、结构损失、是否被破口。
- 根据评级发放一次木材/燃料/药品/维修包；不重复发放。
- 玩家修复防线，准备下一晚。

## 5. M21-F1 夜袭导演 2.0

### 5.1 攻击计划

事件进入预警时生成一份只存在于本次会话的攻击计划：

- 以守夜锚点为中心，把周围划分为 8 个方向扇区。
- 选择 1 个主攻方向；波次数量 ≥2 时准备 1 个备用方向。
- 主攻方向优先满足：
  1. 该方向存在可走通的出生点到基地的通路；
  2. 该方向附近有玩家建造的墙/门/栅栏，且防线强度较低；
  3. 尽量避免连续两晚选择完全相同方向（用夜晚 key 做轻量偏置，不做硬性记忆）。
- 备用方向只有在主攻方向被突破，或主攻波次结束后才激活；一场事件最多切换 1 次。
- 计划使用 `nightKey + 基地中心 + 结构摘要` 作为确定性种子；同一晚的刷新/重试不重新随机。
- 找不到合法方向或出生点时，降级为当前 `BaseSiege` 的环形生成，不阻塞事件。

**破口目标**

- 在主攻扇区内寻找玩家建造的 `Wall`/门结构，按“剩余 HP 比例低、离基地中心近、位于主要通路”排序，取第一个作为预计破口。
- 不考虑地图自带结构、无主旧结构和不可损坏装饰。
- 事件开始时锁定预计破口；每波开始时重新验证：
  - 目标仍存在且仍属于玩家建造：继续使用；
  - 目标已被拆除/摧毁：在同一方向重新选择次弱目标；
  - 该方向没有目标：允许切换到备用方向；仍没有则降级为追玩家。

### 5.2 预警与情报

预警阶段复用现有 `BaseSiege` 计时和 HUD 位置，新增/扩展以下信息：

- 方向：八方向之一，例如“来袭方向：西北”。
- 预计破口：显示结构名称和当前/最大 HP，例如“预计破口：北侧木门 68/120”；没有可识别防线时显示“无成型防线”。
- 波次：保留当前“第 N/M 波”和安全倒计时。
- 提示分级：
  - 预警开始立即显示方向；
  - 预警剩余时间低于 50% 或玩家靠近目标 12 格内，显示精确破口名称/HP；
  - 不显示具体刷新坐标、不显示下一波精确组成。
- 视觉表现：
  - 单机 HUD 顶部沿用 `siegeStatus` 拼接“来袭方向/预计破口/破口状态”；
  - 首版不新增方向箭头或破口高亮，重点保证 HUD 文本可读；M21-F1c 已补充预计破口/实际破口的场景内高亮；
  - 破口被摧毁时显示“防线被突破：北/西北”并使用 `siegeTone=fail`。
- 没有有效防线时仍允许事件发生，但情报显示“无成型防线”，不虚构目标。

### 5.3 单位行为

- **普通事件僵尸**：继续追守夜锚点/玩家；遇到阻挡的玩家结构时按现有逻辑攻击；不获得全图透视，不穿过已关闭的门。
- **Breaker**：优先前往主攻方向的预计破口；目标消失后选择同方向次弱结构；没有结构才恢复追玩家。
- **Howler**：保持在波次后方/玩家 8~12 格外蓄力嚎叫，不主动站到破口最前面；嚎叫引怪逻辑复用现有 `ZombieSpecialSystem`。
- **波次分配**：
  - 第 1 波使用主攻方向；
  - 第 2 波继续主攻，若主攻已破口则使用备用方向；
  - 第 3 波以当前仍有效的方向为主；没有备用方向时继续主攻。
- 任何单位不得在玩家建筑内部、不可走格或未加载 chunk 中生成。

### 5.4 破口与波次

- 预计破口被摧毁后：
  - 记录 `breached = true` 和破口位置；
  - 当前已生成的事件僵尸不瞬移、不集体换目标；
  - 后续波次可以被分配到备用方向；
  - HUD 显示“防线被突破”，但不立刻结束事件。
- 主攻方向和备用方向都没有可用结构时，事件继续追玩家，不因“没有墙”而中止。
- 天亮、玩家离开 `leaveRadius`、玩家死亡、保存/退出仍按现有 `BaseSiege` 规则中止并清理事件僵尸。
- 一场事件最多一次方向切换，避免玩家被无法预判的连续改道惩罚。

### 5.5 战后结算

事件正常结束（天亮或全部波次清完）时计算防御评级：

- `survivingRatio`：玩家建造结构存活比例；
- `breached`：是否出现破口；
- `kills`：事件僵尸击杀数（可由现有击杀统计/事件僵尸存活数推导）；
- `wavesCleared`：完成波次。

建议评级：

| 评级 | 条件（首版建议） | 奖励 |
|---|---|---|
| S | 无破口、存活结构 ≥90%、清完全部波次 | 燃料罐 + 维修包 + 稀有药品/图纸 |
| A | 无破口或仅 1 个破口、存活结构 ≥70% | 燃料罐 + 维修包 |
| B | 有破口但守住基地 | 木材 + 少量药品 |
| C | 基地失守或提前中止 | 少量木材，无额外奖励 |

- 奖励使用现有物品定义，不新增物品图标。
- 奖励只在正常结束结算一次；保存/退出/死亡中止不发奖励。
- 结算通过 HUD notice + `siege` 日志呈现，首版不新增独立结算面板；M21-F1c 已补充独立战报面板，保留 notice 作为即时摘要。
- 如果 F2 尚未接入，奖励不引用泛光灯/电网图纸，避免跨功能阻塞。

### 5.6 存档与联机

- 攻击计划、方向、破口、评级均为会话内状态，不写入世界存档。
- 保存/退出/读档沿用现有“中止守夜 + 清理事件僵尸”，不恢复波次。
- **M21-F1a（单机）**：完成全部 F1 需求，单机 HUD 和战后反馈可验收。
- **M21-F1b（联机，已完成自动化）**：
  - 服务器继续作为唯一权威，生成攻击计划并驱动事件僵尸；
  - 客户端通过 `PlayerState` v6 的 `PlayerSiegeState`（phase/方向/波次/破口/服务器 HUD 文本）获得方向、破口、波次和破口状态；
  - 不新增每玩家独立基地；多玩家共享当前守夜锚点；
  - 联机阶段只要求“信息可见 + 服务器权威”，不要求客户端本地预测；
  - 实现采用现有 `ZLP1` 玩家状态扩展，不新增独立协议；详见 5.11。

### 5.7 配置建议

新增在 `baseEvent.director` 下，全部有安全默认值：

- `enabled`：默认 `true`；关闭时退回当前环形波次。
- `maxAxes`：默认 `2`，范围 1~2。
- `axisSwitchPolicy`：默认 `breach_only`。
- `intelFullDelayRatio`：默认 `0.5`，预警剩余比例低于该值时显示精确破口。
- `weakestWeight`：默认 `0.7`，决定“薄弱防线”和随机方向的权重。
- `rewardEnabled`：默认 `true`。
- `S/A/B` 奖励数量可放在 `baseEvent.director.rewards`；首版允许使用代码默认值。

### 5.9 风险与降级

- **AI 目标选择过重**：只做“方向 + 破口目标”的选择，不改完整寻路；找不到路径时立即降级环形生成。
- **玩家被不可预判的方向切换惩罚**：最多 2 个方向、最多 1 次切换，预警至少保留现有 warningSeconds。
- **精确破口让防守过于简单**：只显示一个预计破口，不显示全部刷新点和下一波组成。
- **联机协议膨胀**：F1b 复用 `ZLP1` v6 `PlayerSiegeState`，F2b 仅升 v7 增加紧凑 `PlayerPowerState` 并复用 `ZLR1` 组件，未新增独立包；旧状态按版本回退。

   - 断电时熄灭，不提供照明/诱饵；
   - 80 HP，事件僵尸会攻击附近的灯；未摧毁前可 H 维修（1 木材/30 HP），被摧毁后消失。

   - 建造消耗：3 木材（首版数值可调）；
   - 作为可损坏的防御结构，默认阻挡移动，玩家可留门/缺口通行；

**美术降级**：首版复用现有 `object.barricade`/`object.trap`/`object.generator` 图集和程序化光晕/电弧特效；不要求新增正式美术。

### 6.2 供电与负载

- 继续使用现有“发电机半径内供电”，不实现电线连接图。
- 发电机有基础负载 `baseLoad`；冷藏柜、泛光灯、电网、现有设施都计入负载。
- 燃料消耗从固定 1 分钟/游戏分钟改为：
  - `每游戏分钟消耗 = baseLoad + sum(运行中设备负载)`；
  - 设备关闭、断电或离开半径时不计数。
- 燃料耗尽：
  - 发电机停止；
  - 冷藏柜、泛光灯、电网全部失效；
  - HUD 显示“停电”；
  - 玩家重新加燃料后可恢复。
- 只有运行中且半径内的设备生效；同一设备被多个发电机覆盖时取最近/第一个可用发电机，避免重复供电。
- 首版不做硬性“负载上限”；用燃料消耗形成取舍，后续再评估是否加过载/跳闸。

### 6.3 照明、噪音与诱饵

- 泛光灯在夜间显示光晕，并提供一个“照明区域”给 HUD/玩家识别；首版不以动态阴影作为验收条件。
