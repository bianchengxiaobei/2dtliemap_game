## 5. 编码规范

### 5.1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类/结构/枚举 | PascalCase | `GridSquare`, `ChunkState` |
| 函数/方法 | PascalCase | `Update()`, `GetSquare()` |
| 局部变量/参数 | camelCase | `moveSpeed`, `tileIndex` |
| 成员变量 | `m_camelCase` | `m_position`, `m_health` |
| 静态成员 | `s_camelCase` | `s_instance` |
| constexpr 常量 | `kPascalCase` | `kChunkSize`, `kTickRate` |
| 宏 | `UPPER_SNAKE`（尽量少用） | `ZL_ASSERT` |
| 文件 | PascalCase.h / .cpp，与主类同名 | `GridSquare.h`, `SpriteBatch.cpp` |
| 目录 | 全小写 | `render/`, `ai/` |
| 命名空间 | `zl`，模块二级 `zl::core`、`zl::world`… | `zl::world::Chunk` |

- 头文件一律 `#pragma once`；
- include 顺序：自身头 → C++ 标准库 → 第三方 → 本项目，组间空行；
- 不用 `using namespace`（头文件里绝对禁止）；`.cpp` 内也尽量避免；
- 注释用中文可以，但只写"为什么"，不写"是什么"；TODO 必须带任务号：`// TODO(M4-T6): ...`

### 5.2 异常 / 断言 / 错误处理

- **初始化阶段**允许异常（加载失败等致命错误），main 里统一捕获并弹日志；
- **运行期**不使用异常做流程控制；逻辑不变量用 `ZL_ASSERT`（Debug 中断、Release 记日志）；
- 可恢复错误（配置缺项、mod 报错）→ 记错误日志 + 降级继续；
- 不可恢复错误 → 日志 + 明确提示 + 有序退出（尽量保存当前进度）。

### 5.3 内存

- 所有权：`std::unique_ptr`（默认）；裸指针/引用 = 非拥有借用（文档注释标明生命周期）；
- 热路径（GridSquare、实体、sprite 实例）**禁止** `shared_ptr` 与每帧堆分配；用对象池/复用 buffer；
- 容器预留容量（`reserve`）用于每帧清空复用的 vector；
- 定期跑 Debug 的 VS 内存快照对比；泄漏检查（CRT 内置或 VS 诊断）。

### 5.4 线程

- 只有主线程能改世界（架构文档第 3.2 节铁律）；**EnTT registry 主线程独占**——后台任务只处理快照与结果数据，禁止持有 registry 引用；
- 跨线程数据只通过：不可变快照 / 结果队列 / 命令队列；
- 线程命名便于调试（`zl-task-0`、`zl-save`）；
- 共享计数器用 `std::atomic`，锁优先 `std::mutex` + 小粒度；不使用读写锁热点（先测再优化）。

### 5.5 日志

- 级别：`trace/debug/info/warn/error/critical`；发行版默认 info；
- 关键系统（chunk 生命周期、存档、mod、脚本、AI 寻路）用 debug 打点，可 config 打开；
- 格式：`[时间][级别][模块] 消息`；模块名与目录一致。

### 5.6 ECS（EnTT）规范

- 组件 = 纯数据 struct（无方法、无虚函数、无逻辑），名字用名词：`Position`、`Health`；查询/换算写成自由函数或系统；
- 公共组件放 `src/ecs/components/`，领域组件放各自模块（`characters/components/`、`items/components/`）；
- 系统命名 `XxxSystem`，签名统一 `void Update(EcsWorld& world, float dt)`；**更新顺序只在 SystemScheduler 一处集中注册**，写注释说明依赖关系；
- 遍历用 `view`/`group`；禁止热路径用 `registry.each` 全量遍历；不得跨 tick 缓存 view / 实体集合；
- 实体引用一律 `entt::entity` + `registry.valid()` 校验；跨模块 / 脚本 / 存档 / 玩家命令交流走 `StableId`；
- 创建/销毁走延迟队列，tick 末统一 flush；大量同类实体（地面物品、尸体）实现"睡眠"标记，不进渲染/AI 系统。

## 6. 性能预算（每次里程碑验收对照）

| 项 | 预算 |
|---|---|
| 帧总时长 | 16.6ms（60fps） |
| 模拟 tick（不含物理/寻路后台） | < 4ms |
| 物理步进（500 静态体 + 150 动态体） | < 2ms |
| AI/移动/战斗系统（1000 实体，LOD 后） | < 2ms |
| 渲染收集 + 提交（CPU 侧） | < 6ms |
| 同帧 drawcall | < 100 |
| chunk 加载（后台单块解析） | < 2ms |
| chunk 主线程挂接（物理/寻路回调） | < 2ms/帧（`world.chunkAttachBudgetMs`，至少挂 1 块） |
| 1000 格 A* 查询 | < 5ms（后台） |

- 每阶段结束用 `perf-baseline.md` 记录：场景、配置、FPS、各系统耗时；
- 性能工具：VS 性能分析器起步；bgfx debug 文本显示 FPS/drawcall/顶点数常开（release 可关）。

## 7. Git 工作流

- `main` 保持随时可编译可运行；
- 功能分支：`feat/m3-chunk-streaming`、`fix/m4-wall-stuck`；完成后合回（个人项目允许直接 main 小步提交，但里程碑任务建议用分支）；
- 提交规范（Conventional Commits）：
  ```
  feat(render): sprite batch + atlas json (M2-T3)
  fix(world): chunk unload race on camera fast move (M3-T4)
  ```

## 9. 资源制作约定

- 美术：系统验证阶段用占位；M12 后进入正式美术垂直切片，视觉方向、画布/锚点、命名、动画契约与验收统一见 `docs/art-pipeline.md`；当前 `assets/own` 已替换核心场景/角色/僵尸/代表性图标，未列入切片的帧仍用占位；
- 图集：`texturec` 打包或简单网格图集，命名全小写+下划线；
- 地图 JSON、物品 JSON、mod、RML/RCSS 全部 UTF-8 无 BOM（RmlUi 遇到 BOM 会告警并可能丢弃整份样式表）；
- RmlUi/RCSS 注意：不支持 `border-style`/`border` 简写（用 `border-width`/`border-color`）；`rgba()` 的 alpha 取 0~255；`div` 默认 inline；滚动条需显式 `scrollbarvertical { width: ... }`；九宫格用 `@spritesheet` + `decorator: ninepatch(...)`；
- UI 基础设施（M9-T1/T2）：RmlUi 6.3 + 自研 bgfx `RenderInterface`/`SystemInterface`，View 1 叠加；预乘 alpha、瞬态几何、纹理/scissor/裁剪；`theme.rcss` 提供面板/卡片/按钮/输入/列表/滑条皮肤与九宫格，控件状态/hover/active/disabled/focus-visible 由 RML 事件驱动；Close/Shutdown 必须先解绑事件再销毁 listener；
- 字体与文本（M9-T3）：字体族统一 `zl_ui`（Noto Sans SC，OFL，Regular 400 + Bold 700 实例化）；字号只用 11/13/15/18/22 五级；CJK 字形按需光栅化，不预载全字库；RmlUi 字体图集单页上限 1024×1024，HUD 目标 ≤12 页 / 48MB；中英混排用 `word-break: break-word`，单行省略用 `white-space: nowrap` + `text-overflow: ellipsis`；F11 Typography 面板显示字体页数/尺寸/字节；
- HUD（M9-T4）：`assets/ui/hud.rml` 常驻显示时间/倍速/Health/Needs.fatigue 映射体力/Needs 三项状态/背包前 5 格/notice；`WorldDemoState::RefreshHud` 每帧构建快照，HUD 元素不可聚焦，输入默认透传；打开背包/菜单时隐藏 HUD 和 bgfx 调试文本，关闭/玩家死亡恢复；
- UI 输入互斥：RmlUi 有输入焦点时 `UiSystem` 调 `Input::SetGameplayBlocked(true)`，所有 `IsAction*/IsKey*/IsMouseButton*/ScrollDeltaY` 返回 false；无焦点时透传。注意 RmlUi 无显式焦点时 `GetFocusElement()` 返回 **body**（不是空指针），必须把 body/html 视为无焦点；点击过的 div 会获得焦点，关闭面板必须 `Blur()`，否则永久阻断游戏输入；`Input::NewFrame` 每帧重置，禁止在 UI 处理前阻断；

- 存档二进制格式（M10-T1）：`save/BinaryFormat.h` 定 16 字节段头 `magic:u32 + version:u16 + flags:u16 + payloadSize:u64`，全部小端；`BinaryWriter` 先占位、`EndSegment()` 回填长度，`BinaryReader` 用 `BeginSegment`/`EndSegment` 逐段读取，未知段可 `SkipSegment()`；顶层循环用 `AtEnd()` 区分正常读完与段头截断（读完不设置 Error）。字符串为 `u32 字节数 + UTF-8 原始字节`，容器为 `u32 元素数 + 元素`，数量/长度上限分别为 1,000,000 / 16MB，单段负载上限 256MB；枚举写底层类型，float/double 写 IEEE 位，禁止直接 `memcpy` 结构体（padding/ABI 不稳定）。损坏/截断/版本不兼容/超限只设置 `Error()`（带偏移）而不抛异常，调用方负责报错、删档或回退备份；旧版本默认不做静默迁移（M23-F1-T2 的物品类组件 v1 兼容除外）；

- SaveManager/SQLite 元数据（M10-T4）：存档根目录由 `save.root`（默认 `saves`）配置；每个存档目录为 `<root>/<saveId>/`，内含 `meta.sqlite`、`save.bin`（段 `ZLSV` v1，存 gameVersion/mapId/createdAt）、`entities.bin`（T3 的 `ZLEN` 快照）、`thumbnail.png` 和 `world/chunk_x_y.bin`。`saveId` 由 UTC 时间戳生成且只允许 `[A-Za-z0-9_-]`，所有 id 操作先做路径校验（拒绝 `..`/分隔符）。`meta.sqlite` schema `user_version=2`：单行 `meta` 表（save_id/name/created_at/updated_at/save_version/game_version/map_id/thumbnail/game_minutes）和 `players` 表（stable_id/name/is_local）；v1 旧档读取时自动 `ALTER TABLE` 补 `game_minutes`（默认 0）；每次写入用事务整体替换。`SaveManager::List` 按 updatedAt 倒序，损坏/不兼容目录记 warn 后跳过；`Create` 可带玩家列表、实体快照与 RGBA 缩略图，失败清理未完成目录；`Save` 更新 entities/thumbnail/meta；`ReadMetadata`/`ReadHeader`/`Load` 返回 `LoadResult{Ok,NotFound,Incompatible,Corrupt}`，旧 `ZLSV`/`ZLEN` 版本返回 Incompatible 并给出清晰信息；`SaveChunk`/`LoadChunk` 委托 `ChunkDiffStore`。缩略图走 bgfx `requestScreenShot` 回调（平台回读 BGRA），`ConvertBgraToRgba` 处理 pitch/yflip，`stb_image_write` 编码 PNG；主线程用 `Renderer::PollScreenshot` 取回。T5 负责把截图+快照请求放到后台、原子落盘和损坏回退；
- 后台存档与损坏恢复（M10-T5）：`SaveManager` 每次提交写 `<root>/.tmp-<id>-<nonce>/`，更新档先把已提交档复制进临时 generation，再写 header/entities/thumbnail/chunks/meta；成功后旧档整体 rename 到 `<root>/.backup/<id>/`，临时 generation rename 为正式目录（同卷目录 rename；失败恢复旧档）。`.tmp-*`/`.backup` 不是合法 saveId，List 自动忽略。`Load`/`LoadChunk` 只在主档 Corrupt/NotFound 时回退 backup，Incompatible 不回退；`LoadReport{usedBackup,warning}` 交给状态显示 HUD。手工损坏 chunk 时错误带偏移、文件路径与“删除存档或使用备份”建议，不崩溃；

### 9.1 资源策略（own 美术切片 + 本地 PZ 临时占位）

- **合规底线**：占位资产（PZ 版权）只放 `assets_placeholder_pz/`（自带 .gitignore，默认忽略全部内容）；**禁止提交公开仓库、禁止随构建产物分发**；发布前必须全部替换为自制资源，细则见该目录 README；
- **AssetProvider 适配层**：游戏代码只按**逻辑名**取资源（如 `tile.floor.grass`、`item.axe`），实际文件由 `asset_manifest.json` 映射（逻辑名 → provider + 文件/图集/子图）；`config/game.json` 的 `assets.provider` 选择 `placeholder_pz` 或 `own`；**换资源 = 换目录 + 换 manifest，零代码改动**；
- **Mod 资源叠加（X-F2b-2a）**：`mods/<id>/assets/asset_manifest.json` 在基础清单后合并，只新增逻辑名，重名/非法绑定跳过；mod 清单里的 `atlas` 优先相对清单目录解析，找不到再回退根目录；图集仍为 `pz-atlas-v1`，`image` 相对图集 JSON；资源不参与内容指纹，联机双方需安装同一份 mod；
- **Mod 搜刮表/POI（X-F2b-2b）**：`mods/<id>/content/loot.json` 在基础 `assets/loot.json` 后追加表，表 id 冲突整份拒绝；`content/pois.json` 只追加新 id，基础 `enabled/guideRange` 不变；POI 仅单机生成，不创建地图房间，坐标需作者保证；二者参与内容指纹；
- **Mod 任务/事件（X-F2b-2c）**：`mods/<id>/content/missions.json` 以 `missions-v1` 在基础 `missions.defs` 后追加；单文件通过候选 `Config` 复用 `LoadMissionConfig`，id 重复、条目非法、前置缺失/成环时整份跳过；基础 `enabled/randomSeed` 不变，任务仅单机运行，服务器读取不执行，参与内容指纹；
- **占位资源获取**：
  - 散装 PNG（物品图标/衣服/UI，3214 张）：直接引用 PZ 安装目录 `media/textures/`；
  - tile/树/覆盖层：`py -3 tools/pz_pack_unpack.py` 解包 `media/texturepacks/*.pack`（支持 PZPK v1 与旧 v0 两种格式，导出 PNG + `pz-atlas-v1` 格式 atlas JSON），用法见 `assets_placeholder_pz/README.md`；
- **PZ 子图字段语义**：`x/y/w/h` = 图内矩形；`ox/oy` = 相对"原始格位左上角"的绘制偏移；`fx/fy` = 缩放前原始尺寸（floor 常为 64x32，2x 版翻倍）；渲染时经 `IsoMath` 换算后贴图。
