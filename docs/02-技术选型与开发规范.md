> - `tools/`（shaderc 等）与预编译 shader 产物是否入库：**shaderc 工具不入库**（vcpkg 自动装），**编译好的 shader 产物（`src/render/shaders_generated/*.bin.h`）要入库**（保证不开工具链也能编译运行）。

## 5. 编码规范

### 5.1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类/结构/枚举 | PascalCase | `GridSquare`, `ChunkState` |
| 函数/方法 | PascalCase | `Update()`, `GetSquare()` |
| 局部变量/参数 | camelCase | `moveSpeed`, `tileIndex` |
| 成员变量 | `m_camelCase` | `m_position`, `m_health` |
| 静态成员 | `s_camelCase` | `s_instance` |
| constexpr 常量 | `kPascalCase` | `kChunkSize`, `kTickRate` |
| 宏 | `UPPER_SNAKE`（尽量少用） | `ZL_ASSERT` |
| 文件 | PascalCase.h / .cpp，与主类同名 | `GridSquare.h`, `SpriteBatch.cpp` |
| 目录 | 全小写 | `render/`, `ai/` |
| 命名空间 | `zl`，模块二级 `zl::core`、`zl::world`… | `zl::world::Chunk` |

- 头文件一律 `#pragma once`；
- include 顺序：自身头 → C++ 标准库 → 第三方 → 本项目，组间空行；
- 不用 `using namespace`（头文件里绝对禁止）；`.cpp` 内也尽量避免；
- 注释用中文可以，但只写"为什么"，不写"是什么"；TODO 必须带任务号：`// TODO(M4-T6): ...`

### 5.2 异常 / 断言 / 错误处理

- **初始化阶段**允许异常（加载失败等致命错误），main 里统一捕获并弹日志；
- **运行期**不使用异常做流程控制；逻辑不变量用 `ZL_ASSERT`（Debug 中断、Release 记日志）；
- 可恢复错误（配置缺项、mod 报错）→ 记错误日志 + 降级继续；
- 不可恢复错误 → 日志 + 明确提示 + 有序退出（尽量保存当前进度）。

### 5.3 内存

- 所有权：`std::unique_ptr`（默认）；裸指针/引用 = 非拥有借用（文档注释标明生命周期）；
- 热路径（GridSquare、实体、sprite 实例）**禁止** `shared_ptr` 与每帧堆分配；用对象池/复用 buffer；
- 容器预留容量（`reserve`）用于每帧清空复用的 vector；
- 定期跑 Debug 的 VS 内存快照对比；泄漏检查（CRT 内置或 VS 诊断）。

### 5.4 线程

- 只有主线程能改世界（架构文档第 3.2 节铁律）；**EnTT registry 主线程独占**——后台任务只处理快照与结果数据，禁止持有 registry 引用；
- 跨线程数据只通过：不可变快照 / 结果队列 / 命令队列；
- 线程命名便于调试（`zl-task-0`、`zl-save`）；
- 共享计数器用 `std::atomic`，锁优先 `std::mutex` + 小粒度；不使用读写锁热点（先测再优化）。

### 5.5 日志

- 级别：`trace/debug/info/warn/error/critical`；发行版默认 info；
- 关键系统（chunk 生命周期、存档、mod、脚本、AI 寻路）用 debug 打点，可 config 打开；
- 格式：`[时间][级别][模块] 消息`；模块名与目录一致。

### 5.6 ECS（EnTT）规范

- 组件 = 纯数据 struct（无方法、无虚函数、无逻辑），名字用名词：`Position`、`Health`；查询/换算写成自由函数或系统；
- 公共组件放 `src/ecs/components/`，领域组件放各自模块（`characters/components/`、`items/components/`）；
- 系统命名 `XxxSystem`，签名统一 `void Update(EcsWorld& world, float dt)`；**更新顺序只在 SystemScheduler 一处集中注册**，写注释说明依赖关系；
- 遍历用 `view`/`group`；禁止热路径用 `registry.each` 全量遍历；不得跨 tick 缓存 view / 实体集合；
- 实体引用一律 `entt::entity` + `registry.valid()` 校验；跨模块 / 脚本 / 存档 / 玩家命令交流走 `StableId`；
- 创建/销毁走延迟队列，tick 末统一 flush；大量同类实体（地面物品、尸体）实现"睡眠"标记，不进渲染/AI 系统。

## 6. 性能预算（每次里程碑验收对照）

| 项 | 预算 |
|---|---|
| 帧总时长 | 16.6ms（60fps） |
| 模拟 tick（不含物理/寻路后台） | < 4ms |
| 物理步进（500 静态体 + 150 动态体） | < 2ms |
| AI/移动/战斗系统（1000 实体，LOD 后） | < 2ms |
| 渲染收集 + 提交（CPU 侧） | < 6ms |
| 同帧 drawcall | < 100 |
| chunk 加载（后台单块解析） | < 2ms |
| chunk 主线程挂接（物理/寻路回调） | < 2ms/帧（`world.chunkAttachBudgetMs`，至少挂 1 块） |
| 1000 格 A* 查询 | < 5ms（后台） |

- 每阶段结束用 `perf-baseline.md` 记录：场景、配置、FPS、各系统耗时；
- 性能工具：VS 性能分析器起步；bgfx debug 文本显示 FPS/drawcall/顶点数常开（release 可关）。

## 7. Git 工作流

- `main` 保持随时可编译可运行；
- 功能分支：`feat/m3-chunk-streaming`、`fix/m4-wall-stuck`；完成后合回（个人项目允许直接 main 小步提交，但里程碑任务建议用分支）；
- 提交规范（Conventional Commits）：
  ```
  feat(render): sprite batch + atlas json (M2-T3)
  fix(world): chunk unload race on camera fast move (M3-T4)
  docs(tasks): mark M2 completed
  chore(build): bump bgfx port
  ```
- 每完成里程碑：更新 README 状态表 + `git tag v0.N.0`；
- 大文件（png/音频）注意仓库体积：单个 > 10MB 的资源先压缩；后续需要时再上 Git LFS。

## 8. 测试规范

- 框架：doctest（轻量，随构建）；
- 必须先写测试的地方：坐标换算（IsoMath）、地图/serialization 往返、寻路正确性、容器堆叠规则、存档往返；
- 运行方式：`ctest --preset x64-debug`（或直接运行 `ZomboidLikeTests.exe`）；
- 手感类（移动/战斗/UI）不写自动化测试，用"验收场景脚本"手动过（任务清单里的验收条目）。

## 9. 资源制作约定

- 美术先全部用**占位资源**（色块/简单图形），系统验证优先，M12 再谈正式美术；
- 图集：`texturec` 打包或简单网格图集（M2 先用网格），命名全小写+下划线；
- 地图 JSON、物品 JSON、mod、RML/RCSS 全部 UTF-8 无 BOM（RmlUi 遇到 BOM 会告警并可能丢弃整份样式表）；
- RmlUi/RCSS 注意：不支持 `border-style`/`border` 简写（用 `border-width`/`border-color`）；`rgba()` 的 alpha 取 0~255；`div` 默认 inline；滚动条需显式 `scrollbarvertical { width: ... }`；九宫格用 `@spritesheet` + `decorator: ninepatch(...)`；
- UI 基础设施（M9-T1/T2）：RmlUi 6.3 + 自研 bgfx `RenderInterface`/`SystemInterface`，View 1 叠加；预乘 alpha、瞬态几何、纹理/scissor/裁剪；`theme.rcss` 提供面板/卡片/按钮/输入/列表/滑条皮肤与九宫格，控件状态/hover/active/disabled/focus-visible 由 RML 事件驱动；Close/Shutdown 必须先解绑事件再销毁 listener；
- 字体与文本（M9-T3）：字体族统一 `zl_ui`（Noto Sans SC，OFL，Regular 400 + Bold 700 实例化）；字号只用 11/13/15/18/22 五级；CJK 字形按需光栅化，不预载全字库；RmlUi 字体图集单页上限 1024×1024，HUD 目标 ≤12 页 / 48MB；中英混排用 `word-break: break-word`，单行省略用 `white-space: nowrap` + `text-overflow: ellipsis`；F11 Typography 面板显示字体页数/尺寸/字节；
- HUD（M9-T4）：`assets/ui/hud.rml` 常驻显示时间/倍速/Health/Needs.fatigue 映射体力/背包前 5 格/notice；`WorldDemoState::RefreshHud` 每帧构建快照，HUD 元素不可聚焦，输入默认透传；打开背包/菜单时隐藏 HUD 和 bgfx 调试文本，关闭/玩家死亡恢复；
- UI 输入互斥：RmlUi 有输入焦点时 `UiSystem` 调 `Input::SetGameplayBlocked(true)`，所有 `IsAction*/IsKey*/IsMouseButton*/ScrollDeltaY` 返回 false；无焦点时透传。注意 RmlUi 无显式焦点时 `GetFocusElement()` 返回 **body**（不是空指针），必须把 body/html 视为无焦点；点击过的 div 会获得焦点，关闭面板必须 `Blur()`，否则永久阻断游戏输入；`Input::NewFrame` 每帧重置，禁止在 UI 处理前阻断；
- 背包 UI（M9-T5）：`inventory.rml` + `ui::InventoryPanel`，5×5 背包、主手/躯干装备槽、附近地面（`inventory.lootRange` 默认 3m）；`InventoryState`/`InventoryAction` 解耦 UI 与游戏逻辑，`WorldDemoState::RefreshInventory` 每帧构建快照；拖拽用 RmlUi `drag: clone`，右键菜单用 `mousedown` button=1；打开背包时隐藏 HUD、隐藏 bgfx 调试文本并 `SetGameplayBlocked(true)`，关闭/玩家死亡恢复。工具维修走 `InventoryActionType::Repair` + `items::Repair`：右键耐久未满的武器显示“维修”，消耗 `inventory.repairKit`（默认 `repair_kit`）并恢复 `inventory.repairAmount`，快照 `damaged/repairAvailable` 驱动按钮；维修在容器副本上完成，失败不扣材料；
- 主菜单/暂停菜单（M9-T6）：`menu.rml` + `ui::MenuPanel`，主菜单（新游戏/继续/读取存档/设置/退出）与暂停菜单（继续/保存/设置/返回主菜单/退出）共用文档；`MainMenuState` 启动时暂停游戏并通过 `AppState` 切到 `WorldDemoState`；暂停/返回主菜单用保留世界状态的 UI 覆盖层（不销毁当前会话，“继续”恢复原世界与倍速）；Esc 在 `WorldDemoState` 打开暂停，菜单打开时隐藏 HUD/调试文本/世界调试叠层并阻断输入；设置页支持点击改键（10 项）与 Master/Music/SFX/Ambient 四组音量 0–100，应用后 `Config::Set + Save` 写回 `config/game.json`、实时更新音频组并重建 Input 绑定；关闭菜单必须 Blur 焦点；读档页通过 `Save.List()` 分页填充（每页 8 条，上一页/下一页、页码与总数），`Save.Load(id)` 只允许主菜单调用，请求状态机在帧末切换；每行“删除”按钮先弹确认层，`Save.Delete(id)` 同时删除主档与备份，写入中拒绝，删除后自动收敛页码；
- 存档二进制格式（M10-T1）：`save/BinaryFormat.h` 定 16 字节段头 `magic:u32 + version:u16 + flags:u16 + payloadSize:u64`，全部小端；`BinaryWriter` 先占位、`EndSegment()` 回填长度，`BinaryReader` 用 `BeginSegment`/`EndSegment` 逐段读取，未知段可 `SkipSegment()`；顶层循环用 `AtEnd()` 区分正常读完与段头截断（读完不设置 Error）。字符串为 `u32 字节数 + UTF-8 原始字节`，容器为 `u32 元素数 + 元素`，数量/长度上限分别为 1,000,000 / 16MB，单段负载上限 256MB；枚举写底层类型，float/double 写 IEEE 位，禁止直接 `memcpy` 结构体（padding/ABI 不稳定）。损坏/截断/版本不兼容/超限只设置 `Error()`（带偏移）而不抛异常，调用方负责报错、删档或回退备份；旧版本不做静默迁移；
- 世界 chunk diff（M10-T2）：`Chunk` 在母地图 apply 后 `CaptureBaseline()`（800 格状态哈希；Mark 临时层不参与），非 const `Square()` 访问置 dirty；`ChunkDiff` 只保存相对基线变化的格，每格保存 roomId + 4 个持久层的完整对象（sprite/offset/blocksMovement），文件为 `<saveRoot>/world/chunk_x_y.bin`（段 `ZLCD` v1）。读档严格按 `ApplyChunkData → CaptureBaseline → ApplyChunkDiff` 顺序，先叠加 diff 再 capture 会让下次保存丢失已有改动；T5 在 chunk 卸载回调（数据清空前）调用 `SaveChunk`，并接管后台快照/原子写盘；
- 实体与玩家持久化（M10-T3）：`save::ComponentRegistry` 登记可存档组件（u32 类型 ID + u16 版本 + has/write/read），内建 Position/Velocity/SpriteRef/Facing/Health/Needs/PlayerTag/ItemInstance/Container/Equipment/Corpse/KnownRecipes/CraftingJob；实体记录以 `StableId` 为键（绝不写 entt 句柄），整个快照为段 `ZLEN` v1，每个组件负载是嵌套的标准段（可跳过未知类型）。`EcsWorld::CreateWithStableId` 在空/新 world 中按存档 ID 重建实体并推进后续分配器（`2^63` 以上的外部档案 ID 不推进普通实体分配游标）；`CapturePlayer` 要求全 world 恰好一个 `PlayerTag`，Container 保存容量+堆叠顺序（defId/count/condition），Equipment 保存两槽 optional 物品。`LoadEntities` 先创建全部实体再应用组件，任一冲突/损坏回滚本次创建；后续存档接线（T5）需在此基础上为玩家/僵尸补运行时组件（物理胶囊、输入/AI/寻路等），不能把通用实体加载当成完整角色工厂。读档校验 StableId 非 0/不重复、组件类型不重复、已知组件版本精确匹配、容器/物品/数值范围合法；损坏/截断/未知版本报错不崩溃，未知组件跳过，旧版本不做静默迁移；
- SaveManager/SQLite 元数据（M10-T4）：存档根目录由 `save.root`（默认 `saves`）配置；每个存档目录为 `<root>/<saveId>/`，内含 `meta.sqlite`、`save.bin`（段 `ZLSV` v1，存 gameVersion/mapId/createdAt）、`entities.bin`（T3 的 `ZLEN` 快照）、`thumbnail.png` 和 `world/chunk_x_y.bin`。`saveId` 由 UTC 时间戳生成且只允许 `[A-Za-z0-9_-]`，所有 id 操作先做路径校验（拒绝 `..`/分隔符）。`meta.sqlite` schema `user_version=1`：单行 `meta` 表（save_id/name/created_at/updated_at/save_version/game_version/map_id/thumbnail）和 `players` 表（stable_id/name/is_local）；每次写入用事务整体替换。`SaveManager::List` 按 updatedAt 倒序，损坏/不兼容目录记 warn 后跳过；`Create` 可带玩家列表、实体快照与 RGBA 缩略图，失败清理未完成目录；`Save` 更新 entities/thumbnail/meta；`ReadMetadata`/`ReadHeader`/`Load` 返回 `LoadResult{Ok,NotFound,Incompatible,Corrupt}`，旧 `ZLSV`/`ZLEN` 版本返回 Incompatible 并给出清晰信息；`SaveChunk`/`LoadChunk` 委托 `ChunkDiffStore`。缩略图走 bgfx `requestScreenShot` 回调（平台回读 BGRA），`ConvertBgraToRgba` 处理 pitch/yflip，`stb_image_write` 编码 PNG；主线程用 `Renderer::PollScreenshot` 取回。T5 负责把截图+快照请求放到后台、原子落盘和损坏回退；
- 后台存档与损坏恢复（M10-T5）：`SaveManager` 每次提交写 `<root>/.tmp-<id>-<nonce>/`，更新档先把已提交档复制进临时 generation，再写 header/entities/thumbnail/chunks/meta；成功后旧档整体 rename 到 `<root>/.backup/<id>/`，临时 generation rename 为正式目录（同卷目录 rename；失败恢复旧档）。`.tmp-*`/`.backup` 不是合法 saveId，List 自动忽略。`Load`/`LoadChunk` 只在主档 Corrupt/NotFound 时回退 backup，Incompatible 不回退；`LoadReport{usedBackup,warning}` 交给状态显示 HUD。手工损坏 chunk 时错误带偏移、文件路径与“删除存档或使用备份”建议，不崩溃；
- 后台存档线程（M10-T5）：`save::SaveService` 独占 `zl-save` 线程，主线程提交 `SaveRequest`（实体快照/玩家列表/缩略图/chunk diff 副本），后台调用 `SaveManager`；主线程每帧 `PollResults` 后通过 `GameContext.onSaveFinished` 回到当前状态。ECS registry、World/Chunk 指针禁止跨线程；快照采集（`CaptureEntities`/`CaptureChunkDiff`）只在主线程。`F12` 快速存档：先采集快照，再请求一帧截图（2s 超时则无缩略图保存），最后交给后台；退出时 `save.autoSaveOnExit` 自动提交（无缩略图），GameApp Shutdown 等待 zl-save 收尾；
- 运行时存档接线（M10-T5）：主菜单 Continue 读最近一次 `List` 结果；`WorldDemoState(loadId)` 读实体后补建玩家/僵尸的 Collider/RigidBody/AI/寻路/输入等运行时组件（通用 EntityStore 不是角色工厂）。chunk 加载回调在 `CaptureBaseline` 之后、物理静态体/寻路位图之前叠加 `LoadChunk` diff；chunk 卸载回调在数据清空前 `SaveChunk`（备份回退会话禁止回写旧主档）。存档缩略图/实体/chunk 快照不改主线程世界；
- 音频设备与音量组（M11-T1）：`audio::AudioEngine` 用 miniaudio 高层 engine；`audio.device=default|null|off`，设备初始化失败或 `off` 时所有接口安全 no-op，游戏不因拔设备崩溃。音量组为 `Master → Music/SFX/Ambient`，`audio.{master,music,sfx,ambient}Volume` 默认 65/70/85/55 持久化；设置页应用时实时 `SetGroupVolume`。音频文件按逻辑名从 `audio.root` 加载 `.wav`，占位资源见 `assets/audio/README.md`；
- 2D/3D 与声景（M11-T2/T3）：听者 = 相机中心（`FromScreen(Camera::Center())`），距离线性衰减、pan 按等距屏幕横向投影（`ComputeSpatial` 纯函数可单测）；`SoundManager` 启动低音量 `music_calm` 循环（Music 组），昼夜切换 `ambient_day/night`（Ambient 组），僵尸低吼按听者附近存活数量调节间隔（SFX 组）；世界声音（枪声/脚步）只发 `OnSound`，UI 点击/拾取为 2D 直放；脚步按地面 sprite 映射 `footstep_grass/dirt/wood`，步幅 `audio.footstepStride` 默认 0.9 格；
- 声音传播与 AI 共用（M11-T4）：`core/SoundPropagation` 提供 0.5 格采样、阻挡格计数、`wallAttenuation` 增益/有效半径；`PerceptionSystem::HearsSound` 与 `AudioEngine::ComputeSpatial` 必须调用同一实现，禁止复制公式。音频与 AI 均用 `perception.wallAttenuation`（默认 0.6）；音频 maxDistance 是听感上限，AI 用 `SoundEvent.radius`，但隔墙参数一致；
- 玩家命令层（M12-T1/T2）：所有会改变玩家/世界状态的输入（WASD、点击移动、攻击、拾取、使用/装备/丢弃、背包 UI 动作、开枪、快捷栏）先构造 `net::Command{type, payload, tick, playerStableId}`；实体引用只用 `StableId`。`net.mode=direct`（默认）提交即执行；`loopback` 由 `CommandPipeline` 在帧末 `Flush()` 编码为包（magic `ZLC1` v1，小端定长，单包 ≤64 条/4KB），下一 tick 开头 `Pump()` 解码执行并回 `ZLS1` 心跳快照。`InputSystem` 在两种模式下都只读 `MoveInput`（屏幕方向）→ `MoveIntent`，不直接读键盘；`net.*` 队列/包上限见 `config/game.json`。真实联机由 `net.mode=client` + `NetworkClient`/`KcpSession` 承担；Server 与 Client 不共享 ECS，客户端只保留复制副本，不做回滚；
- 实体复制层（M13-T4）：`net/Replication` 不依赖 world/ecs，定义 `ZLR1` v1 快照（32B 头：magic/version/flags/sequence/serverTick/baseTick/upsertCount/removalCount；实体 22B 头 + 组件 8B 头 + 负载）。`ReplicationRegistry` 按 type/version/maxBytes 注册组件；编码/解码严格校验包 ≤60KB、实体 ≤4096、组件 ≤32/实体、未知组件、重复 StableId/组件、非法 full/delta baseTick 和尾部多余字节。`game/EntityReplication` 注册 Position/Velocity/Health/SpriteRef/Facing/AnimState/ItemInstance（type ID 由 ASCII 四字符生成），抓取 AOI 内玩家、有 Health 的角色与有 ItemInstance 的地面物品，按距离/StableId 裁剪到 maxEntities；`NetworkOwner` 随实体元数据复制。服务端 producer 为每个客户端维护全量基线，`BuildDelta` 只发变化组件、新实体与 AOI 离开/销毁移除，meta 变化时发完整实体；客户端 `Apply` 校验 baseTick 与 LastAppliedTick，失败标记 `NeedsFullSnapshot`，全量清空旧副本。远端位置用 previous/current 插值；本地玩家预测只做输入积分（最多 0.25s/步），服务器位置误差超过阈值直接吸附，否则按 blend 平滑校正。
- 真实客户端接线（M13-T5）：`net.mode=client` 时 `GameApp` 保留本地 `CommandPipeline`（供返回主菜单后开单机），但把 `GameContext::commands` 置空并创建 `game::NetworkClient`；`NetworkClient` 用 KCP 会话发送 `ZLC1` 命令包，接收 `ZLA1` 玩家分配与 `ZLR1` 快照。服务器按 SessionId 维护权威玩家与 producer，所有会话命令校验 `playerStableId`/包序列；移动/点击移动/攻击在服务器执行，客户端 `WorldDemoState` 只生成视觉副本并做本地预测，不调用 `WorldSimulation::Tick`。断线自动重连（`net.autoReconnect`）会清空副本并等待服务器全量。关键配置：`net.host/port/contentHash/bindHost/maxSessions/aoiRadius/maxEntities/predictionSpeed/autoReconnect/reconnectDelayMs/handshakeTimeoutMs/heartbeatIntervalMs/heartbeatTimeoutMs/playerIdentity/identityFile/playerName`；独立服务器默认 `--server` 监听，`--server.network=false` 可关闭；
- 命令安全与容错（M13-T6）：服务器不可信客户端参数。`SessionPlayer` 每 tick 配额（`net.maxCommandsPerTick`，默认 8）、攻击 tick 冷却（`net.attackCooldownSeconds`，默认 0.35s）、`MoveTo` 距离（`net.maxMoveToDistance`，默认 64 格）与攻击目标距离（`net.maxAttackDistance`，默认 3 格）；所有命令仍校验会话 `playerStableId`。命令包 >4KB、magic/长度/序列非法、未登记会话或玩家未生成只拒绝并计数，不崩溃/不断开正常会话；`ServerHost::NetworkStats` 记录数据包、畸形/超大/过期包、命令收/受/拒、限频/冷却/越权/距离、分配/快照/状态失败与枪声，`LogStatus` 每 5s 汇总。`NetworkClient` 暴露握手/心跳/重连参数，服务器重启后自动重连并按持久身份恢复；localhost 测试覆盖越权、限频、冷却、超距、畸形/超大包、KCP 丢包重传、延迟命令与自动重连；
- 服务器权威背包（M13-T7）：`game::PlayerInventoryService` 只操作权威 ECS 与内容注册表，覆盖拾取（最近/实体，服务器校验 `inventory.pickupRadius`/`inventory.lootRange`）、使用/蓝图、装备/卸下/丢弃/维修、制作批次与 FIFO 队列；制作进度写入玩家 `CraftingJob` 并由 `ServerHost` 每个固定 tick 推进，材料在完成时原子扣除。`ZLP1` 玩家状态仅发给 owner（背包/装备/已学配方/制作/队列/提示，`net.playerStateIntervalTicks` 默认 6，动作后立即标脏）；客户端 `NetworkClient` 解码后由 `WorldDemoState` 镜像到本地玩家，背包 UI 只读展示，所有修改仍回发 `ZLC1` 命令。`ZLR1` 复制地面 `ItemInstance`，使丢落/拾取在客户端可见；服务器默认在出生点生成与单机相同的演示散落物；
- 玩家持久化（M13-T8）：`SessionHello` v2 携带客户端持久身份；`PlayerProfileStore` 用身份分配 `EcsWorld::kExternalStableIdStart` 以上的 StableId 并原子写 `saves/multiplayer_players.bin`，记录 `save::SavedEntity` 玩家快照与 `ZLP1` owner 状态。`ServerHost` 在断线/死亡/复活/定时/退出时保存，重连时 `WorldSimulation::RestoreNetworkPlayer` 恢复同一实体；死亡后 `ZLP1.alive=false`，默认 `net.respawnDelaySeconds=5` 在出生点满血复活并保留背包。身份不是密码，客户端应保护 `saves/client_identity.txt`；同身份新连接会接管旧会话（旧连接被服务器断开），用于网络抖动后的快速重连。关键配置：`net.playerProfilesFile/playerProfileSaveSeconds/respawnDelaySeconds/playerIdentity/identityFile/playerName`；
- 联机入口与社交（M13-T9）：主菜单“联机游戏”由 `MainMenuState` 打开独立 `assets/ui/multiplayer.rml`，玩家名称/地址/端口/主机端口与 `saves/servers.json` 收藏列表模型在 `ui::MultiplayerUi`，面板只读输入并回调，网络启动与 UI 解耦。`game::EmbeddedServer` 在后台线程驱动独立 `ServerHost`（`bindHost=0.0.0.0`、`port=0` 自动分配、`spawnLocalPlayer=false`、玩家档案开启），本机 `NetworkClient` 随后连接 `127.0.0.1:<实际端口>`；离开/退出先 `NetworkClient::Close` 再停止并回收服务器，保证档案保存。`net/SocialProtocol` 定义 `ZLH1` 聊天消息（≤200 字节、UTF-8、无控制字符）与 `ZLS2` 社交状态（按 StableId 排序的玩家列表 + 最近 16 条聊天，≤16KB），服务器校验每会话 `net.chatCooldownSeconds` 并广播；客户端由 `WorldDemoState` 映射到 `ui::SocialUiState`，独立 `social.rml` 显示右上在线玩家与左下聊天，Enter 开/发送、Esc 取消，焦点输入阻断游戏键位。关键配置：`net.serversFile/socialStateIntervalTicks/chatCooldownSeconds`。
- 远程表现与投射物（M13-T10）：`ZLR1` 组件表新增 `Equipment` 与 `ActionState`，archetype 新增 Effect/Projectile；服务器权威 `FireProjectile` 命令生成带 Velocity 的投射物，`MovementSystem` 积分后 `ServerHost::UpdateProjectiles` 做墙体/角色半径判定，命中走 `CombatSystem::ApplyDamage` 并生成 `TransientEffect`，投射物和特效均通过普通 ZLR1 实体快照复制。`ActionPresentationSystem` 位于固定链 AnimationSystem 之后，从 Velocity/CraftingJob/Health 推导移动、制作、死亡状态，CombatSystem 写入攻击/受击短时状态；客户端 `WorldDemoState` 把复制 `Equipment` 应用成武器/衣物图标叠加，把 `ActionState` 画成挥砍/制作火花，Effect/Projectile 直接走 `RenderCollectSystem`。关键配置：`net.projectileDamage/projectileSpeed/projectileLifetimeSeconds/projectileCooldownSeconds/maxProjectileDistance`。
- 性能策略（M12-T3）：地面批（stage 0）先按纹理聚簇再排序，减少多图集交错 drawcall（placeholder 场景 244→71）；`ChunkManager::ProcessResults` 受 `world.chunkAttachBudgetMs`（默认 2ms）与 `world.chunkAttachBudget`（默认 8 块）双预算限制，至少挂接 1 块避免饥饿；启动时间在 `GameApp::Run` 记录 `启动耗时`。基准与 500 人口巡航数据见 `docs/perf-baseline.md`；
- 内容管线（M12-T4）：`tools/pack_tileset.py` 把 PNG 帧目录 shelf 打包为 `pz-atlas-v1` 页 + JSON，可选传 `--texturec` 生成发布用 DDS（运行时仍读 PNG）；自制品图标/物品全部走 `assets/own` + `asset_manifest.json` + `assets/items.json`，当前 19 条物品定义（含维修包、烤豆子与烹饪杂志；配方产物复用占位帧，待正式美术替换）；`tools/tiled_import.py` 支持 TMX/TSX 与 TMJ/TSJ 的有限正交地图导入，Tiled tile 的 `sprite`/`floor`/class 映射为逻辑名，图块层/对象层/房间转换为稀疏 chunk（约定与限制见 `docs/tiled-import.md`）；
- 配方与制作（后续扩展）：`assets/recipes.json`（`recipes-v3`，兼容 v2/v1；`config/game.json` 的 `recipes.file`）由 `items::RecipeRegistry` 启动加载并与 `ItemRegistry` 交叉校验（未知物品、重复 id/材料/工具、数量/时长/磨损/station 越界、`unlocksRecipes` 引用未知配方整体拒绝）；v3 的 `station` 指向世界对象逻辑名 `object.<station>`（内置 `workbench`/`campfire`，显示名由 `crafting.stationLabels` 配置），玩家需在 `crafting.stationRange`（默认 2.5 格）内才能开始/完成，`game::HasStationNearby` 只扫描已加载 chunk；v2 的 `tools` 只校验背包内拥有、不扣除，但按 `wear`（0~1，缺省 0.1）磨损 `ItemInstance.condition`，耗尽即移除；工具必须 `maxStack=1`。`time` 为可选制作秒数（0.1~60，缺省 1.0）。`items::CraftingProcess` 由固定 tick 推进，计时完成后才调用 `items::Craft` 重新校验并原子扣料/产出/磨损，取消、离开制作站或失败不消耗材料也不磨损工具。`Inventory.GetState().recipes/crafting` 暴露配方、制作站状态、当前任务及槽位 `condition`，`Inventory.Action({type="craft", fromIndex=N, count=K})` 启动任务、`cancel_craft` 取消，均走现有玩家命令管线；工具效率为 `0.5 + 0.5 × 最低可用工具耐久`（无工具 1.0，缺工具 0），实际时长 = `time / 效率`（最多 2 倍），`recipes[].estimatedSeconds` / `crafting.toolEfficiency` 暴露给脚本，`core_ui` 背包页每页显示 4 条配方并支持 `‹`/`›` 翻页、预计耗时、可制作/不可制作/缺工具/缺对应制作站/未学会、进度条/取消按钮及物品耐久百分比；蓝图解锁由 `items.json` 的可选 `unlocksRecipes` 声明（当前 `magazine_cooking` → `campfire_beans`），被引用的配方默认未学会；使用杂志/图纸消耗 1 件并写入玩家 `KnownRecipes` ECS 组件（随存档持久化，已全学会不消耗），`recipes[].known` 暴露给 Lua/Python，未学会时 C++ 拒绝开始且 UI 提示“阅读对应配方杂志解锁”；批量制作由 `items::MaxCraftCount` 在容器副本上连续预检材料/工具磨损/输出空间，把请求件数截断到实际可做上限；同配方逐件制作，每件完成才原子扣料并自动重算工具效率续下一件，中途资源/工具/制作站/空间不足则停止并保留已完成产物；空闲时 `craft` 立即开始，已有任务时追加到 FIFO 制作队列（最多 8 项，可跨配方），队首开始时重新校验并截断，任一批次中断或 `cancel_craft` 清空剩余队列；`InventoryCrafting.batchCount/completedCount/queue` 暴露批次进度与后续队列，`Inventory.Action` 另提供 `queue_up/queue_down/queue_remove/queue_count`（`fromIndex` 为队列下标，`queue_count` 的 `count` 为 1~99）编辑后续队列且不影响当前任务/材料，Lua/Python `core_ui` 提供数量 `- N +`、批次进度、队列选中预览、`<`/`>` 选择、`↑`/`↓` 调序、`−`/`+` 调整请求件数、`×` 移除与“取消全部”；活跃批次计时/批次计数与后续队列保存到玩家 `CraftingJob` ECS 组件（`CRFT` v1，队列上限 8、请求件数 1~99），读档后恢复进度并重新校验配方存在/已学会（制作站与材料在继续计时完成或队首开始时再校验），失效时取消任务并清空队列；
- 事件监听器生命周期：`AddEventListener` 时同时保存 `element + event + listener`，UI Shutdown 必须先 `RemoveEventListener` 再销毁 listener；否则 RmlUi `Context` 析构的 `DetachAllEvents` 会解引用悬空指针（M9-T5 踩坑）；
- 一切资源文件名不带中文、不带空格。

### 9.1 占位资源策略（开发期借 PZ 资源，后期换自制）

- **合规底线**：占位资产（PZ 版权）只放 `assets_placeholder_pz/`（自带 .gitignore，默认忽略全部内容）；**禁止提交公开仓库、禁止随构建产物分发**；发布前必须全部替换为自制资源，细则见该目录 README；
- **AssetProvider 适配层**：游戏代码只按**逻辑名**取资源（如 `tile.floor.grass`、`item.axe`），实际文件由 `asset_manifest.json` 映射（逻辑名 → provider + 文件/图集/子图）；`config/game.json` 的 `assets.provider` 选择 `placeholder_pz` 或 `own`；**换资源 = 换目录 + 换 manifest，零代码改动**；
- **占位资源获取**：
  - 散装 PNG（物品图标/衣服/UI，3214 张）：直接引用 PZ 安装目录 `media/textures/`；
  - tile/树/覆盖层：`py -3 tools/pz_pack_unpack.py` 解包 `media/texturepacks/*.pack`（支持 PZPK v1 与旧 v0 两种格式，导出 PNG + `pz-atlas-v1` 格式 atlas JSON），用法见 `assets_placeholder_pz/README.md`；
- **PZ 子图字段语义**：`x/y/w/h` = 图内矩形；`ox/oy` = 相对"原始格位左上角"的绘制偏移；`fx/fy` = 缩放前原始尺寸（floor 常为 64x32，2x 版翻倍）；渲染时经 `IsoMath` 换算后贴图。
