# 技术选型与开发规范

## 1. 工具链（Windows）

| 组件 | 版本要求 | 安装 |
|---|---|---|
| Visual Studio 2022 | 17.8+，勾选「使用 C++ 的桌面开发」 | winget / 官网安装器 |
| CMake | 3.24+ | `winget install Kitware.CMake` |
| Ninja | 新版 | `winget install Ninja-build.Ninja` |
| Git | 新版 | `winget install Git.Git` |
| vcpkg | 最新 | `git clone https://github.com/microsoft/vcpkg E:\Dev\vcpkg` → `bootstrap-vcpkg.bat` → 环境变量 `VCPKG_ROOT=E:\Dev\vcpkg` |

C++ 标准：**C++20**。编译器：MSVC（x64）。

## 2. 第三方依赖

### 2.1 vcpkg.json（工程根目录，草案）

```json
{
  "name": "zomboidlike",
  "version": "0.3.0",
  "dependencies": [
    "glfw3",
    "bgfx",
    "glm",
    "bullet3",
    "entt",
    "lua",
    "sol2",
    "spdlog",
    "stb",
    "nlohmann-json",
    "doctest",
    "sqlite3",
    "miniaudio",
    { "name": "bgfx", "features": ["tools"], "host": true }
  ],
  "features": {
    "python": {
      "description": "Python script backend (M8)",
      "dependencies": ["pybind11", "python3"]
    }
  }
}
```

> 说明：
> - bgfx 的 shaderc/bin2c/texturec 工具已通过 **host 依赖 `bgfx[tools]`** 解决（port 注释推荐写法，装在 `build/<preset>/vcpkg_installed/x64-windows/tools/bgfx/`）；`tools/build_shaders.ps1` 一键重编 shader。
> - Python 后端走 vcpkg 的 `python3` + `pybind11`；假如 vcpkg python3 在你的环境有问题，退路是用官方 Python 安装 + CMake `find_package(Python3)`（当前先不用管，M8 再处理）。
> - `tools/`（shaderc 等）与预编译 shader 产物是否入库：**shaderc 工具不入库**（vcpkg 自动装），**编译好的 shader 产物（`src/render/shaders_generated/*.bin.h`）要入库**（保证不开工具链也能编译运行）。

## 4. CMakePresets.json（已落地，见仓库根目录）

```json
{
  "version": 6,
  "configurePresets": [
    {
      "name": "x64-debug",
      "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/x64-debug",
      "toolchainFile": "$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake",
      "cacheVariables": {
        "CMAKE_BUILD_TYPE": "Debug",
        "CMAKE_CXX_COMPILER": "cl",
        "CMAKE_CXX_STANDARD": "20",
        "CMAKE_EXPORT_COMPILE_COMMANDS": "ON",
        "VCPKG_TARGET_TRIPLET": "x64-windows",
        "ZL_ENABLE_PYTHON": "OFF"
      }
    },
    {
      "name": "x64-release",
      "inherits": "x64-debug",
      "binaryDir": "${sourceDir}/build/x64-release",
      "cacheVariables": { "CMAKE_BUILD_TYPE": "RelWithDebInfo" }
    }
  ],
  "buildPresets": [
    { "name": "x64-debug", "configurePreset": "x64-debug" },
    { "name": "x64-release", "configurePreset": "x64-release" }
  ]
}
```

> - **Ninja + MSVC 必须有 VS 环境变量**（cl/INCLUDE/LIB）：普通 PowerShell 用 `tools/dev.ps1 <命令>` 包装执行（自动经 vswhere 加载 VS 环境并兜底设置 `VCPKG_ROOT`）；或在「x64 Native Tools 命令提示符」里直接跑 cmake。`CMAKE_CXX_COMPILER=cl` 用于在 PATH 里同时存在 clang 时强制走 MSVC（vcpkg 依赖按 MSVC ABI 编译，编译器必须一致）。
> - Debug 配 VS 调试器（打开 `build/x64-debug` 下的目标可直接调试）；Release 用 RelWithDebInfo（带符号，性能问题排查用）。

## 5. 编码规范

### 5.1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类/结构/枚举 | PascalCase | `GridSquare`, `ChunkState` |
| 函数/方法 | PascalCase | `Update()`, `GetSquare()` |
| 局部变量/参数 | camelCase | `moveSpeed`, `tileIndex` |
| 成员变量 | `m_camelCase` | `m_position`, `m_health` |
| 静态成员 | `s_camelCase` | `s_instance` |
| constexpr 常量 | `kPascalCase` | `kChunkSize`, `kTickRate` |
| 宏 | `UPPER_SNAKE`（尽量少用） | `ZL_ASSERT` |
| 文件 | PascalCase.h / .cpp，与主类同名 | `GridSquare.h`, `SpriteBatch.cpp` |
| 目录 | 全小写 | `render/`, `ai/` |
| 命名空间 | `zl`，模块二级 `zl::core`、`zl::world`… | `zl::world::Chunk` |

- 头文件一律 `#pragma once`；
- include 顺序：自身头 → C++ 标准库 → 第三方 → 本项目，组间空行；
- 不用 `using namespace`（头文件里绝对禁止）；`.cpp` 内也尽量避免；
- 注释用中文可以，但只写"为什么"，不写"是什么"；TODO 必须带任务号：`// TODO(M4-T6): ...`

### 5.2 异常 / 断言 / 错误处理

- **初始化阶段**允许异常（加载失败等致命错误），main 里统一捕获并弹日志；
- **运行期**不使用异常做流程控制；逻辑不变量用 `ZL_ASSERT`（Debug 中断、Release 记日志）；
- 可恢复错误（配置缺项、mod 报错）→ 记错误日志 + 降级继续；
- 不可恢复错误 → 日志 + 明确提示 + 有序退出（尽量保存当前进度）。

### 5.3 内存

- 所有权：`std::unique_ptr`（默认）；裸指针/引用 = 非拥有借用（文档注释标明生命周期）；
- 热路径（GridSquare、实体、sprite 实例）**禁止** `shared_ptr` 与每帧堆分配；用对象池/复用 buffer；
- 容器预留容量（`reserve`）用于每帧清空复用的 vector；
- 定期跑 Debug 的 VS 内存快照对比；泄漏检查（CRT 内置或 VS 诊断）。

### 5.4 线程

- 只有主线程能改世界（架构文档第 3.2 节铁律）；**EnTT registry 主线程独占**——后台任务只处理快照与结果数据，禁止持有 registry 引用；
- 跨线程数据只通过：不可变快照 / 结果队列 / 命令队列；
- 线程命名便于调试（`zl-task-0`、`zl-save`）；
- 共享计数器用 `std::atomic`，锁优先 `std::mutex` + 小粒度；不使用读写锁热点（先测再优化）。

### 5.5 日志

- 级别：`trace/debug/info/warn/error/critical`；发行版默认 info；
- 关键系统（chunk 生命周期、存档、mod、脚本、AI 寻路）用 debug 打点，可 config 打开；
- 格式：`[时间][级别][模块] 消息`；模块名与目录一致。

### 5.6 ECS（EnTT）规范

- 组件 = 纯数据 struct（无方法、无虚函数、无逻辑），名字用名词：`Position`、`Health`；查询/换算写成自由函数或系统；
- 公共组件放 `src/ecs/components/`，领域组件放各自模块（`characters/components/`、`items/components/`）；
- 系统命名 `XxxSystem`，签名统一 `void Update(EcsWorld& world, float dt)`；**更新顺序只在 SystemScheduler 一处集中注册**，写注释说明依赖关系；
- 遍历用 `view`/`group`；禁止热路径用 `registry.each` 全量遍历；不得跨 tick 缓存 view / 实体集合；
- 实体引用一律 `entt::entity` + `registry.valid()` 校验；跨模块 / 脚本 / 存档交流走 `StableId`；
- 创建/销毁走延迟队列，tick 末统一 flush；大量同类实体（地面物品、尸体）实现"睡眠"标记，不进渲染/AI 系统。

## 6. 性能预算（每次里程碑验收对照）

| 项 | 预算 |
|---|---|
| 帧总时长 | 16.6ms（60fps） |
| 模拟 tick（不含物理/寻路后台） | < 4ms |
| 物理步进（500 静态体 + 150 动态体） | < 2ms |
| AI/移动/战斗系统（1000 实体，LOD 后） | < 2ms |
| 渲染收集 + 提交（CPU 侧） | < 6ms |
| 同帧 drawcall | < 100 |
| chunk 加载（后台单块解析） | < 2ms |
| 1000 格 A* 查询 | < 5ms（后台） |

- 每阶段结束用 `perf-baseline.md` 记录：场景、配置、FPS、各系统耗时；
- 性能工具：VS 性能分析器起步；bgfx debug 文本显示 FPS/drawcall/顶点数常开（release 可关）。

## 7. Git 工作流

- `main` 保持随时可编译可运行；
- 功能分支：`feat/m3-chunk-streaming`、`fix/m4-wall-stuck`；完成后合回（个人项目允许直接 main 小步提交，但里程碑任务建议用分支）；
- 提交规范（Conventional Commits）：
  ```
  feat(render): sprite batch + atlas json (M2-T3)
  fix(world): chunk unload race on camera fast move (M3-T4)
  docs(tasks): mark M2 completed
  chore(build): bump bgfx port
  ```
- 每完成里程碑：更新 README 状态表 + `git tag v0.N.0`；
- 大文件（png/音频）注意仓库体积：单个 > 10MB 的资源先压缩；后续需要时再上 Git LFS。

## 8. 测试规范

- 框架：doctest（轻量，随构建）；
- 必须先写测试的地方：坐标换算（IsoMath）、地图/serialization 往返、寻路正确性、容器堆叠规则、存档往返；
- 运行方式：`ctest --preset x64-debug`（或直接运行 `ZomboidLikeTests.exe`）；
- 手感类（移动/战斗/UI）不写自动化测试，用"验收场景脚本"手动过（任务清单里的验收条目）。

## 9. 资源制作约定

- 美术先全部用**占位资源**（色块/简单图形），系统验证优先，M12 再谈正式美术；
- 图集：`texturec` 打包或简单网格图集（M2 先用网格），命名全小写+下划线；
- 地图 JSON、物品 JSON、mod 全部 UTF-8 无 BOM；
- 一切资源文件名不带中文、不带空格。

### 9.1 占位资源策略（开发期借 PZ 资源，后期换自制）

- **合规底线**：占位资产（PZ 版权）只放 `assets_placeholder_pz/`（自带 .gitignore，默认忽略全部内容）；**禁止提交公开仓库、禁止随构建产物分发**；发布前必须全部替换为自制资源，细则见该目录 README；
- **AssetProvider 适配层**：游戏代码只按**逻辑名**取资源（如 `tile.floor.grass`、`item.axe`），实际文件由 `asset_manifest.json` 映射（逻辑名 → provider + 文件/图集/子图）；`config/game.json` 的 `assets.provider` 选择 `placeholder_pz` 或 `own`；**换资源 = 换目录 + 换 manifest，零代码改动**；
- **占位资源获取**：
  - 散装 PNG（物品图标/衣服/UI，3214 张）：直接引用 PZ 安装目录 `media/textures/`；
  - tile/树/覆盖层：`py -3 tools/pz_pack_unpack.py` 解包 `media/texturepacks/*.pack`（支持 PZPK v1 与旧 v0 两种格式，导出 PNG + `pz-atlas-v1` 格式 atlas JSON），用法见 `assets_placeholder_pz/README.md`；
- **PZ 子图字段语义**：`x/y/w/h` = 图内矩形；`ox/oy` = 相对"原始格位左上角"的绘制偏移；`fx/fy` = 缩放前原始尺寸（floor 常为 64x32，2x 版翻倍）；渲染时经 `IsoMath` 换算后贴图。
